The core figures behind the harness-as-worker direction, measured on 2026-10-01 and 2026-10-02 in roadmap Milestone 0, Part A (verifications V1 to V10 of xref:../../discussions/control-direction.adoc#verification[Control Direction]). The complete record with every run, the pass criteria set before the runs, and the fallbacks is xref:../../discussions/control-direction-measurements.adoc[Control Direction Measurements]; this document keeps what a design decision needs.

== How it was measured

* *Stub*: a throwaway MCP server (`de.cuioss.pm.mcp.spike`) with a blocking wait tool, a submit tool, a distractor tool, scripted tasks, leases, and model slots. Every observation comes from its event log and from the arrival time of the harness's output lines, never from what a model says about itself.
* *Transport*: the host reaches the stub as it will reach the product, over `stdio`, through a stand-in for `pm-mcp serve` that forwards to the stub over Streamable HTTP and logs the host side.
* *Harnesses and models*: Claude Code 2.1.287 with `claude-haiku-4-5` (Sonnet for one comparison), OpenCode 1.18.34 with `space-bunny-free`, Antigravity 1.2.14 with `gemini-3.8-flash-medium`. Headless runs unless stated.
* *Isolation*: the final series ran every worker in a directory outside the repository, with the server under the product's name `plan-marshall`, and with Claude Code's tools loaded directly. The first series did not; what that changed is listed in <<setup-lessons>>.
* *Tasks*: closed-answer decisions modelled on a running plan (remediation, review triage, scope, build classification, commit type, quality gate).

== Lifecycle, usage, and injected text

* *V4*: on all three harnesses a headless session ends within a second of `SIGTERM` without orphaned processes, and a stored session can be resumed (3 to 13 s). A terminated session reports no usage.
* *V7*: Claude Code and OpenCode report usage per turn with all four token components, so a task in a warm session gets its own figures. Antigravity reports no cache-creation figure; its `total_tokens` stays unmeasured.
* *V8*: injected instructions in one task never reached a later task: 25 warm runs each on Claude Code and OpenCode, 15 on Antigravity, five variants. In three runs the injected text changed the decision of the task that carried it.

== What the setup taught

Found while measuring; each changed the tooling and names a requirement for the product. The complete list, with names, prompts, server setup, and connecting hosts, is in xref:findings.adoc[Findings].

* *A harness started inside a repository is not isolated.* Claude Code loaded the project instructions and shared the project's persistent memory across sessions; a value one session saved appeared in later, unrelated sessions. A model job needs a working directory outside the project tree, or project instructions and memory switched off.
* *A server name that says "stub" invites giving up*; the OpenCode model cited it. It gave up under the product's name as well, so the name was not the cause, but it was a reason the model used.
* *Deferred tools lose fresh jobs.* With Claude Code's tool search active, 6 of 72 fresh Haiku jobs never made the call. With `ENABLE_TOOL_SEARCH=false` all 72 did, at the price of about 11k more tokens of context per session.
* *The relay carries identity, not the model.* A model invented a worker id from a remembered value; the relay overrode it.
* *A relay must add the per-request headers of a sessionless host* (`Mcp-Method`, `Mcp-Name`), *must never answer a notification* (Antigravity ends a server that does), and *must report a lost daemon* to the host at once (Claude Code otherwise waits out its 30 minutes).
* *Machine load moves the figures*: with 19 runs started together, fresh jobs took twice as long.
