== Distribution & Client Packaging (PM-DIST)

[#PM-DIST-1]
=== PM-DIST-1: Single Version Authority & Embedded Client Bundles

`PM-MCP` distributes a compiled software system rather than a generated markdown corpus, unifying server and client components under a single version authority.

* The system must distribute the native executable `pm-mcp` as a unified package containing all server runtime code and embedded client bundles (`classpath:/bundles/<client>/`) for all four supported frontier coding agent runtimes: Claude Code (`claude`), OpenCode (`opencode`), Antigravity (`antigravity`), and Codex (`codex`).
* The system must eliminate separate client-side package downloads and repository distributions, ensuring that client-installed artifacts always originate directly from the installed `pm-mcp` binary.
* The system must embed the following artifacts within each client bundle:
** User-invocable entry commands / skills that execute `pm-mcp enter --client <client>`.
** Execution-context sub-agent variant definitions per model effort level.
** Host lifecycle hooks (such as session-start checks for stale bundles or resumable plans) where supported by the host.
** Host MCP `stdio` connection configurations (`pm-mcp serve`) and permission deny rules for credential directories.
* The system must structure the server filesystem installation using a clean separation between installation and instance directories:
** `<PM_MCP_HOME>/`: Read-only installation directory containing the `pm-mcp` binary (`bin/pm-mcp`), default configuration (`conf/pm-mcp.properties`), and CycloneDX SBOM (`sbom/pm-mcp-cyclonedx.json`).
** `<PM_MCP_BASE>/`: Mutable instance directory (default `~/.plan-marshall/mcp/`) that survives software upgrades, containing `conf/` (operator overrides), `logs/`, `locks/`, and `state/` (enrolments, build slots, install records).

See the link:specification/client-profiles.adoc[Client Profiles & Dynamic Translation Specification] and link:specification/filesystem-layout.adoc[Filesystem Layout Specification] for implementation details.

[#PM-DIST-2]
=== PM-DIST-2: Embedded Bundle Extraction & Interactive Client Installer

Client configuration artifacts and bundles must be extracted directly from the `pm-mcp` binary's embedded resources and applied via an interactive CLI installer without requiring any network or HTTP listener.

* The `pm-mcp` executable must embed a deterministic bundle manifest (`classpath:/bundles/<client>/bundle-manifest.json`) for each supported client (`claude`, `opencode`, `antigravity`, `codex`), defining target relative paths, file types, SHA-256 digests, file modes, and owned configuration keys.
* The system must provide a client installation tool (`pm-mcp client install|update|remove|status`) that reads the embedded bundle manifest directly from the binary, compares it against the target filesystem and installation ledger, displays an interactive diff of files and permissions to be changed, and requires explicit operator confirmation on a TTY (`--yes` for non-interactive CI/automation).
* The client installer must support two installation scopes:
** `--scope user`: Installs entry commands and MCP `stdio` server configurations into the user's global client configuration (`~/.claude/`, `~/.config/opencode/`, `~/.gemini/antigravity/`, `~/.codex/`).
** `--scope project`: Writes entry commands and MCP `stdio` settings into the repository checkout (`.mcp.json`, `opencode.json`, `.codex/config.toml`, containing zero user-specific paths or secrets) for team version control.

See the link:specification/client-profiles.adoc[Client Profiles & Dynamic Translation Specification] and link:specification/daemon-endpoint.adoc[Daemon Endpoint Specification] for implementation details.

[#PM-DIST-3]
=== PM-DIST-3: Uniform Host MCP STDIO Connection Configuration

The system must configure all supported coding agent hosts to spawn `pm-mcp serve` directly over the `stdio` transport.

* The system must configure every supported host runtime to launch `pm-mcp serve` over `stdio`:
** *Claude Code (`claude`)*: `.mcp.json` / `~/.claude.json` entry `{"mcpServers": {"plan-marshall": {"type": "stdio", "command": "pm-mcp", "args": ["serve"]}}}`.
** *OpenCode (`opencode`)*: `opencode.json` entry `{"mcp": {"plan-marshall": {"type": "local", "command": ["pm-mcp", "serve"], "enabled": true}}}`.
** *Antigravity (`antigravity`)*: `mcp_config.json` entry `{"mcpServers": {"plan-marshall": {"command": "pm-mcp", "args": ["serve"]}}}`.
** *Codex (`codex`)*: `.codex/config.toml` / `~/.codex/config.toml` table `[mcp_servers.plan-marshall]` with `command = "pm-mcp"` and `args = ["serve"]`.
* Because the host spawns `pm-mcp serve` directly as a child process per session and `pm-mcp enter` accesses the shared filesystem stores directly under `FileChannel.lock()`, no background daemon pre-start, bearer token helper, or TCP port configuration is required.

See the link:specification/daemon-endpoint.adoc[Daemon Endpoint Specification] and link:specification/client-profiles.adoc[Client Profiles & Dynamic Translation Specification] for implementation details.

[#PM-DIST-4]
=== PM-DIST-4: Bundle Upgrade Detection & Atomic Reconciliation

The system must detect discrepancies between installed client bundles and the installed `pm-mcp` binary, performing safe, idempotent updates.

* The system must detect bundle version or digest divergence during `pm-mcp enter` and session-start hooks, issuing an actionable recommendation to run `pm-mcp client update`.
* The system must record every installed file path and configuration key in an installation ledger (`~/.plan-marshall/mcp/state/install-records.json`); subsequent updates must modify or delete only recorded files.
* The client updater must verify file digests before overwriting; any file modified locally by the operator must be preserved and reported with a warning.
* The client updater must merge shared configuration files (such as `.mcp.json`, `settings.json`, `opencode.json`, `mcp_config.json`, and `config.toml`) strictly at owned keys (e.g., `mcpServers.plan-marshall` or `mcp_servers.plan-marshall`), preserving all unowned configuration.
* When the `pm-mcp` binary is upgraded on disk while active sessions are running, `pm-mcp enter` and `pm-mcp status` must detect the version mismatch against running process records and allow graceful draining via `pm-mcp drain`.

See the link:specification/client-profiles.adoc[Client Profiles & Dynamic Translation Specification] and link:specification/daemon-endpoint.adoc[Daemon Endpoint Specification] for implementation details.

[#PM-DIST-5]
=== PM-DIST-5: Multi-Host Concurrent Coexistence on One Machine

Multiple `pm-mcp` STDIO server processes across distinct coding agent hosts must operate simultaneously and safely across different projects or within the same project.

* The system must permit concurrent `pm-mcp serve` STDIO processes from any combination of supported coding agent runtimes (`claude`, `opencode`, `antigravity`, `codex`) on the same machine.
* The system must install client bundles into host-specific directories without file name collisions.
* The system must coordinate machine-wide build slot caps (`build-slots.json`), per-repository merge queues (`merge-queue.json`), cross-plan review-bot rate windows (`review-bot-windows.json`), and per-plan locks fairly across all concurrent `pm-mcp` processes via `FileChannel.lock()`.
* The system must support development and test isolation: setting `PM_MCP_BASE` or `PLAN_MARSHALL_HOME` to an alternate path must isolate all state locks, build slots, audit logs, and credential namespaces to that directory.

See the link:specification/filesystem-layout.adoc[Filesystem Layout Specification] and link:specification/client-profiles.adoc[Client Profiles & Dynamic Translation Specification] for implementation details.
