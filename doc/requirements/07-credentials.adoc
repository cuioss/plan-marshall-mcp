== Credential Management (PM-CRED)

[#PM-CRED-1]
=== PM-CRED-1: Dual-Lane Credential Separation (System vs Token Lane)

External provider authentication must be partitioned into a System Lane managed by host CLI tools and a Token Lane managed by the daemon's credential stores.

* The system must classify every external provider declaratively in domain support into either the *System Lane* or the *Token Lane*.
* The system must hold zero credentials for System Lane providers (`git`, `gh`, `glab`), delegating authentication entirely to the host tool's native stores (git credential helpers, SSH agent, and CLI login profiles) and verifying readiness by running the tool's verification command as a job (e.g. `gh auth status`).
* The system must manage credentials for Token Lane providers (REST code-quality services such as Sonar and authenticated upstream MCP servers) within PM-MCP's credential stores and verify them via authenticated requests to the provider's verification endpoint.
* The system must store its persistent operator CLI token in the Token Lane credential stores and, when the active store is not the macOS Keychain, additionally require an operator passphrase of which the daemon persists only a cryptographic hash (rotatable via `pm-mcp operator credentials rotate`).
* The system must keep the ephemeral per-start MCP endpoint cookie separate from the credential stores, generating it fresh on each daemon startup in `~/.plan-marshall/mcp/`.

See the link:specification/daemon-endpoint.adoc[Daemon Endpoint Specification] and link:specification/filesystem-layout.adoc[Filesystem Layout Specification] for implementation details.

[#PM-CRED-2]
=== PM-CRED-2: OS Credential Store Priority & Native Access

The operating system's native credential store must serve as the primary repository for Token Lane secrets, resolved ahead of file-based fallbacks.

* The system must prioritize the operating system credential store for all Token Lane credentials and operator secrets, using a configurable service name (default `plan-marshall-mcp`) and account identifiers `<provider>` (global) or `<project>/<provider>` (project-scoped).
* The system must integrate with the macOS login Keychain using an Access Control List (ACL) that trusts only the `pm-mcp` binary, ensuring that any read attempt by another process—including a shell driven by the model—triggers an interactive OS confirmation prompt to the user.
* The system must integrate with the Linux Secret Service (`org.freedesktop.secrets` via GNOME Keyring or KWallet) over the D-Bus session Unix domain socket using the JDK's native `UnixDomainSocketAddress` channel.
* The system must resolve provider credentials in strict priority order: (1) OS credential store project entry, (2) OS credential store global entry, (3) file store project entry, and (4) file store global entry—selecting the first complete entry and skipping entries marked with placeholders.
* The system must automatically fall back to the file credential store when an OS credential store is unavailable (such as headless Linux environments without an unlocked keyring or Windows WSL sessions).

See the link:specification/daemon-endpoint.adoc[Daemon Endpoint Specification] and link:specification/filesystem-layout.adoc[Filesystem Layout Specification] for implementation details.

[#PM-CRED-3]
=== PM-CRED-3: Permission-Guarded Fallback File Credential Store

When the OS credential store is unavailable, secrets must be stored in a permission-guarded directory structure compatible with plan-marshall.

* The system must maintain the fallback file credential store under `~/.plan-marshall/credentials/` (or the root specified by `PLAN_MARSHALL_HOME`), storing global entries at `<provider>.json` and project entries at `<project>/<provider>.json`.
* The system must derive `<project>` from the final path segment of the version-control remote URL (stripped of `.git`), or, if no remote URL exists, from the directory name suffixed with the first 8 lowercase hex characters of the SHA-256 hash of its canonical absolute path.
* The system must enforce POSIX directory permissions of `0700` on the credential store directory and `0600` on every credential file, creating files atomically with `0600` mode and verifying permissions immediately after creation.
* The system must canonicalize all resolved credential file paths to prevent directory traversal outside `~/.plan-marshall/credentials/` and must sanitize `<project>` names strictly to `[a-zA-Z0-9._-]`.
* The system must support credential schemas with `auth_type` set to `none`, `token`, or `basic` (with `username` and `password`), optional `header_name` and `header_value_template` (defaulting to `Authorization` and `Bearer {token}`), and must treat entries containing `REPLACE_WITH_YOUR_TOKEN`, `REPLACE_WITH_YOUR_USERNAME`, or `REPLACE_WITH_YOUR_PASSWORD` as incomplete.
* The system must include defense-in-depth host file-tool deny rules covering `~/.plan-marshall/credentials/` when installing client bundles (`pm-mcp client install`).

See the link:specification/filesystem-layout.adoc[Filesystem Layout Specification] and link:specification/store-schemas.adoc[Store Schemas Specification] for implementation details.

[#PM-CRED-4]
=== PM-CRED-4: Operator-Only Secret Entry & Zero Model Exposure

Secrets must be entered exclusively by the human operator and must never be exposed to the model or passed through CLI flags.

* The system must restrict all credential configuration and lifecycle operations exclusively to the operator CLI (`pm-mcp operator credentials`).
* The system must read secrets interactively from the terminal with echo disabled during `pm-mcp operator credentials set <provider> [--project]` when targeting the OS credential store, or generate a placeholder file for direct operator editing when targeting the file store, strictly prohibiting secrets in CLI arguments or environment variables.
* The system must provide operator credential management subcommands: `status` (displaying serving store and verification status without revealing secret values), `check` (verifying completeness), `verify` (testing provider authentication), `remove` (deleting an entry), and `migrate` (transferring a file-store entry into the OS credential store and deleting the file).
* The system must expose only closed-enum credential status indicators (`complete`, `incomplete`, `not_found`, `verified`, `unverified`) to the model and workflow engine.
* The system must transition any workflow step requiring a missing or incomplete credential into a `*.blocked` state whose representation specifies the exact `pm-mcp operator credentials` command required to unblock it.

See the link:specification/daemon-endpoint.adoc[Daemon Endpoint Specification] for implementation details.

[#PM-CRED-5]
=== PM-CRED-5: Outbound Domain Scoping & Output Secret Redaction

Token Lane secrets must be held in memory only during active requests, scoped strictly to their issuing HTTPS origin, and redacted from all outputs.

* The system must read a Token Lane secret from the credential store only at the moment of an outbound HTTP request, retain it in memory solely for the duration of that request, and never cache it, persist it elsewhere, or pass it to subprocesses.
* The system must enforce HTTPS with full TLS certificate and hostname verification for all Token Lane requests, transmit credentials exclusively to the configured origin for which they were issued, and abort any HTTP redirect to a plain `http://` URL as an error.
* The system must prohibit credential passthrough in the MCP proxy, authenticating to each upstream MCP server exclusively with PM-MCP's own configured credential for that server and never forwarding tokens received from a host or another server.
* The system must redact and strip all secret values from tool results, state representations, error payloads, diagnostic logs, and the audit log, sanitizing upstream provider error responses before logging or returning them.

See the link:specification/daemon-endpoint.adoc[Daemon Endpoint Specification] for implementation details.
