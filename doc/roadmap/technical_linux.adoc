== Purpose

This runbook covers the Linux half of link:../roadmap.adoc[Roadmap] Milestone 0, Part B (technical verifications): every item that runs only on Linux (Landlock, Secret Service), and every item that must hold on both platforms (native image, on-demand start, web listener, the `PM-TECH-3` bounds). The macOS half is link:technical_macos.adoc[Technical Verifications on macOS]. Each item checks a technique against a gate of the link:../Requirements.adoc#_appendix_verification_gates_risk_register_non_normative[Requirements, Appendix: Verification Gates & Risk Register]. The technique is built in its target module, so a result applies to the product code.

The document is self-contained. A Claude Code session on the Linux machine can run it from top to bottom without any other context.

=== Rules

* *Pass criteria are fixed.* Every item states its pass criterion below, set before the first run. Never edit a pass criterion after a run. If a criterion turns out to be wrong, record that as a finding in the item's result.
* *Branch.* Work on `feature/m0-part-b-linux`, created from `main`. Write results only into this document, in the item's *Result* block, its *Status* line, and <<setup-record>>.
* *Code changes.* Code may change only in the Linux-specific classes, and every change comes with a test:
** `pm-modules/pm-exec` (Landlock), `pm-mcp-server/.../credentials/dbus` and `SecretServiceStore` (Secret Service);
** the Linux branches of `pm-modules/pm-api/.../posix` (spawn).
+
A failure elsewhere is recorded as a finding and is not fixed here; the macOS side owns that code.
* *Builds and tests.* Use Maven and JUnit only. `.plan/execute-script.py` is not tracked, so use `./mvnw` with the arguments given here. Never run `javac` directly, and never write ad-hoc verifier programs; a shell sequence written out in an item is allowed. Analyse a failing build and never work around it.
* *Figures.* Every verification IT writes its measured figures to `<module>/target/verification-results/<item>.json`. Copy the figures into the result table and name the file.
* *Fallbacks.* A failed item records the fallback its gate names (quoted in the item) and does not apply it in code. The consolidation on the macOS side decides and applies it.
* *Handback.* At the end: commit, push `feature/m0-part-b-linux`, and open one PR against `main`, titled `docs: Part B technical verifications on Linux`. Do not merge it.

== Machine Setup

The machine is a vanilla Ubuntu 24.04 LTS, on `x86_64` or `aarch64`. Run every step as the normal user (not root), with `sudo` where shown.

=== Kernel and Landlock

[source,bash]
----
uname -r            # must be >= 5.19 for Landlock ABI 2; Ubuntu 24.04 ships 6.8
cat /sys/kernel/security/lsm   # must contain "landlock"
----

The Landlock ABI itself is read with `pm-exec --probe` once the binaries are built (<<build>>).

=== Keyring Session (gate 5)

On a desktop session the keyring already runs; record which one it is. On a headless machine, start a session bus and an unlocked keyring for the run:

[source,bash]
----

If `DBUS_SESSION_BUS_ADDRESS` names an abstract socket (`unix:abstract=...`), that is itself a finding for L8: the JDK cannot connect to an abstract socket. Record it, and start `dbus-daemon --session --address=unix:path=$XDG_RUNTIME_DIR/bus --fork` to continue.

== Build

[source,bash]
----
./mvnw -l target-build.log verify                                   # JVM: unit tests of all modules
./mvnw -l target-native.log verify -Pnative,integration-tests       # native binaries and every *IT
----

The native build produces four binaries:

* `pm-clients/pm-relay/target/pm-mcp`
* `pm-clients/pm-operator/target/pm-operator`
* `pm-modules/pm-exec/target/pm-exec`
* `pm-mcp-server/target/pm-mcp-server-*-runner` (the binary `pm-mcpd`)

A single module and its ITs run as `./mvnw verify -Pnative,integration-tests -pl <module> -am`. Record the binary sizes and the native build durations in L2.

A *staged installation* for manual steps: copy the four binaries into one `bin/` directory under their release names `pm-mcp`, `pm-operator`, `pm-exec` and `pm-mcpd`, and export `PM_MCP_HOME` as its parent. Use a short `PM_MCP_BASE`, for example `export PM_MCP_BASE=$HOME/.pmv`, so that the socket path fits `sun_path`.

== Items

Every item has the same blocks: what it verifies, the fixed pass criterion, the procedure, the fallback if it fails, and the result.

=== L1: Local Adapter under Native Image (gate 1)

*Verifies*: roadmap Part B, item "local adapter under native image". `pm-mcpd` serves MCP and `/api/v1` on its Unix socket with runtime-token authentication and unbuffered SSE. It handles a stale socket under the singleton lock and refuses to start when the socket path exceeds the Linux `sun_path` limit of 108 bytes. `cui-http` and `commonmark` are part of the same native build. See link:../specification/runtime-model.adoc[Runtime & Interaction Model Specification].

*Pass criterion*: all of the following hold for the native binary:

. The socket has mode `0600` in a `0700` `run/`.
. A request without the token, or with a wrong one, gets `401`.
. The first SSE event arrives before the stream ends.
. A second runtime exits `0` and leaves `<PM_MCP_BASE>` byte-identical.
. After a `kill -9` the next start removes the stale socket and serves.
. A base whose socket path exceeds 108 bytes exits `77` and writes no token and no socket.
. The ingestion validator (which uses `commonmark` and `cui-http`) works in the native binary.

*Procedure*: `./mvnw verify -Pnative,integration-tests -pl pm-mcp-server -am`, which runs the daemon ITs listed in <<daemon-its>> against the native runner.

*Fallback (gate 1)*: listener fallback (1) is loopback `127.0.0.1` with the runtime token and `Host`/`Origin` validation. Fallback (2) is an own JDK `UnixDomainSocketAddress` channel bridging to the Quarkus router. Otherwise: explicit reachability metadata, or replace the incompatible library.

*Result*:

|Check |Figure / evidence |Pass

|401 without / with wrong token | |
|Unbuffered SSE | |
|Second runtime exits 0, base unchanged | |
|Stale socket after `kill -9` | |
|Exit 77 at 108+ bytes, nothing written | |
|`commonmark` / `cui-http` in native | |
|===

=== L4: Detached On-Demand Start (gate 8)

*Verifies*: `pm-mcp` and `pm-operator` start `pm-mcpd` through FFM `posix_spawn` with `POSIX_SPAWN_SETSID` (glibc value `0x80`, glibc ≥ 2.26). The descriptors of the child are closed with `posix_spawn_file_actions_addclosefrom_np` (glibc ≥ 2.34). A termination of the relay by the host never reaches the runtime.

*Pass criterion*: all of the following, for the native binaries:

* The started daemon's process-group id and session id equal its pid.
* Its `stdin` is `/dev/null`, and `stdout`/`stderr` are appended to `logs/daemon.log`.
* After `kill -9` of the relay, and after `kill -HUP` of the relay's process group, the daemon still answers `GET /api/v1/status`.
* No zombie of the relay's children remains.

*Procedure*:

. Run the gate 8 tests of `PmMcpProcessIT` and `PmOperatorProcessIT` (L3 run).
. Manually, with a staged installation:
+
[source,bash]
----
setsid bash -c 'echo "" | $PM_MCP_HOME/bin/pm-mcp serve --client neutral & echo $! > /tmp/relay.pid; wait' &
sleep 2; pid=$(jq .pid $PM_MCP_BASE/state/runtime.json)
ps -o pid,pgid,sid,stat,cmd -p $pid
kill -HUP -- -$(ps -o pgid= -p $(cat /tmp/relay.pid) | tr -d ' ') 2>/dev/null; sleep 1
$PM_MCP_HOME/bin/pm-operator status
----

*Fallback (gate 8)*: on a failing platform the starting binary reports the failure and names `pm-operator runtime install`, and the per-user `systemd --user` service serves that platform. On-demand start stays the default wherever it works.

=== L9: Landlock Confinement in `pm-exec` (gate 3)

*Verifies*: the Landlock ruleset of `pm-exec`, applied through FFM in the native binary (`PR_SET_NO_NEW_PRIVS`, ABI ≥ 2). The write set is the project root plus the declared caches, `/tmp` and `/dev`. The read set is everything except `<PM_MCP_BASE>`. Real builds are checked under confinement: wrapper caches, the Gradle daemon, `mvnd`, Testcontainers and Docker Compose. Landlock availability on WSL2 is also part of the gate.

*Argument vector of `pm-exec`* (from `pm-modules/pm-exec/.../package-info.java`):

----
pm-exec --probe
pm-exec [--write <path>]... [--read <path>]... --deny-read <PM_MCP_BASE> -- <absolute program> [<arg>...]
----

`pm-exec` passes its environment unchanged and writes one JSON launch report line to `stderr` before `execve`. Its exit codes are `64` (usage), `126` (confinement could not be applied) and `127` (`execve` failed).

*Pass criterion*:

. `pm-exec --probe` reports `landlock_abi` ≥ 2 and `confinement` `confined`.
. `PmExecIT` passes natively, the `Landlock` group included:
** a write outside the write set is denied with `EACCES`;
** writes into `<PM_MCP_BASE>`, and reads of `run/runtime.token` and a credential file, are denied;
** a write into the project is allowed;
** a sibling of the base is readable;
** a job-private `--read` directory is readable but not writable.
. Each real build below succeeds under confinement with exactly the write set listed. Any extra path a build needs is recorded as an enrolment `write_paths` candidate.

*Procedure*:

. Run `./mvnw verify -Pnative,integration-tests -pl pm-modules/pm-exec`.
. Define the confined launcher (the staged installation, and a real `PM_MCP_BASE` with a runtime token):
+
[source,bash]
----
E="$PM_MCP_HOME/bin/pm-exec --deny-read $PM_MCP_BASE --write /tmp --write /dev"
----
+
. Run the builds:
** *Maven wrapper* (this repository; write set: repository, `~/.m2`): `$E --write $PWD --write $HOME/.m2 -- $PWD/mvnw -q -l /tmp/l9-mvn.log verify -pl pm-modules/pm-core -am`
** *mvnd* (write set: repository, `~/.m2`, `~/.m2/mvnd`): `$E --write $PWD --write $HOME/.m2 -- $(command -v mvnd) -q verify -pl pm-modules/pm-core -am`. Then run it a second time while the daemon is still up, and record whether the daemon started under confinement keeps its ruleset.
** *Gradle daemon*: create the fixture with `mkdir -p ~/pmfix/gradle && cd ~/pmfix/gradle && gradle init --type java-application --dsl kotlin --test-framework junit-jupiter --project-name fix --package fix --no-split-project --java-version 25`. Then run `$E --write $HOME/pmfix/gradle --write $HOME/.gradle -- $HOME/pmfix/gradle/gradlew build`, twice (the second run uses the warm daemon).
** *Testcontainers*: create `~/pmfix/tc` as a minimal Maven project, one JUnit 5 test that starts `GenericContainer("alpine:3")` with `withCommand("true")`, using the dependencies `org.testcontainers:testcontainers` and `org.testcontainers:junit-jupiter`. These dependencies are for this fixture only, outside the repository. Run `$E --write $HOME/pmfix/tc --write $HOME/.m2 -- $PWD/mvnw -f $HOME/pmfix/tc/pom.xml -q test`. Record whether the Docker socket `/var/run/docker.sock` is reachable under Landlock.
** *Docker Compose*: create `~/pmfix/compose/compose.yaml` with one service `hello` (`image: alpine:3`, `command: ["echo","ok"]`). Run `$E --write $HOME/pmfix/compose --write $HOME/.docker -- /usr/bin/docker compose -f $HOME/pmfix/compose/compose.yaml up --abort-on-container-exit`.
. Adversarial check: `$E --write $PWD -- /usr/bin/touch $PM_MCP_BASE/x` must fail, and `$E --write $PWD -- /usr/bin/cat $PM_MCP_BASE/run/runtime.token` must fail.
. Side effect of the read set: the directories on the path from `/` to `<PM_MCP_BASE>` get no rule of their own. Record whether `$E --write /tmp -- /usr/bin/ls /` and `… ls $HOME` are denied, and whether any build above needed such a listing.
. WSL2: run only if a Windows machine with WSL2 is available. Run `pm-exec --probe` there and record the ABI; otherwise record "not run".

*Fallback (gate 3)*: enrol extra explicit write paths in project enrolment. Never disable confinement where Landlock is available.
