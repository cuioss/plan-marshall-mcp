== Purpose

plan-marshall-mcp is moving from an open-source project to a proprietary product. Its artifacts are delivered *only
through the package registry of the GitHub organisation `plan-marshall`*, never through Maven Central or another
public registry (link:../specification/module-structure.adoc#artifact-flow[Module Structure § Artifact Flow]). Until the
repositories of Roadmap Milestone 1 exist, nothing is deployed at all: builds and artifacts stay local. This document
records what was switched off, where, and what still runs, so that no other publishing path is re-enabled by accident.

== Licensing

* The code is proprietary, all rights reserved (link:../../LICENSE.md[LICENSE.md]); source headers carry
  `SPDX-License-Identifier: LicenseRef-Proprietary`.
* The last state published under FSL-1.1-ALv2 is the tag `fsl-final` (`47c9cfc`). Release 0.1.0 on Maven Central and
  every commit up to that tag stay FSL-1.1-ALv2; the grant cannot be revoked.
* External contributions are not accepted (link:../../CONTRIBUTING.md[CONTRIBUTING.md]); the repository's interaction
  limit is "collaborators only".
* The code is split over the repositories of link:../specification/module-structure.adoc#repositories[Module Structure § Repositories]: the
  plain-Java modules, the parent and the documentation stay public while the product is developed, so that CI, static
  analysis and the review bots stay free for them. The assembly `plan-marshall-mcp` stays public for the first
  iterations as well and is switched to private before the first model-facing content is committed to it.
  Every repository is switched to private when the product is distributed. A public repository does not change the
  licence: its code is proprietary and its packages, which every GitHub account can download, are too.

|`mvn deploy` from this repository
|`maven-deploy-plugin` skipped: this repository deploys nothing yet
|`pom.xml`

|Maven repository and site targets

|`pom.xml` of `pm-mcp-parent`
|===

The Sonatype, GPG and release-app credentials are organisation secrets of `cuioss`; no workflow of this repository
passes the publishing credentials any more.

== What Still Runs

* *CI build* (`maven.yml`): compile, tests, quality gates and the SonarQube Cloud analysis; required check
  `build / conclusion`.
* *Integration tests* (`integration-tests.yml`); required check `integration-tests / conclusion`.
* *Dependency review*, *Dependabot auto-merge* and *OpenSSF Scorecard* — none of them publishes artifacts.
* *Local builds*: `compile`, `verify`, `-Ppre-commit`, `-Pcoverage`, `-Pintegration-tests` and `install` (into the local
  Maven repository) work unchanged; `deploy` uploads nothing from this repository.

== Deployment to the Organisation's Registry

Deployment is enabled by Roadmap Milestone 1 and only to the organisation's package registry: the parent POM
`pm-mcp-parent`, released there as `0.1.0`, carries that target for every repository, and its build check fails for
any other (link:../developer/registry-setup.adoc#deployment-target[Developer Guide § The Deployment Target]). The paths of the table above stay
switched off. The product itself, the four native binaries of a release, is delivered from the organisation as well;
its form for an end user (archive, installer) is settled with the first distributed release.
