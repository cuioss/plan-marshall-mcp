== Overview

This document defines the staged delivery sequence and actionable implementation tasks for *plan-marshall-mcp* (`PM-MCP`), bridging the normative requirements in link:Requirements.adoc[Requirements] and the technical blueprints in link:Specification.adoc[Specification].

Project prefix: `PM-` | Status: Pre-implementation (`PLANNED`)


1. *Foundation (Milestones 0–4)*: Module structure and build integration (four native binaries), spike verifications, always-on daemon with local adapter, `pm-mcp` CLI and `pm-mcp serve` STDIO relay, core DSL & state stores with operator enrolment and scope entry, and the job runtime.
2. *Native Core Stores & Services (Milestones 5–6)*: Differential-tested PM-MCP-native stores, build server with native parsers, CI jobs, token-lane credentials, domain descriptors, configuration migration, and the operator release verb.
3. *Hypermedia Workflow Phases (Milestones 7–11)*: Phase-by-phase build-out (`init` with the project setup first run, the dispatch mechanics, and the `claude` installer, bundle, and agent variants -> `refine`/`outline` ->`plan`/`execute` -> `finalize` with the `local_changes` and `pr` plan sources and the setup reconcile path -> `epics`), closed by the lifecycle gate that offers the plan lifecycle in enrolled projects for the client profiles shipped by then (`claude`).
4. *Platform Services & Client Distribution (Milestones 12–14)*: Warm LSP pool, upstream MCP proxy, dynamic skill serving and client bundle distribution for the remaining hosts (`opencode`, `antigravity`, `codex`), and the optional web server with the web application.

Every migration stage is a self-contained usable release (`PM-MIG-1`): prerequisites are pulled forward into the milestone that first needs them, and no stage relies on legacy `plan-marshall` delivery (`PM-MIG-2`).

Improvements deliberately deferred by operator decisions (accepted limitations of the first iteration) are collected in link:later-improvements.adoc[Later Improvements] until they are scheduled here.
