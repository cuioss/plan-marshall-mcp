== Overview

This document defines the staged delivery sequence and actionable implementation tasks for *plan-marshall-mcp* (`PM-MCP`), bridging the normative requirements in link:Requirements.adoc[Requirements] and the technical blueprints in link:Specification.adoc[Specification].

Project prefix: `PM-` | Status: Pre-implementation (`PLANNED`)


1. *Foundation (Milestones 0–4)*: Verification first (the harness as worker, then every technical spike), module structure and build integration (four native binaries), always-on daemon with local adapter, the relay binary `pm-mcp` with the `pm-mcp serve` STDIO relay and the operator CLI `pm-operator`, core DSL & state stores with operator enrolment and scope entry, and the job runtime with the role workers: role artifacts and the model caller, the task queue and task protocol, generations and fencing, the supervisor, consultation, and role qualification.
2. *Native Core Stores & Services (Milestones 5–6)*: Differential-tested PM-MCP-native stores, build server with native parsers, CI jobs, token-lane credentials, domain descriptors, configuration migration, and the operator release verb.
3. *Hypermedia Workflow Phases (Milestones 7–11)*: Phase-by-phase build-out, every model step a task of a role (`init` with the plan bootstrap, the project setup first run, the first roles on `claude` (screener, architecture enrichment), and the `claude` installer and bundle -> `refine`/`outline` ->`plan`/`execute` -> `finalize` with the `local-changes` and `pr` bootstrap sources, lesson maintenance, and the setup reconcile path -> `epics` with the epic bootstrap and server-started epic plans), closed by the release that opens the lifecycle gate (a compiled constant of the release; until then plans and epics are created only in projects enrolled as pilots) for the client profiles shipped by then (`claude`).
4. *Platform Services & Client Distribution (Milestones 12–14)*: Warm LSP pool, upstream MCP proxy, dynamic skill serving and client bundle distribution for the remaining hosts (`opencode`, `antigravity`, `codex`) with the headless templates of `opencode` and `codex` and the worker measurement that decides each host's worker eligibility, and the optional web access of the runtime with the web application, the dependable view and question channel.

Milestone 0 holds every verification and comes before any product code.

Every migration stage is a self-contained usable release (`PM-MIG-1`): prerequisites are pulled forward into the milestone that first needs them, and no stage relies on `plan-marshall` delivery (`PM-MIG-2`).

Improvements deliberately deferred (accepted limitations of the first iteration) are collected in link:later-improvements.adoc[Later Improvements] until they are scheduled here.
