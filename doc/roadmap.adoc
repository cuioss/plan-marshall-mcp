== Overview

This document defines the staged delivery sequence and actionable implementation tasks for *plan-marshall-mcp* (`PM-MCP`), bridging the normative requirements in link:Requirements.adoc[Requirements] and the technical blueprints in link:Specification.adoc[Specification].

Project prefix: `PM-` | Status: Pre-implementation (`PLANNED`)


1. *Foundation (Milestones 0–4)*: Module structure and build integration (four native binaries), spike verifications, always-on daemon with local adapter, `pm-mcp` CLI and `pm-mcp serve` STDIO relay, core DSL & state stores, and the job runtime with operator enrolment.
2. *Native Core Stores & Services (Milestones 5–6)*: Differential-tested PM-MCP-native stores, build server with native parsers, CI jobs, token-lane credentials, domain descriptors, configuration migration, and the operator release verb.
3. *Hypermedia Workflow Phases (Milestones 7–11)*: Phase-by-phase build-out (`init` -> `refine`/`outline` -> `plan`/`execute` -> `finalize` -> `epics`), closed by the lifecycle gate that offers the plan lifecycle in enrolled projects.
4. *Platform Services & Client Distribution (Milestones 12–14)*: Warm LSP pool, upstream MCP proxy, dynamic skill serving, client bundle distribution, and the optional web server with the web application.

Improvements deliberately deferred by operator decisions (accepted limitations of the first iteration) are collected in link:later-improvements.adoc[Later Improvements] until they are scheduled here.

* [ ] Implement the `pm-mcp` CLI (module `pm-mcp-cli`, picocli) with the command tree `serve`, `enter`, `hook`, `status`, `drain`, `runtime`, `client`, `web`, `operator`: every command that reads or changes state is a request to the daemon's REST API over the Unix socket with the runtime token, starting `pm-mcpd` on demand (the daemon is the only writer); without a running daemon only the four runtime-free verbs `status` (reads `state/runtime.json`, reports not running), `drain` (signal to the recorded PID), `hook session-start` (reads files, never starts the daemon, exits 0), and `client status` (reads `state/install-records.json` and the recorded target files) work, each reading only the CLI's closed read-only file list through the read-only codec of `pm-mcp-api`, and none of them writes; the CLI's only lock is `runtime-start.lock`, held until its authenticated round trip succeeds or the runtime start timeout expires (link:specification/cli-and-security.adoc[CLI, Coordination & Security Specification])
