== Scope

Support status of the MCP Skills extension (`io.modelcontextprotocol/skills`, SEP-2640) and of the base protocol revision it is written against (`2026-07-28`) in the three host runtimes plan-marshall targets: Claude Code, OpenCode and Google Antigravity. The extension is analysed in xref:mcp-skills-extension.adoc[MCP Skills Extension].

This document records a point-in-time observation. Recheck the sources below before acting on it.

== Summary

None of the three target hosts implements the Skills extension, and none has an announced plan to. The design must therefore treat tool-based skill delivery (`pm.skill`, see xref:../requirements/03-skills.adoc[Skill Model]) as the primary path, with SEP-2640 as an optional enhancement.

[cols="1,2,2"]
|===
|Host |Skills extension |Base protocol `2026-07-28`

|Claude Code
|Not supported. Feature request https://github.com/anthropics/claude-code/issues/27070[anthropics/claude-code#27070] ("Officially support loading Skills from MCP resources") closed as not planned after going stale, without a maintainer response. No changelog entry covers skills over MCP.
|Supported for direct HTTP servers: the changelog states the v2 MCP client uses "MCP 2026-07-28 negotiation with direct HTTP servers by default". No statement found for stdio servers.

|OpenCode
|Not supported. Feature request https://github.com/anomalyco/opencode/issues/12100[anomalyco/opencode#12100] ("Load skills over MCP") closed; no visible maintainer response or linked PR. The request notes that hot-loading skills would require architectural preparation.
|No clear statement found.

|Antigravity
|Not supported. The https://antigravity.google/docs/mcp/[Antigravity MCP documentation] covers tools, resources, transports (stdio, Streamable HTTP, SSE) and authentication; it does not mention extensions or skills over MCP. Skills are loaded from the filesystem only.
|Claimed by a third-party project; no statement in Google's documentation.

== Wider ecosystem

According to the https://modelcontextprotocol.io/extensions/client-matrix[MCP extension client matrix] and the https://github.com/modelcontextprotocol/ext-skills/blob/main/docs/implementations.md[ext-skills implementations list]:

Hosts and clients::

* Partial: ChatGPT, fast-agent, MCP Inspector, MCPJam Inspector, mcpkit host.
* Prototype: a community VS Code fork.
* Planned: Goose (https://github.com/aaif-goose/goose/issues/12068[aaif-goose/goose#12068]).
* Not listed for Skills: Claude (web and desktop), Cursor, VS Code GitHub Copilot, and others that support other extensions.

SDKs::

* Official TypeScript, Python, Go and C# SDKs: in progress.
* Java SDK: open issue https://github.com/modelcontextprotocol/java-sdk/issues/1140[modelcontextprotocol/java-sdk#1140].
* Community: FastMCP SkillsProvider, mcpkit.

Servers::

* Hugging Face `hf-mcp-server` is the first reference server implementing the v1 wire contract.

== Consequences for plan-marshall-mcp

. *Tool delivery is primary.* `pm.skill`, `pm.skill_file` and `pm.skills` are the skill channel on all three target hosts. Representations reference skills by URI independently of the channel.
. *Declare the extension anyway.* Serving the vocabulary skills over SEP-2640 in addition costs little and becomes effective without server changes once a host adopts it.
. *Do not rely on base-protocol `2026-07-28` features over stdio.* Claude Code's documented `2026-07-28` negotiation covers direct HTTP servers; the front end must work with the protocol revision each host actually negotiates.
. *Evaluate the Tasks extension.* The `2026-07-28` release introduced standardized extensions including Tasks for long-running work. It overlaps with the job model behind `pm.wait` (xref:../requirements/02-workflow.adoc[Long-running operations]); its host support has not yet been assessed.
. *Implementation technology.* SEP-2640 support in the official Java SDK is still open; the chosen Quarkus MCP Server does not build on that SDK and offers its own extension API (xref:../requirements/09-technology.adoc[Technology]).
