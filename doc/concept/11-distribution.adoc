== From a corpus to a program

plan-marshall today distributes a corpus through a multi-stage chain: generator per runtime, dist branches and tags, marketplace install per host, plugin cache with registry pin, executor regeneration, host restart. Each stage has its own failure modes, and each additional runtime adds a generator target and an install path.

PM-MCP distributes a program:

. Versioned artifacts, released as a unit: the PM-MCP image, the build runtime images, the host build server binary, the entry script and the entry commands per client (xref:10-technology.adoc#_delivery[Delivery]).
. One MCP server entry in the host configuration — user-level, or project-level so that every checkout starts it.
. Skills generated per project at runtime (xref:04-skill-model.adoc[Skill Model]).

[source,json]
----
{
  "mcpServers": {
    "plan-marshall": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "<volumes>", "<pm-mcp-image>", "serve", "--stdio"]
    }
  }
}
----

== Updates

* Updating the image updates skills, tools and services together. There is no second copy that can lag behind.
* A running core daemon is upgraded by draining in-flight jobs and restarting; front ends reconnect.
* Hosts see changed skill digests and refresh their skill registry; no host restart is required for new skill content.
* The host build server is upgraded like `marshalld` today: drain, replace, restart.

== Multiple runtimes

Every client (Claude Code, OpenCode, Antigravity, and others) connects to the same server, also when several clients run on one machine. Per client, only the entry points are installed — thin commands in the client's command format that run the entry script and call `pm.enter`. There is no per-runtime generator target for the corpus:

* skills, representations and links are translated on the fly through the client's profile (xref:15-client-profiles.adoc[Client Profiles]);
* skills are delivered through tools everywhere and through the MCP Skills extension where supported;
* the workflow and PM-MCP's own tools are identical across runtimes.

== Extensions

Domain support (Java, Python, frontend, documentation, OCI, requirements) is packaged as server extensions: build-system adapters, build runtime image selection, LSP configurations, triage rules and vocabulary skills. Extensions are installed into the server, not into hosts.
