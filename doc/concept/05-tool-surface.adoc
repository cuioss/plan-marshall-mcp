== Design constraints

* *Tool schemas are resident context.* Every declared tool costs context on every turn. The surface is a small set of verbs, not one tool per script.
* *Every stateful call is scoped* by `plan_id` or `epic_id`, carries the session's `client` and a `state_token`.
* *Results are TOON* representations (xref:03-hypermedia-workflow.adoc[Hypermedia Workflow]); tools that do not change state return plain TOON data.
* *No paths from the model.* Worktrees, branches and file locations are resolved server-side from the scope.

== Verb set

=== Discovery and state

`pm.enter(client, client_session, entry, …)`::
Entry from one of the user-invoked entry points; binds the client identity for all following links and returns the first representation (xref:15-client-profiles.adoc#_how_the_identity_is_established[Client Profiles]).

`pm.start(request)`::
Create a plan from a request; returns the first representation.

`pm.state(plan_id | epic_id)`::
Current representation.

`pm.plans()`, `pm.epics()`::
Listings with one-line summaries.

=== Transition

`pm.do(plan_id, transition, token, args)`::
The generic transition call. Links name it with the transition bound. Keeping transitions behind one tool keeps the schema surface constant as the workflow grows.

Named convenience verbs (`pm.push`, `pm.commit`, `pm.submit`, …) may be added as aliases of `pm.do`; whether to expose them is open (xref:13-open-questions.adoc[Open Questions]).

=== Long-running work

`pm.wait(scope, job, token)`::
Bounded blocking wait; returns the final or updated running representation.

`pm.cancel(scope, job, token)`::
Cancel a job.

=== Services

`pm.build(scope, command)`::
Build through the build server (xref:06-services.adoc#build-server[Build server]). Normally reached via links; directly callable for ad-hoc work.

`pm.lsp(scope, op, args)`::
Language operations (definition, references, symbols, diagnostics, rename) against the warm LSP pool (xref:06-services.adoc#lsp[LSP]).

=== Skills

`pm.skill(uri)`, `pm.skill_file(uri)`, `pm.skills()`::
Tool-based skill delivery (xref:04-skill-model.adoc#_delivery[Skill Model]).

=== Operator

`pm.operator(scope, action, args)`::
Operator-only actions. Never offered as a link; intended to be invoked through host prompts or commands the user triggers. See xref:09-security.adoc[Security and Trust Model].

== Resources

Read-only state is exposed as MCP resources so that large data is referenced instead of inlined:

[source,text]
----
pm://plans/{plan_id}                      representation (same as pm.state)
pm://plans/{plan_id}/outline              solution outline
pm://plans/{plan_id}/tasks/{n}            task definition
pm://plans/{plan_id}/findings             findings
pm://plans/{plan_id}/builds/{job}/log     full build log
pm://plans/{plan_id}/dispatch/{id}        rendered sub-agent prompt
pm://epics/{epic_id}                      epic representation
----

== Results and errors

* A successful transition returns the next representation.
* A rejected transition (stale token, invalid transition) returns the current representation plus a `rejected` field naming the reason. It is not an MCP error.
* A failed operation (build red, push refused) is a *state*, not an error: the representation moves to a failure state with `fix`, `retry` and `escalate` links.
* MCP-level errors are reserved for protocol faults and server faults.

== Build results

`pm.build` returns only the structured outcome: status as a closed enum, counts, and the individual errors or failing tests with locations. The full log is a resource URI. The model never reads raw build output unless it follows that URI.
