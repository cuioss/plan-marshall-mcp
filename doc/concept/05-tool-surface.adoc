== Design constraints

* *Tool schemas cost context.* On hosts that keep schemas resident, every declared tool costs context on every turn; on hosts that load schemas on demand, every tool costs a lookup before its first use. The surface is a small set of verbs, not one tool per script. On hosts that load on demand, the entry command preloads `pm_start`, `pm_state` and `pm_do`, so the workflow never waits on a tool lookup (xref:15-client-profiles.adoc#_client_profiles[Client profiles]).
* *Every stateful call is scoped* by `plan_id` or `epic_id`; the client identity is read from the scope's entry record. Transitions on part of a plan name the entity (task, finding).
* *Results are TOON text only* — representations for transitions and state (xref:03-hypermedia-workflow.adoc[Hypermedia Workflow]), plain TOON data for tools that do not change state. Tools declare no `outputSchema` and return no `structuredContent`; validation happens on the server, on inputs.
* *Portable names.* Tool names use only `[a-z0-9_]` with the prefix `pm_`, so they are valid on every host and model API and identical in skills, links and prompts.
* *No paths from the model in PM-MCP calls.* Worktrees, branches and file locations are resolved server-side from the scope.

== Verb set

=== Discovery and state

Entry is not a tool: the user-invoked entry points call `pm-mcp enter`, which writes the entry record (xref:15-client-profiles.adoc#_how_the_identity_is_established[Client Profiles]).

`pm_start(request)`::
Create a plan from a request after a plan entry without a plan id; moves the project-level entry record into the new plan and returns its first representation.

`pm_state(plan_id | epic_id, entity)`::
Current representation of the plan or epic, or — with `entity` — of one entity in it, as a dispatched sub-agent sees it (xref:03-hypermedia-workflow.adoc#dispatch[Sub-agent dispatch]).

`pm_plans()`, `pm_epics()`::
Listings with one-line summaries.

=== Transition

`pm_do(plan_id | epic_id, link, args)`::
The only transition call. `link` is a link id from the current representation, `args` the link's free parameters (xref:03-hypermedia-workflow.adoc#_links[Links]). Waiting on and cancelling long-running work are links as well (`wait:<job>`, `cancel:<job>`); a `wait` link blocks up to a bounded time and returns the final or the updated running representation. One transition tool keeps the schema surface constant as the workflow grows.

=== Services

`pm_build(scope, command)`::
Build through the build server (xref:06-services.adoc#build-server[Build server]). `command` is one of the project's build verbs (`verify`, `module-tests`, …) from its domain support, never a command line. Normally reached via links; directly callable for ad-hoc work.

`pm_lsp(scope, op, args)`::
Language operations (definition, references, symbols, diagnostics, rename) against the warm LSP pool (xref:06-services.adoc#lsp[LSP]).

=== Skills

`pm_skill(uri)`, `pm_skill_file(uri)`, `pm_skills()`::
Tool-based skill delivery (xref:04-skill-model.adoc#_delivery[Skill Model]).

=== Operator actions

Operator-only actions are not part of the tool surface. They are taken through MCP elicitation or the operator CLI (xref:09-security.adoc#operator-channel[Operator channel]).

== Resources

Read-only state is exposed as MCP resources so that large data is referenced instead of inlined:

[source,text]
----
pm://plans/{plan_id}                      representation (same as pm_state)
pm://plans/{plan_id}/outline              solution outline
pm://plans/{plan_id}/tasks/{n}            task definition
pm://plans/{plan_id}/findings             findings
pm://plans/{plan_id}/builds/{job}/log     full build log
pm://epics/{epic_id}                      epic representation
----

== Results and errors

* A successful transition returns the next representation.
* A rejected transition (invalid transition, entity no longer in an accepting state) returns the current representation plus a `rejected` field naming the reason. It is not an MCP error.
* A failed operation (build red, push refused) is a *state*, not an error: the representation moves to a failure state with `fix`, `retry` and `escalate` links.
* MCP-level errors are reserved for protocol faults and server faults. They carry a closed-enum reason and an audit record id, never internals (xref:09-security.adoc#_hardening[Hardening]).

== Build results

`pm_build` returns only the structured outcome: status as a closed enum, counts, and the individual errors or failing tests with locations. The full log is a resource URI. The model never reads raw build output unless it follows that URI.
