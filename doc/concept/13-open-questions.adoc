== Open decisions

State file formats::
State is persisted in the filesystem (xref:02-architecture.adoc#_state_persistence[State persistence]); whether the formats stay those of plan-marshall's `.plan/` tree beyond migration is open.

Cloud sessions::
A cloud session can use PM-MCP only if `pm-mcp` is installed in its environment and the daemon can run there. Whether the cloud lane becomes a PM-MCP client or stays a separate lane is open.

Roots and elicitation support::
Which clients provide MCP roots and support elicitation — the operator channel for decisions within a running plan or epic; clients without it fall back to the operator CLI (xref:09-security.adoc#operator-channel[Operator channel]).

Client detection::
The environment variables OpenCode and Antigravity set for their processes, and their self-reported names in MCP's client information, are to be verified; Claude Code sets `AI_AGENT`, `CLAUDECODE` and `CLAUDE_CODE_SESSION_ID`.

Model identity::
MCP does not tell the server which model a session runs. Whether calibration beyond vocabulary — per model rather than per client — is needed, and how the model would be identified, is open.

Build details::
* Enrolment file format in `~/.plan-marshall/mcp/`.
* Windows hosts, including control scripts for them.

Operator boundary without the Keychain::
Where the operator token lives in the file store or an unlocked Secret Service collection, a shell the model drives can read it and call operator routes directly (xref:09-security.adoc#operator-channel[Operator channel]). Whether such hosts get an additional guard — for example a passphrase the operator types for each operator action, of which the daemon keeps only a hash — is open.

Workflow decisions from the analysis::
The workflow and contract analysis lists decisions the concept has not taken yet, each with a proposal (xref:workflow-analysis/README.adoc#_decisions[Decisions]): routine user interaction and sub-agent questions, plan sources beyond a free-text request (issue, lesson, recipe), composite and non-job waits, backward transitions, dispatch observability and lost sub-agents, recipes, project extensions, argument schemas, the configuration split, architecture and setup, locks, and workflow settings.

Workflow DSL::
The grammar is sketched (xref:16-implementation.adoc#_workflow_definition[Workflow definition]); it is fixed with the finalize pilot, the first workflow written in it. Whether project finalize steps and recipes are declared in the same DSL, as data within the closed world, is open (xref:workflow-analysis/README.adoc[Workflow Analysis]).

== Verifications pending

Each verification names what happens if it fails.

. The daemon's full dependency set under Quarkus native image — the Quarkus MCP Server extension, cui-http, TokenSheriff. If a dependency fails, it gets native-image configuration or is replaced; the daemon stays native.
. LSP4J under Quarkus native image, with its protocol classes registered for reflection and its service interfaces as dynamic proxies. If it fails, LSP4J is replaced by a client for the operations PM-MCP uses; the daemon stays native (xref:10-technology.adoc#_native_binary[Native binary]).
. The systemd confinement on Linux against real builds: write paths for wrapper caches, Testcontainers and Compose stacks. A build that needs more write paths gets them through its enrolment; confinement is not dropped.
. macOS Keychain access from the native daemon: items bound to the `pm-mcp` binary through their access control list, read through the Security framework (Java FFM) under native image (xref:08-credentials.adoc#_os_credential_store[OS credential store]). If it fails, the file store applies, and the operator boundary loses the Keychain's guard (xref:09-security.adoc#operator-channel[Operator channel]).
. Secret Service on the supported Linux setups, reached over D-Bus through the JDK's Unix domain socket channel under native image. Where it is missing or fails, the file store applies.
. Which clients can obtain request headers dynamically, as Claude Code does with `headersHelper`; a client that cannot uses `pm-mcp serve --stdio`.
. Per client: whether its own extension manager can install the client bundle from the loopback install endpoint — for Claude Code, a plugin marketplace served by the daemon (xref:11-distribution.adoc#_applying_a_bundle[Applying a bundle]).
. Per client: the idle timeout of an MCP call and whether progress notifications reset it; this decides per client profile between the bounded and the progress wait (xref:16-implementation.adoc#_waiting_primitives[Waiting primitives]). For Claude Code it is documented (5 minutes over HTTP, reset by progress) and still to be confirmed in a scenario.

== Risks

Framework maturity::
The Quarkus MCP Server is a Quarkiverse extension outside the official MCP SDK tiers, maintained by a small group; the extension API needed for the Skills extension is not yet released; Tasks support is a draft. Mitigation: PM-MCP's own job model, tool-based skill delivery, and an upstream contribution of the Skills extension.

Host support varies::
Skills extension support, progress notifications, sub-agent access to MCP servers and tool-call timeouts differ between hosts. Mitigation: plain tools as the baseline, extensions as enhancement.

Models ignoring links::
A model may call tools out of sequence or re-derive arguments. Mitigation: validation of every call independent of links; rejection returns the fresh representation.

Tool schema cost::
A large tool surface can cost more context than it saves, resident or loaded on demand. Mitigation: small verb set, all transitions behind `pm_do`, preloading of the core tools on hosts that load schemas on demand, selective upstream proxying.

Judgment quality regression::
Removing whole-phase documents removes context the model may have used implicitly. Mitigation: vocabulary skills per judgment state; measure outline and triage quality in the finalize pilot before extending.

Single point of failure::
A daemon crash stalls all sessions on the machine. Mitigation: job state persisted, restart on the next connection or by the OS service, hosts reconnect, transitions validated against persisted state, idempotent side effects.

Proxy trust laundering::
Upstream content presented under PM-MCP's origin. Mitigation: provenance in `_meta`, untrusted marking, no re-serving of upstream skills.

Build code runs with the developer's privileges::
Build definitions are repository code the model may have edited, and builds run natively on the host. Mitigation: operator enrolment with verify-not-resolve, systemd confinement on Linux; on macOS it remains a residual risk.

Migration duration::
Two models coexisting prolongs maintenance cost. Mitigation: bounded stages with exit criteria; retire each current-model surface when its stage completes.
