== Two kinds of content

PM-MCP delivers two kinds of instruction content through different channels:

[cols="1,2,2"]
|===
| |Vocabulary skills |State representations

|Changes
|Per release and per project configuration
|Per transition

|Channel
|Skill tools; additionally the MCP Skills extension (<<_delivery>>)
|Tool results

|Integrity
|Per-file digests
|Bound to `state_token`

|Content
|How to interpret states and relations; how to exercise judgment
|Current state, facts, links

|Size in context
|Loaded on demand, one per judgment state
|Small, only the current state
|===

Per-plan and per-state content is never delivered as a skill. A skill with `resources: "dynamic"` may be declined by hosts and cannot be bound to an approval; a tool result is the natural carrier for per-call content. The analysis behind this is in xref:discussions/mcp-skills-extension.adoc[MCP Skills Extension].

== Vocabulary skills

A vocabulary skill answers "how do I act well here", never "what do I call next". It contains:

* the meaning of the states in its area and of the relations the model will encounter;
* the judgment criteria for free parameters (what a good outline, triage decision or commit message looks like);
* domain standards (Java, Python, documentation, …) relevant to that judgment.

It contains no commands, script names, paths or argument lists. Those arrive as links.

=== Catalogue

[source,text]
----
skill://pm/core/SKILL.md                    representation format, relations, state token
skill://pm/refine/SKILL.md                  request clarification criteria
skill://pm/outline/SKILL.md                 solution-outline authoring
skill://pm/execute/task/SKILL.md            task implementation discipline
skill://pm/finalize/<step>/SKILL.md         per finalize step with judgment
skill://pm/triage/<domain>/SKILL.md         finding triage per domain
skill://pm/domain/<domain>/<topic>/SKILL.md domain standards (java, python, docs, …)
----

The organizational prefix `pm/` keeps names recoverable from the URI and separates them from host filesystem skills.

=== Generated per project

The skill generator in the core daemon produces the catalogue per project and client from:

* the client profile of the session — tool names, load mechanism, command naming, component scope (xref:15-client-profiles.adoc[Client Profiles]);
* the project's configuration (enabled domains, build systems, finalize steps);
* domain extensions installed in the server;
* the server version.

A project without Java never lists Java skills. A skill's content is stable for a given client, configuration and server version, so real digests are published and host approvals remain valid until one of them changes.

=== Minimal skills for operations

Some operations need a skill only to announce that they exist. The build skill of a project, for example, states which build verbs are available and what their results mean; the commands themselves are the server's concern.

== Delivery

None of the target hosts — Claude Code, OpenCode, Antigravity — implements the MCP Skills extension (xref:discussions/skills-host-support.adoc[Skills Host Support]). Delivery is therefore tool-based, with the extension as an addition:

Primary: skill tools::
`pm.skills()` returns the catalogue (names, descriptions, URIs); `pm.skill(uri)` returns a `SKILL.md` with its URI and digest; `pm.skill_file(uri)` returns a supporting file. Works in every MCP host.

Additional: MCP Skills extension::
PM-MCP declares `io.modelcontextprotocol/skills` and serves the same catalogue through `skills/list`, `skills/get` and `resources/read`. Hosts that adopt the extension use it without server changes.

Representations reference skills by URI, independent of the channel.

== Progressive disclosure

Only three levels ever reach context:

. The catalogue entry (name, description) — resident, small.
. The vocabulary skill named in the current representation — loaded when judgment is required.
. Supporting files of that skill — loaded when referenced.

Whole-phase workflow documents do not exist; the workflow is the state machine.
