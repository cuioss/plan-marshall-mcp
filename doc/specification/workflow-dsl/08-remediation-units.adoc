== Remediation Policy Units (`remediation.*`)
_See Requirement link:../../Requirements.adoc#PM-WF-7[PM-WF-7: Remediation Policies, Loop-Back & Iteration Bounds]_
_Implementation watch: link:../../implementation-watch/phase-workflows.adoc#PM-WATCH-PHASE-13[PM-WATCH-PHASE-13]_

_See Requirement link:../../Requirements.adoc#PM-WF-9[PM-WF-9: Composite Wait States & Short-Circuit Failure Handling]_

_See Requirement link:../../Requirements.adoc#PM-WF-16[PM-WF-16: Reusable Compound Sub-Workflows & Config-Driven Git Commit/Push]_

_See Requirement link:../../Requirements.adoc#PM-WORK-6[PM-WORK-6: Role Qualification]_

Every blocking failure of a plan gets a bounded self-remedy through a remediation policy unit and then a defined fallback end; no failure waits for an operator decision. A remediation unit is an ordinary sub-workflow (`scope subworkflow`, one unit per failure class) that is project-owned like every other sub-workflow (xref:04-ast-node-model.adoc#project-owned-units[Project-Owned Workflow Units & Compiled Invariants]), rendered as a diagram, and scenario-testable. The server gathers the evidence and composes the facts of the decision with the evidence it rests on; the remedy comes from a closed action set the server validates: `retry` (re-run without changing code, reason `enum[flaky|infra|timeout]`), `fix` (change code or artifact and re-verify), the `loop_back` form of `fix` (the fix runs as Phase 5 remediation tasks), and `request_waiver` (a request to the operator). Where the bound actions and the budgets left admit one remedy, the server takes it without a task; otherwise a task of the unit's triage role chooses it (`decide`, <<unit-template>>), and while that role is unqualified the server takes the conservative fallback instead. Every unit's actions are bounded by per-plan budgets, its compiled invariants (<<remediation-invariants>>) hold on every load and every plan instance version, and its exit contract is a subset of the domain outcomes `resolved | waived | exhausted | fix_requested` plus the control outcome `stepped_out`.

[cols="2,3,3,2"]
|===
|Unit |Evidence (gather job) |Actions of `decide` (decision role) |Domain outcomes (waivable gate)

|`remediation.ci-failure`
|Failed checks of `HEAD` through the provider module, logs parsed by the domain `log_parser` (kinds `compile`, `test`, `lint`, `infra`, `timeout`, `unknown`), and the base's CI result of the same checks in the same job: a red that the base shows with the same fingerprints is recorded `baseline_red` and never reaches `decide`
|`retry` (re-run the checks), `fix` (in-branch commit, push, await the checks of the new `HEAD`), `loop_back` (`triage-ci`)
|`resolved`, `waived` (`ci_check:<name>`), `exhausted`, `fix_requested`

|`remediation.review-findings`
|Open findings without a terminal disposition (wait region, barrier re-fetch, self-review, security audit), structural refusals, and missing review evidence (`evidence_missing`); the screen job `remediation-review.screen` and the triage task `remediation-review.triage` (role `triage-review`, one disposition per finding group) precede the budget check
|`retry` (window-gated per-bot re-trigger; never for `unregistered_kind` or `not_wired`), `fix` (in-branch; bound only at call sites after the pull request exists), `loop_back`; review-chain-terminus findings are fix-free, dependency-delta findings `FIX`-only (`triage-review`)
|`resolved`, `waived` (`review_evidence[:<bot_kind>]`, `findings:<class>`; security findings are never waivable), `exhausted`, `fix_requested`

|`remediation.analysis`
|Every configured analysis provider's failed gate conditions and new issues, tagged by provider (`gate_failed`, `findings`, `undecidable`); the provider messages pass the screen job `remediation-analysis.screen`
|`retry` (re-scan or re-trigger the provider, the remedy for `undecidable`), `fix` (in-branch) (`triage-analysis`)
|`resolved`, `waived` (`analysis_gate:<provider>`, `findings:<provider>`), `exhausted`

|`remediation.build-failure`
|The failing build ledger row (`errors[]` by file and line) with the persisted `remediation_cause` (`deliverable` or `sweep`; none for the finalize gate); a proven baseline-only red never reaches `decide`
|`retry` (re-run the build, for no-verdict fates), `fix` (as remediation tasks) (`triage-build`)
|`resolved`, `exhausted`, `fix_requested`

|`remediation.merge-conflict`
|Conflicting paths and hunks with the base commits that touched them (a `sync-baseline` or merge-path rebase)
|`retry` (aborts the rebase and re-runs the integration against the current base and remote head, without a code change), `fix` (a task of the role `implement` resolves the conflicted files in the checkout; the unit continues the rebase) (`triage-merge`); no `request_waiver`: a merge conflict is not waivable
|`resolved`, `exhausted`

|`remediation.qgate-findings`
|The phase's blocking Q-Gate findings, persisted by the Q-Gate task
|`fix` (a new task of the authoring state, or `plan.revise-tasks` in Phase 4; an unchanged artifact is refused `fix_unchanged`), `request_waiver` (`qgate`)
|`resolved`, `waived` (`qgate_findings:<phase>`), `exhausted`, `fix_requested`

|`remediation.spend`
|The spend report against the plan's budget anchor
|none (degenerate unit: only the waiver wait; the spend ceiling is not raisable)
|`resolved` (the spend report is within the ceiling), `waived` (a `met` waiver of the gate `spend` arrived during a bound waiver wait; `merge.gate-entry` consumes it), `exhausted`
|===

=== Call Sites & Default Budgets

The budgets are call arguments of the project-owned phase units (the template values). The plan instance binds the *effective* ceiling per policy with its source (the template's call argument, a composition rule, or a `raise` waiver id), capped by the compiled hard limits of `retry_budget`, `fix_budget`, and `waiver_wait_seconds` (link:../timeouts/01-job-budgets-and-waits.adoc#retry-budget[Timeouts & Budgets Specification, Retry Budget], link:../timeouts/01-job-budgets-and-waits.adoc#fix-budget[Fix Budget], link:../timeouts/01-job-budgets-and-waits.adoc#waiver-wait[Waiver Wait]; xref:09-plan-instance.adoc#plan-instance[Plan Instance]). With the shipped `waiver_wait_seconds` of `0` a `request_waiver` goes into the hand-back report instead of waiting.

In the finalize wait region one unit runs at a time, in the fixed order CI -> analysis -> review findings; a unit's await state watches only its own class at the new `HEAD`, and after `resolved` or `waived` verdict currency re-fires the region for every class that is stale at the new `HEAD` (xref:03-reference-excerpt.adoc#_reference_workflow_dsl_excerpt_finalize_pmwf[Reference Workflow Excerpt]). For a `land` plan the shipped composition rule binds every call with `actions=[retry]`, so `decide` takes the `retry` without a task while its budget is left, and exhaustion hands the plan back with the user's change and the failure documented (xref:09-plan-instance.adoc#composition-rules[Composition Rules]).

[#unit-template]
=== Unit Template
_Implementation watch: link:../../implementation-watch/workflow-dsl.adoc#PM-WATCH-DSL-30[PM-WATCH-DSL-30], link:../../implementation-watch/workflow-dsl.adoc#PM-WATCH-DSL-31[PM-WATCH-DSL-31]_

Every unit follows one state template; the unit's own states are named `remediation-<class>.<state>`. No state of a unit is a link state: the server moves the unit, and a model acts in it only through the tasks of its task states. Every unit with an action set declares the full template (`INV-REM-7`): `gather`, `budget-check`, `decide`, `choose`, `conservative`, and the remedy states its class needs. No unit hard-wires who decides: whether `decide` creates a decision task follows at runtime from the remedies the call binds, the budgets left, and the waiver wait. With the shipped bindings the calls of `remediation.qgate-findings` and `remediation.merge-conflict` bind only `fix` and no waiver wait, so the server takes `fix` without a task; a project unit that binds a second remedy, or a positive waiver wait for the waivable Q-Gate findings, gets the decision task of the unit's role without any change to the unit.

1. *`gather`* (`composite_job`; an `auto` state in a unit whose evidence only reads stores, such as the Q-Gate findings and the spend report): The server's evidence job. It persists one failure envelope per failure `{failure_id, class, kind, source, file?, line?, message, fingerprint, excerpt_uri?}` (the fingerprint is class, kind, file, and normalized message; logs and excerpts live in the plan's evidence directory and are served as untrusted resources `pm://plan/{plan_id}/evidence/{evidence_id}`, never inlined beyond `message`; link:../store-schemas/14-plan-instance-waivers-questions.adoc#evidence-directory[Store Schemas Specification, Evidence Directory]), together with the evidence a decision rests on (the code at the commit, the log line, the standing decision). A unit whose evidence carries externally authored text (review comments and bot findings, analysis-provider messages; never CI logs, which are level-1 only) writes the new items of the firing as one server-built batch (`batch-v1`, level-1-cleaned text in spotlighting delimiters, SHA-256 per item). Outcomes: `failures` -> `budget-check` in a unit without a batch; in a unit with a batch the failure outcome is split by the fact it routes on: `failures_unscreened` (the batch holds items without a cached verdict) -> `screen`, `failures_screened` (every item cached) -> `triage` (review findings) or `budget-check`, and in `remediation.review-findings` `failures_no_triage` (findings already dispositioned `FIX`, or evidence missing only) -> `budget-check`; `none` -> `resolved`; `all_waived` (every failure is covered by a consumed `met` waiver) -> `waived`. Constituent fates other than success map to a failure outcome with the kind `infra` that needs neither screening nor triage (`failures`, `failures_screened` in `remediation.analysis`, `failures_no_triage` in `remediation.review-findings`), so a gathering problem is itself remediable. In `remediation.merge-conflict` the job first attempts the server rebase onto the observed remote head; a clean rebase settles `none` (`resolved`), so a lease rejection without a content conflict consumes no fix.
2. *`screen`* (`job llm screen role screener each screen.batch-parts`, units with external text only): one task of the `zero_tool` role `screener` per part of the batch's uncached items (one part, unless the batch exceeds the screening split bound; xref:02-units-jobs-decisions.adoc#model-job-states[Task States] item 6), whose verdicts are validated fail-closed and cached per scope by the text's SHA-256. A `suspicious` item, and an item whose verdict is missing, is withheld: only its structured fields (author, file, line, kind) and `withheld: flagged by screener` reach a model; a withheld finding stays pending, so the unit ends through its budget and fallback (the hand-back report lists it) unless a `met` waiver covers it. The completion continues to `triage` (review findings) or `budget-check`; `lost` (the role undefined, unqualified, or without a startable worker) withholds every item of the batch and continues the same way.
3. *`triage`* (`job llm triage role triage-review`, review findings only): one task per firing over every finding of the batch without a terminal disposition that is not withheld, grouped by `(domain, rule_id)`; it submits one disposition per group with per-finding exceptions (`triage-groups`), which the server writes per finding, each disposition defined once in its facts (link:../hypermedia-format/01-representation-and-link-forms.adoc#options-defined-once[Hypermedia Format Specification, Options Defined Once]). The submit carries `confidence:int[0..100]`, and the server appends one `triage.group` decision record per group (link:../model-work/11-decision-records.adoc#decision-points[Model Work Specification, Decision Points]). It is entered only while such a finding remains, so the decision asks for the remedy alone (guided step-in); `lost` leaves the findings without a disposition and continues to `budget-check`.
4. *`budget-check`* (`auto remediation.check-budgets`): `budget_left` -> `decide`; `exhausted_wait` (every budget spent, `waiver_wait_seconds > 0`, and a failing gate waivable: the server files the waiver request) -> `waiver-wait`; `exhausted` -> the `exhausted` terminal. It precedes every entry into `decide`, so `decide` is never entered with no remedy left. `remediation.spend`, which has no `decide`, runs its own primitive `remediation.check-spend-budget` here, whose closed outcomes are only `exhausted_wait` and `exhausted` (Rule 2).
5. *`decide`* (`auto remediation.offer-actions`): the server computes the offered remedies: each action of the call's bound `actions` whose budget is left (`loop_back` only `in_worktree`), and `request_waiver` while `remediation.waiver-requestable` holds (`waiver_wait_seconds > 0`, the failing gate on the closed waivable list, no request pending). When one remedy is offered, the server takes it without a task (`retry` -> `rerun`, `fix` -> `apply-fix` or, for a fix that runs in the caller, `fix-requested`, `loop_back` -> `fix-requested`, each charged by the primitive that takes it); when several are offered -> `choose`. The offered set depends only on the bindings and the budgets left, never on the unit: a `land` plan's calls bind only `retry`, and the shipped Q-Gate and merge-conflict calls bind only `fix`. Every `decide` appends a `remediation.decide` decision record with each bound action's counter against its effective ceiling and the ceiling's source (`call_argument` or `waiver`) and the remedy taken, or no choice when several are offered (link:../model-work/11-decision-records.adoc#decision-points[Model Work Specification, Decision Points]).
6. *`choose`* (`job llm remediation-decision role <triage role>`, `skill` of the class, `facts remediation.failure-evidence`): the one judgment of the unit, a task of the unit's triage role. Its entity offers one closing link per offered remedy, each defined once in `facts.options` (link:../hypermedia-format/01-representation-and-link-forms.adoc#remediation-evidence-facts[Hypermedia Format Specification, Remediation Evidence]): `retry` (rel `retry`, `reason: enum[flaky|infra|timeout]`), `fix` (rel `fix`, `summary: text[1..500]`), `loop_back` (rel `loop_back`, `remediation_summary: text[1..2000]`), `request_waiver` (rel `escalate`, `rationale: text[1..2000]`). The server validates the choice: `retry` is refused with `retry_not_applicable` when the same fingerprints already failed after a retry with the same reason; `fix` and `loop_back` are refused with `fix_unchanged` when the worktree or the artifact is unchanged since the previous attempt; non-waivable failures are marked `waivable: false` in the evidence. Every closing link also carries `confidence:int[0..100]`, and the accepted choice appends a `remediation.choose` decision record with the facts snapshot (link:../model-work/11-decision-records.adoc#decision-confidence[Model Work Specification, Decision Confidence of a Task]). The outcomes route like `decide`'s; `request_waiver` -> `waiver-wait`; `lost` -> `conservative`.
7. *`conservative`* (`auto remediation.conservative-retry`): the conservative fallback of a decision task that closed `lost` (link:../model-work/01-roles-and-configuration.adoc#conservative-fallback[Model Work Specification, Conservative Fallback]): `retry` -> `rerun` once per unit instance when `retry` is bound and its budget is left (recorded with the task's reason, for example `role_unqualified`); otherwise `exhausted` -> the `exhausted` terminal. It never routes to the operator. It appends a `remediation.conservative` decision record with the reason.
8. *`rerun`* (`auto`, the class's re-run primitive, charged to the retry budget): re-runs the failed checks, the scan, the bot trigger, or the build without a code change and binds the re-run job (its job-starting outcome `rerun_started`) -> `await`; in `remediation.merge-conflict` it is a `composite_job` that waits the retry backoff (`TIME`), then aborts the rebase, fetches, and re-runs the integration (`EXTERNAL_STATE`) (`rebased` -> `resolved`, `conflict` -> `gather`), so the retry never forms an engine-chained cycle (Rule 11a).
9. *`apply-fix`* (`job llm remediation-fix role implement`, in-branch fixes only): a task of the plan's writer role changes the code in the worktree and submits a summary of the change. `fixed` -> `commit-fix`, charged to the fix budget in that transaction; `no_change` -> `budget-check`, charged as well, so a fix that changes nothing still consumes its attempt; `lost` -> `conservative`. In `remediation.merge-conflict` the task resolves the conflicted files and the server continues the rebase.
10. *`commit-fix`* (`call git.commit_and_push`, `message_mode=interactive`, `push_mode=always`) for in-branch fixes, reachable only where the call binds `fix` (every such call site lies after the pull request exists): `done` with `guard result.commit` -> `await`; `done` with `guard not result.commit` and `stepped_out` -> `budget-check`. The `loop_back` and the Q-Gate and build `fix` enter the `fix_requested` terminal instead, charged by the primitive that takes them; the caller allocates the work and calls the unit again after the next verification, on the same counter.
11. *`await`* (`composite_job`): re-verifies only the unit's class at the new `HEAD` (the checks, a re-scan, a bot re-review, the build): passing -> `resolved`; failing, interrupted, or cancelled -> `gather`.
12. *`waiver-wait`* (`composite_job remediation.await-waiver`): the bounded wait for the operator, a server timer plus a watch of the waiver record (`OPERATOR_WAIVER`, `TIME`), no model turn: `raised` -> `budget-check` with the new ceiling; `waived` -> `waived`; `expired` -> `exhausted`; `interrupted` (a constituent fate other than success) -> `budget-check`, which re-enters the wait against the request's persisted `expires_at`, so a restart never extends it; `cancelled` -> `exhausted`.
13. *Terminals*: `resolved` (`success`), `waived` (`success`, only in units whose class has a `met`-waivable gate), `exhausted` (`failure`), `fix_requested` (`unsettled`), declared only where reachable.

*Budget accounting*: budgets are counted per plan and class in `mcp/status.json` `policy_counters` (link:../store-schemas/14-plan-instance-waivers-questions.adoc#policy-counter[Store Schemas Specification, Remediation Budget Accounting]), persisted and never reset: re-entering a unit, a new `HEAD`, a loop-back, and a re-composition of the instance continue the same counter, a `raise` waiver lifts only the effective ceiling, and a re-planning that re-enters execution renews the allowance once by counting the ceiling from the counter at the re-entry (link:../phase-workflows/08-dynamic-re-planning.adoc#replan-apply[Phase Workflows Specification, Dynamic Re-Planning]). A retry is charged when the server re-runs; an in-branch fix when its task submits the change, a `loop_back` or a fix that runs in the caller when the primitive that takes it requests it. A server step-out of a nested commit consumes no further budget and writes no waiver; a phase caller routes the unit's `stepped_out` to the same fallback as `exhausted`, and the gap record distinguishes `cause: stepped_out` (with the reason) from `cause: exhausted` (with the budget) (link:../store-schemas/14-plan-instance-waivers-questions.adoc#gap-record[Store Schemas Specification, Gap Record]).

=== DSL Sketch: `remediation.ci-failure`

[source,text]
----
workflow remediation.ci-failure version 1 format 1
scope subworkflow
param retry_budget: int[0..5]
param fix_budget: int[0..5]
param waiver_wait_seconds: int[0..86400]
param actions: list<enum[retry|fix|loop_back]>
start remediation-ci.gather

state remediation-ci.gather
  phase inherit
  composite_job remediation.gather-ci-evidence   # provider logs, log_parser, base CI result
    failures        -> remediation-ci.budget-check
    none            -> remediation-ci.resolved
    all_waived      -> remediation-ci.waived
    cancelled       -> remediation-ci.budget-check

state remediation-ci.budget-check
  phase inherit
  auto remediation.check-budgets
    budget_left     -> remediation-ci.decide
    exhausted_wait  -> remediation-ci.waiver-wait
    exhausted       -> remediation-ci.exhausted

state remediation-ci.decide
  phase inherit
  auto remediation.offer-actions                 # bound actions with budget left; one remedy: no task
    retry           -> remediation-ci.rerun
    fix             -> remediation-ci.apply-fix
    loop_back       -> remediation-ci.fix-requested
    choice          -> remediation-ci.choose

state remediation-ci.choose
  phase inherit
  skill pm/finalize/ci-triage
  facts remediation.failure-evidence
  job llm remediation-decision role triage-ci
    retry           -> remediation-ci.rerun
    fix             -> remediation-ci.apply-fix
    loop_back       -> remediation-ci.fix-requested
    request_waiver  -> remediation-ci.waiver-wait
    lost            -> remediation-ci.conservative

state remediation-ci.conservative
  phase inherit
  auto remediation.conservative-retry            # the single retry once, else exhausted
    retry           -> remediation-ci.rerun
    exhausted       -> remediation-ci.exhausted

state remediation-ci.rerun
  phase inherit
  auto remediation.rerun-checks                  # charged to the retry budget
    rerun_started   -> remediation-ci.await-ci

state remediation-ci.apply-fix
  phase inherit
  facts remediation.failure-evidence
  job llm remediation-fix role implement         # charged to the fix budget on submit
    fixed           -> remediation-ci.commit-fix
    no_change       -> remediation-ci.budget-check
    lost            -> remediation-ci.conservative

state remediation-ci.commit-fix
  phase inherit
  call git.commit_and_push (message_mode=interactive, push_mode=always)
    done            -> remediation-ci.await-ci
      guard result.commit
    done            -> remediation-ci.budget-check
      guard not result.commit
    stepped_out     -> remediation-ci.budget-check

state remediation-ci.await-ci
  phase inherit
  composite_job ci.watch-checks                  # only the CI checks of the new HEAD
    passed          -> remediation-ci.resolved
    failed          -> remediation-ci.gather
    interrupted     -> remediation-ci.gather
    cancelled       -> remediation-ci.gather

state remediation-ci.waiver-wait
  phase inherit
  composite_job remediation.await-waiver         # bounded by waiver_wait_seconds
    raised          -> remediation-ci.budget-check
    waived          -> remediation-ci.waived
    expired         -> remediation-ci.exhausted
    interrupted     -> remediation-ci.budget-check
    cancelled       -> remediation-ci.exhausted

state remediation-ci.resolved terminal resolved success
  phase inherit

state remediation-ci.waived terminal waived success
  phase inherit

state remediation-ci.exhausted terminal exhausted failure
  phase inherit

state remediation-ci.fix-requested terminal fix_requested unsettled
  phase inherit
----

The unit has no link state and no server step-out terminal, so it returns only its domain outcomes; its call sites still route `stepped_out` (Rule 6), which keeps the exit contract of every sub-workflow uniform. Every cycle passes a job state (`gather`, `await-ci`, `waiver-wait`) or a task state (`choose`, `apply-fix`) (Rule 11); a unit whose `gather` is an `auto` state has no cycle through it; the `budget-check` -> `waiver-wait` -> `budget-check` cycle awaits `OPERATOR_WAIVER` or `TIME`, and the `apply-fix` -> `budget-check` cycle is bounded by the fix budget its submit consumes. The caller binds the arguments, for example `call remediation.ci-failure (retry_budget=2, fix_budget=3, waiver_wait_seconds=0, actions=[retry,fix,loop_back])`, and routes `resolved`, `waived`, `exhausted`, `fix_requested`, and `stepped_out` (Rule 6).

[#remediation-invariants]
=== Compiled Invariants of Remediation Units
_Implementation watch: link:../../implementation-watch/workflow-dsl.adoc#PM-WATCH-DSL-17[PM-WATCH-DSL-17]_

The invariants extend the table of compiled invariants (xref:04-ast-node-model.adoc#project-owned-units[Project-Owned Workflow Units & Compiled Invariants], item 5); they are checked over every `remediation.*` unit, its call sites, and every plan instance version, and `DefaultUnitInvariantTest` refuses a weakened fixture for each.

[cols="1,6"]
|===
|Invariant |Check

|`INV-REM-1`
|Contract: the unit declares `retry_budget` and `fix_budget` as `int[0..5]`, `waiver_wait_seconds` as `int[0..86400]`, and `actions` as a `list<enum[…]>` of its actions (`remediation.spend`: `waiver_wait_seconds` only); its terminals are the reachable subset of `resolved` (`success`), `waived` (`success`), `exhausted` (`failure`), and `fix_requested` (`unsettled`), with `waived` only for a class with a `met`-waivable gate (CI, review findings, analysis, Q-Gate, spend), and every declared terminal is reachable.

|`INV-REM-2`
|No dead end and no budget-free remedy: every entry into `decide` passes `budget-check`; `decide` and the decision task offer a remedy only when the call binds it and its budget is left (`loop_back` only `in_worktree`), `request_waiver` only while `remediation.waiver-requestable` holds; `decide` takes a single remedy without a task; `choose` and `apply-fix` route `lost` to `conservative`, which takes at most one `retry` and otherwise `exhausted`, and never reaches the operator; `screen` routes `lost` to its continuation with every item withheld, and `triage` routes `lost` to `budget-check`.

|`INV-REM-3`
|Waived path: the `waived` terminal is entered only from the gather job's `all_waived` or the waiver wait's `waived`, never from a link; the waiver wait is the unit's only state awaiting `OPERATOR_WAIVER`, is a `composite_job` bounded by `waiver_wait_seconds`, and is entered only when `waiver_wait_seconds > 0`; no primitive of the unit writes a waiver (`INV-GEN-2`).

|`INV-REM-4`
|Nested commits: a call of `git.commit_and_push` inside the unit routes `stepped_out`, and `done` without a commit, back to `budget-check` (a server step-out with `cause: condition` is exempt: it unwinds every frame to the phase's fallback without taking this transition); an in-branch fix is charged in the transaction in which its task submits the change (`fixed` or `no_change`), a fix that runs in the caller when the primitive that takes it requests it.

|`INV-REM-5`
|Callers: every call site in a plan-scope unit routes `exhausted` and `stepped_out` to the phase's fallback state (`plan.return` in Phases 1–4, which forwards committed work beyond the base to `finalize.hand-back`; `finalize.hand-back` afterwards), except that a call site in Phase 5 outside the `land` lane or in finalize before the merge routes `exhausted` of every unit but `remediation.spend` to its phase's re-planning call state (`execute.replan`, `finalize.replan`, trigger `ceiling`, link:../phase-workflows/08-dynamic-re-planning.adoc#replan-existing-mechanisms[Phase Workflows Specification, Dynamic Re-Planning]), `waived` to the continuation completing the class's step `waived`, and `fix_requested` to an authoring or allocation state; every bound and every effective ceiling of every instance version is at most the compiled hard cap (retry 5, fix 5, wait 86400 s).

|`INV-REM-6`
|Accounting: the counters are per plan and class, charged only by the unit's primitives, and never reset by re-entry, a new `HEAD`, a loop-back, or a re-composition.

|`INV-REM-7`
|Full template: every unit with an action set (every class but `remediation.spend`, which has no action) declares `gather` (a `composite_job`, or an `auto` state when it only reads stores and no cycle of the unit returns to it), `budget-check`, `decide` (`auto remediation.offer-actions`), `choose` (a `job llm remediation-decision` state of the unit's role, routing `lost` to `conservative`), `conservative`, and the remedy states its action enum and class need: `rerun` where `retry` is in the enum, `apply-fix` for an in-branch fix, `fix-requested` for a fix that runs in the caller or `loop_back`, and `waiver-wait` where the class has a waivable gate. `decide` routes `choice` to `choose`, and no state, guard, or call argument takes a remedy past `decide`: whether a decision task is created is decided only at runtime from the remedies `remediation.offer-actions` computes from the bound actions, the budgets left, and `remediation.waiver-requestable`.
|===
