[#general-rules]
== General Rules

The following rules apply to every identifier in the registry; a table row states only what it adds.

1. *ASCII only*: Every identifier consists of printable ASCII characters (`0x21..0x7E`); none contains whitespace, a path separator other than the ones its grammar names, or a character that needs escaping in a file name, a URI path segment, a TOON scalar, or a host tool name. Unicode normalization never applies because no identifier admits non-ASCII input.
2. *Case*: Identifiers are lower case unless the grammar admits upper case explicitly (entity-addressed identifiers such as `TASK-001` and `F-12`, `module_id`, repository paths). An identifier is compared byte-exactly; the server never folds case to make two identifiers match.
3. *Separators*: `-` separates words inside one identifier, `_` separates words inside names that must also be valid tool or parameter names, `.` separates the segments of a dotted identifier (`state_id`, `primitive_id`), `:` separates the parts of a link identifier and a finalize step identifier, and `/` separates URI and path segments. No other separator is used, and an identifier never starts or ends with a separator unless its grammar says so.
4. *Maximum length*: Every identifier has a maximum length, stated in the table; a grammar whose regex is unbounded is bounded by the stated length (enforced as `maxLength` in a schema, or by the server's validator where the schema subset cannot express it). An identifier that exceeds its bound is refused, never truncated.
5. *Server-generated identifiers are opaque to the model*: The model copies a server-generated identifier verbatim from a representation, a model job's prompt file, or a tool result; it never composes, increments, or parses one. The server never derives meaning from the model's spelling of such an identifier beyond looking it up in the addressed scope.
6. *Model-supplied identifiers are validated server-side*: Every identifier that arrives from the model (tool arguments, link identifiers, `args` values that name an entity) is checked against its grammar by the server's argument validator before it is looked up, and a violation is answered as defined in link:../mcp-tools/04-errors-and-testing.adoc#protocol-errors-vs-domain-workflow-failure-states[MCP Tools Specification, Protocol Errors] (`invalid_arguments` for tool arguments, `rejected` for link arguments). A grammatically valid identifier that names nothing in the addressed scope is `scope_not_found` or `link_not_available`, never an empty result.
7. *No identifier encodes another scope's identifier*: An identifier is resolved only within the scope that the same call addresses; it never embeds the `plan_id`, `epic_id`, or `project_id` of another scope (`message_id`, `job_id`, `waiver_id`, `question_id`, and `batch_id` carry no scope). Composite storage addresses such as `plans/<plan_id>/`, `locks/plan-<plan_id>.lock`, the credential account `<project_id>/<credential_key>`, the archived epic directory `<epic_id>-<YY-MM-DD>`, the capture ref `refs/pm-mcp/captures/<plan_id>` of a `local_changes` plan (link:../phase-workflows/01-planning-phases-1-2.adoc#_plan_source_contracts[Phase Workflows, Plan Source Contracts]), or the baseline scratch worktree `.marshall/local/worktrees/baseline-<plan_id>-<sha12>` (`<sha12>` the first 12 hex digits of the merge-base commit, link:../job-runtime/03-parsers-and-gates.adoc#_gate_honesty_verification[Job Runtime, Gate Honesty Verification]) are paths built from identifiers, not identifiers, and are never parsed back into one.
8. *Stability*: An identifier is immutable once allocated. An identifier marked _never reused_ is not allocated again after its entity is deleted, archived, or retired; one marked _re-derivable_ is computed from content and is equal whenever the content is equal.
9. *Schema subset*: A tool `inputSchema` expresses a grammar with a lookaround-free `pattern` plus `minLength`/`maxLength` (link:../mcp-tools.adoc[MCP Tools Specification], Architectural Constraint 3). Stored schemas may use lookaround.

[#registry]
== Registry

`Generated by` names the party that allocates the value: *server* (the runtime or the operator CLI computes it), *model* (supplied in a tool call or link argument, validated by the server), *operator* (set through an operator CLI verb or operator-owned file), *user* (typed into the host entry command), or *build* (fixed in the compiled binary, a workflow definition, or a compiled-in catalogue).
