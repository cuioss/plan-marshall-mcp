[#resolution-record]
== Resolution Record

Unifying the identifiers (operator decision) removed the following divergences; each resolution chose the most restrictive rule consistent with every use.

[cols="1,3"]
|===
|Identifier |Resolution

|`recipe_key` / `recipe_id`
|`pm_start.recipe_id` admitted `_` and 64 characters while `recipe_key` admitted any length: a key with `_` or of more than 37 characters produced a recipe plan ID outside the `plan_id` grammar. Both now use the `recipe_key` grammar with at most 37 characters, and `recipe_id` is the parameter name only.

|`plan_slug`
|The slug admitted one or two characters, which derive no valid `plan_id`; the minimum length is now 3.

|`lesson_id`
|`pm_start.lesson_id` accepted any `^[A-Za-z0-9][A-Za-z0-9_.-]{1,63}$` token while the lesson store defines the dated form; `pm_start` now uses the lesson store grammar.

|Link identifier and `entity`
|`pm_do.link` bounded neither part (`maxLength` 128), the hypermedia patterns allowed 64-character actions (138 characters in total), and `entity` admitted `:`, which no entity-addressed link can carry. Actions are now at most 32 characters, entities follow one grammar without `:`, and the link is at most 106 characters.

|`module_id`
|`pm_build.module` admitted `/` and `:` and 128 characters, which cannot appear in the URI segment of `pm://architecture/modules/{module_id}` or in the entity `enrich-<module_id>`; `module_id` now has one grammar of at most 57 characters.

|Canonical build verb
|`pm_build.command` and `PM-TOOL-2` listed `compile`, `test`, `module-tests`, `quality-gate`, `verify`, `coverage`, `format-check`, while the domain templates and the build classes used `plan-marshall`'s canonical commands. One closed set, equal to `plan-marshall`'s `ALL_CANONICAL_COMMANDS`, now serves all of them (link:../job-runtime/02-confinement-and-environment.adoc#canonical-build-verbs[Canonical Build Verb Set]); `test` and `format-check` are removed.

|`job_id`
|Only builds had a grammar (`b-`); CI (`c-`) and review-bot (`r-`) jobs appeared only in examples, and the other job kinds had none. One grammar with a kind prefix now covers all five job kinds (the former `l` prefix of language servers is gone: they run without job records).

|`audit_id`
|The security specification defined a UUIDv7 while the error envelope example showed `aud-20260925-004192`; `audit_id` is the UUIDv7 `event_id` of the audit record. `transaction_id` uses the same UUIDv7 form.

|`phase`
|Findings used `2-refine`..`6-finalize` while the status store used `phase-2-refine`..`phase-6-finalize`, and the representation projection omitted the `workspace` phase. Every persisted `phase` now uses the status-store value; the representation projection gained `workspace`.

|`upstream tool name` / `server_id`
|`^up_[a-z0-9_]+$` let a `server_id` containing `_` make the name ambiguous and did not bound the length; `server_id` is now alphanumeric and the name at most 64 characters.

|Skill URIs
|`^skill://pm/[a-z0-9/_-]+/SKILL\.md$` admitted empty and separator-only segments; segments now start with a letter or digit.

|Recipe `script_job_id`
|Named a key of the enrolled `project_scripts`, not a job; renamed `project_script_id`.

|SHA-256 and migration patterns
|`[a-f0-9]` / `\d` spellings of the same grammar are normalized to `[0-9a-f]` / `[0-9]`.
|===
