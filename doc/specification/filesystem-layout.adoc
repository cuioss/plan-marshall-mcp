== Overview

This document specifies the authoritative filesystem layout for *plan-marshall-mcp* (`PM-MCP`), covering both repository-scoped workspace structures (`.plan/`) and machine-wide user-level daemon directories (`~/.plan-marshall/mcp/` and `~/.plan-marshall/credentials/`). It defines path resolution rules, worktree isolation boundaries, same-filesystem guarantees, and mutual coexistence markers.

=== Worktree Path Resolution & Same-Filesystem Invariant

* *Deterministic Location*: For any plan identified by `<plan_id>`, the server resolves its active working tree deterministically:
** If `.plan/local/worktrees/<plan_id>/` exists and is a valid git worktree, the plan directory is located at `.plan/local/worktrees/<plan_id>/.plan/plans/<plan_id>/`.
** Otherwise, the plan directory is located at `.plan/local/plans/<plan_id>/` within the primary checkout.
* *Same-Filesystem Invariant*: All worktrees are created within `.plan/local/worktrees/<plan_id>`. This guarantees that moving the `<plan_id>` directory between the primary checkout and the worktree operates on the *same physical filesystem partition*, enabling POSIX atomic renames (`rename(2)` / `Files.move(..., ATOMIC_MOVE)`).
* *Stateless Client Scope*: Neither the model nor the MCP client ever passes filesystem paths (`PM-ARCH-4`, `PM-SEC-2`). The client passes only `plan_id` or `epic_id`. The daemon dynamically resolves the canonical real path (`Path.toRealPath()`) and verifies workspace confinement before any file I/O.

== Machine-Wide Runtime Layout (`~/.plan-marshall/mcp/`)

`pm-mcp` persists machine-wide configuration, cross-process `FileChannel.lock()` files, audit logs, and project enrolments in the user's home directory (`PM-ARCH-2`, `PM-ARCH-6`).

[source,text]
----
~/.plan-marshall/
├── credentials/                         # Token-lane file credential fallback (PM-CRED-3, mode 0700)
│   ├── <provider>.json                  # User-wide token record (e.g. sonar.json, mode 0600)
│   └── <project>/
│       └── <provider>.json              # Project-scoped token override (mode 0600)
│
└── mcp/                                 # PM-MCP runtime instance directory (mode 0700)
    ├── machine-config.json              # Build slot caps and warm LSP pool defaults (mode 0600)
    ├── enrolments.json                  # Registered projects, wrappers, and tool SHA-256 hashes (mode 0600)
    │
    ├── conf/                            # Operator-owned configuration overrides
    │   ├── upstream-mcp.json            # Selective upstream MCP proxy configuration
    │   └── profiles/                    # Optional machine-wide client profile overrides
    │       └── <client_id>.json
    │
    ├── state/                           # Persistent cross-session operational state
    │   ├── install-records.json         # Client bundle ownership & SHA-256 manifest records
    │   ├── build-timings.json           # Adaptive build timeout baselines
    │   ├── build-slots.json             # Active PID-keyed build concurrency leases
    │   └── processes/                   # Active STDIO server process descriptors
    │       └── <pid>.json
    │
    ├── locks/                           # Cross-session OS FileChannel.lock() primitives
    │   ├── merge.lock                   # Machine-wide merge mutex and FIFO queue
    │   ├── review-bot.lock              # Bot rate-window claim records
    │   └── build-slots.lock             # Concurrency limiter semaphore lock
    │
    └── logs/                            # Diagnostic logs and structured security audit
        ├── daemon.log                   # Rolling server diagnostic log (mode 0600)
        ├── audit.jsonl                  # Append-only transition, tool call & security audit (mode 0600)
        └── jobs/                        # Subprocess execution logs by job ID
            └── <job_id>.log
----

=== File Permissions & Security Attributes

[cols="2,1,3"]
|===
|Path |POSIX Permissions |Security Requirement

|`~/.plan-marshall/credentials/`
|`0700` (`drwx------`)
|Strict user-only read/write directory; rejected on startup if group/others have read, write, or execute permissions (`PM-CRED-3`).

|`~/.plan-marshall/credentials/<provider>.json` and `<project>/<provider>.json`
|`0600` (`-rw-------`)
|Strict user-only access (`PM-CRED-3`). `pm-mcp` refuses to read any credential file whose permissions are broader than `0600`.

|`~/.plan-marshall/mcp/enrolments.json`
|`0600` (`-rw-------`)
|Operator-verified project roots and pinned tool SHA-256 digests (`PM-EXEC-2`); rejected at startup if permissions are broader than `0600`.

|`~/.plan-marshall/mcp/locks/*.lock`
|`0600` (`-rw-------`)
|Held via OS kernel `FileChannel.lock()` across concurrent `pm-mcp` STDIO server and CLI processes.

|`~/.plan-marshall/mcp/logs/audit.jsonl`
|`0600` (`-rw-------`)
|Append-only security and transition audit log; verified against tampering on startup.
|===

== Plan Directory Relocation Sequence

When a plan transitions to or from an isolated worktree, the daemon executes atomic relocation under an exclusive lock backed by `link:move-journal.adoc[move-journal.json]` (`PM-ARCH-7`):

* *Outward Relocation (Main Checkout -> Worktree)*:
** Git worktree is created at `.plan/local/worktrees/<plan_id>/`.
** `.plan/local/worktrees/<plan_id>/.plan/plans/` directory is prepared.
** Write-ahead journal entry is flushed (`operation: RELOCATE_TO_WORKTREE`, `phase_state: TARGET_PREPARED`).
** Atomic directory rename moves `.plan/local/plans/<plan_id>/` to `.plan/local/worktrees/<plan_id>/.plan/plans/<plan_id>/`.
** Journal state is updated to `COMMITTED`, then deleted.
* *Inward Relocation (Worktree -> Main Checkout)*:
** Prior to worktree removal, write-ahead journal entry is flushed (`operation: RELOCATE_TO_MAIN`, `phase_state: TARGET_PREPARED`).
** Atomic directory rename moves `.plan/local/worktrees/<plan_id>/.plan/plans/<plan_id>/` back to `.plan/local/plans/<plan_id>/`.
** Journal state is updated to `COMMITTED`, then deleted.
** Git worktree at `.plan/local/worktrees/<plan_id>/` is safely dismantled (`git worktree remove`).

If a power failure or crash occurs during either step, the daemon's startup recovery procedure inspects `move-journal.json` to complete or roll back the move idempotently.

== Legacy Store Coexistence, File Locking & Cutover (`PM-MIG-2`, `PM-MIG-3`, `PM-MIG-5`)

During the phased migration from `plan-marshall` Python scripts to `PM-MCP`:

1. *Mutual Coexistence Guard (`PM-MIG-2`)*: When a plan or epic is entered via `pm-mcp enter`, the daemon creates `<scope_dir>/mcp/entry.json` and acquires `.plan/co-exist.lock`. Legacy `plan-marshall` workflow entry points (`execute-script.py` phase routers) inspect `<scope_dir>/mcp/entry.json` and refuse to run legacy phase mutations on an MCP-managed scope unless explicitly downgraded via rollback.
2. *Cross-Runtime Advisory File Locking (`PM-MIG-3`)*: Both the Java daemon and legacy Python scripts acquire OS-level `flock` / `FileChannel.lock()` on companion `.lock` files before mutating shared `.plan/` JSON/JSONL stores (`status.json`, `findings.jsonl`, `references.json`, `TASK-*.json`, `merge-mutex.json`).
3. *Quantitative Rollback & Per-Project Reversion (`PM-MIG-5`)*: Because `.plan/` stores preserve structural compatibility with `format_version: 1`, an operator can revert a project or individual plan to legacy `plan-marshall` execution by removing `mcp/entry.json` (via `pm-mcp operator rollback-scope <plan_id>` or `pm-mcp client remove --scope project`), leaving all domain artifacts (`request.md`, `outline.md`, `TASK-*.json`, `findings.jsonl`) intact.
