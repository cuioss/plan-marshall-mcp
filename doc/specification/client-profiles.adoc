== Overview

This document specifies the data-driven client profile schema, on-the-fly placeholder rendering rules, three-tier environment identity detection and mismatch auditing, neutral fallback profile behavior, and embedded client bundle `manifest.json` schema for *plan-marshall-mcp* (`PM-MCP`). By translating vocabulary skills, sub-agent dispatch payloads, and host tool idioms at request time from the scope's persisted `mcp/entry.json` record, a single `pm-mcp` daemon serves Claude Code, OpenCode, Antigravity, and unknown MCP hosts concurrently without static per-runtime corpus generation.

=== Profile Override Hierarchy

At runtime, the daemon resolves a client profile by merging three layers in order of increasing precedence:

1. *Compiled Binary Baseline* (`classpath:/profiles/<client_id>.json`): Authoritative defaults shipped with the `pm-mcp` binary.
2. *Machine-Wide Operator Overrides* (`~/.plan-marshall/mcp/conf/profiles/<client_id>.json`): Optional partial JSON override allowing the operator to customize `models` pins or `connection.bounded_wait_seconds` across all repositories on the workstation.
3. *Project-Level Overrides* (`.plan/marshal.json` -> `client_profiles.<client_id>`): Optional repository-scoped `models` overrides. Project-level configuration is strictly restricted to overriding `models`; attempts to override `connection`, `dispatch.host_tool`, or security properties from `.plan/marshal.json` are ignored and logged to `audit.jsonl`.

=== Rendering Invariants

1. *Zero Unresolved Placeholders*: If any `{{...}}` token in a skill template fails to resolve against the active `ClientProfile`, `ClientProfileRenderer` fails closed and logs a template defect rather than emitting raw `{{...}}` syntax to the model.
2. *Per-Variant SHA-256 Digest*: The `_meta.sha256` digest published by `pm_skills` / `pm_skill` and the MCP Skills extension is computed *after* rendering the skill for `(project_config, client_id, daemon_version)`. Each client sees a stable, deterministic SHA-256 digest for its rendered variant.
3. *Dispatch Suppression When Unsupported*: When `profile.dispatch.supported == false` (such as on the `neutral` profile or a host whose sub-agents lack MCP access), the workflow engine automatically suppresses `form: dispatch` links and instead serves the entity's task links directly in the main plan scope.

== Three-Tier Environment Detection Matrix & Mismatch Auditing
_See Requirement link:../Requirements.adoc#PM-CLIENT-1[PM-CLIENT-1: Advisory Entry Identity Declaration & Persistence]_

_See Requirement link:../Requirements.adoc#PM-CLIENT-3[PM-CLIENT-3: Three-Tier Environment Mismatch Detection & Audit]_

_See Requirement link:../Requirements.adoc#PM-CLIENT-4[PM-CLIENT-4: Neutral Fallback Profile for Unknown Clients]_

Client identity is advisory routing and rendering metadata, never a security credential. To prevent silent profile corruption and provide full forensic visibility, PM-MCP evaluates and logs three independent identity tiers on every `pm-mcp enter` execution and every MCP tool request.

=== The Three Identity Tiers

1. *Tier 1 — Declared Entry Identity (`declared_client`)*:
   * Supplied explicitly via `pm-mcp enter --client <client_id> <entry> [plan_id | epic_id]` by the installed client bundle's entry command.
   * Persisted in `<scope_dir>/mcp/entry.json` alongside `workspace_root`, `client_version`, `client_session`, and `entered_at`.
2. *Tier 2 — Detected Environment & Protocol Signature (`detected_client`)*:
   * *At Entry (`pm-mcp enter`)*: Evaluated by inspecting the process environment inherited from the host shell against the deterministic signature matrix below.
   * *At Tool Call (`/mcp`)*: Evaluated from the MCP protocol `clientInfo.name` and `clientInfo.version` fields when present in the request or initialization metadata (`absent` when omitted by stateless callers).
3. *Tier 3 — Authenticated OS Principal (`os_principal`)*:
   * The operating system effective user ID (`uid`) and username owning the local process and authenticating with `~/.plan-marshall/mcp/cookie`.

=== Mismatch Resolution & Audit Behavior

[cols="2,2,3"]
|===
|Scenario |Active Profile Selected |Audit & Representation Effect

|`declared_client == detected_client` (e.g., both `claude`)
|`claude`
|`audit.jsonl` records `identity_match: "exact"`. No warning in representation.

|`pm-mcp enter` has `declared_client: "claude"`, but environment matches `opencode` or `unknown`
|`claude` (honors explicit `--client`, never switches silently)
|`audit.jsonl` records `event: "client_identity_mismatch"`, `declared_client`, `detected_client`, `os_principal`. `pm-mcp enter` prints a mismatch notice; representations include `profile_warning: client_identity_mismatch`.

|MCP tool call carries `clientInfo.name: "opencode"`, but `mcp/entry.json` has `client: "claude"`
|`claude` (persisted `entry.json` remains authoritative until re-entered)
|`audit.jsonl` records the cross-client call mismatch. The returned TOON representation includes `profile_warning: client_identity_mismatch` and `facts.recorded_client: claude` so the calling session sees it has not entered the plan with its own client bundle.

|Unrecognized client or `--client neutral`
|`neutral`
|`mcp/entry.json` records `"client": "neutral"`. Every representation includes `profile_warning: neutral_fallback`; all host-specific `dispatch` links are replaced with inline `submit` task links, and skill loading uses `pm_skill`.
|===

=== Ownership & Digest Verification on Install/Update/Remove

1. *Install Record Persistence*: When `pm-mcp client install` or `update` applies a manifest, it records the installed `bundle_version`, `scope`, target root, and the `sha256` of every written file and `shared_configs` key in `~/.plan-marshall/mcp/state/client-installs.json`.
2. *Modification Conflict Protection*: During `pm-mcp client update` or `remove`, before overwriting or deleting any file in `files[]`, `pm-mcp client` computes the current on-disk file's SHA-256 and compares it with the `sha256` recorded in `client-installs.json`. If the user has modified the file (digest mismatch), `pm-mcp client` skips overwriting that file, reports the conflict on the terminal, and preserves the user's changes unless `--force` is confirmed interactively.
3. *Surgical Shared Configuration Merging*: For `shared_configs[]`, `pm-mcp client` parses the existing JSON/TOML file, updates or removes *only* the JSON pointers listed in `owned_keys`, and preserves all other MCP servers, hooks, and settings owned by the user.
