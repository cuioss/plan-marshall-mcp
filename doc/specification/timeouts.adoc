== Overview

This document is the single normative source of every timeout, time window, wait window, budget, deadline, expiry, idle limit, heartbeat, back-off, interval, and age-based retention of *plan-marshall-mcp* (`PM-MCP`), and of the two compiled size limits of worker input (link:timeouts/03-retention-host-config.adoc#size-limits[Worker Input Size Limits]). Every other requirement and specification names *what* is timed and links the anchor here for the value, its derivation, its configuration key, its floor or cap, and the behaviour on expiry; none of them restates a number or a derivation rule.

JSON Schemas of configuration stores (`machine-config.json` and the per-project enrolment files `enrolments/<project_id>.json` in link:store-schemas.adoc[Store Schemas Specification], the client profile schema in link:client-profiles.adoc[Client Profiles Specification]) keep their `default`, `minimum`, and `maximum` values because a schema must be self-contained; each of those values equals the value registered here, and a divergence is a defect of the schema.

Every duration is stated in seconds unless the table says otherwise. Deadlines are measured on the monotonic clock of the process that enforces them; persisted instants (`lease_expires_at`, `reset_at`, next-allowed timestamps) follow the one wire shape of link:store-schemas.adoc[Store Schemas Specification] (RFC 3339 UTC).

Not in scope: the startup and memory bounds of `PM-TECH-3` (performance bounds, not timeouts, defined there), the token and wall-minute spend anchors of link:model-work.adoc[Model Work Specification] (spend accounting: spend warnings, never a deadline), and the token budget of a role, which is a context size, not a time (its effect is listed in link:timeouts/01-job-budgets-and-waits.adoc#worker-supervision[Worker Supervision & Recycling]).

== Table Conventions

Every group below is one normative table with the columns:

* *Name*: what is timed.
* *Value / derivation*: the compiled default or the rule that computes the value.
* *Configurable?*: the configuration key and its store, or `fixed` (compiled into the binary; changed only by a release).
* *Floor / cap*: the bounds a configured or derived value is clamped to; `—` when none applies.
* *Applies to*: the jobs, calls, or records the value governs.
* *Behaviour on expiry*: what happens when the time runs out.
* *Defined for*: the sections that use the value (they link here and restate nothing).

A value marked _open_ is not yet defined; it belongs to the named open design topic, and nothing may assume a value for it until that topic defines it here.
