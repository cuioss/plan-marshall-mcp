== Normative Client Profile JSON Schema
_See Requirement link:../../Requirements.adoc#PM-CLIENT-5[PM-CLIENT-5: Versioned Client Profile Schema & Override Hierarchy]_

_See Requirement link:../../Requirements.adoc#PM-TOOL-5[PM-TOOL-5: Tool Schema Stability & Context Budget Discipline]_

_See Requirement link:../../Requirements.adoc#PM-WF-14[PM-WF-14: Dispatch Envelopes, Return Observability & Effort Role Resolution]_

Client profiles are declarative JSON documents compiled into `pm-mcp-core` under `classpath:/profiles/<client_id>.json` (`claude.json`, `opencode.json`, `antigravity.json`, `codex.json`, `neutral.json`) and validated against the following JSON Schema (Draft 2020-12):

`dispatch.token_usage_components` and `dispatch.reports_tool_uses` are the profile's usage-reporting capability. The server renders on the `returned:<dispatch_id>` link only the usage parameters the profile declares (link:../dispatch-and-effort.adoc[Dispatch & Effort Specification], Normative Schema for `returned:<dispatch_id>`); a figure the host cannot report is recorded `unmeasured` with reason `not_reported_by_client`, and the model is never asked for a figure its host does not expose. The values are verified per host in Milestone 1 like the other _(provisional)_ host facts.

`connection.idle_timeout_seconds`, `connection.bounded_wait_seconds`, and `connection.progress_resets_timeout` are the host's timing facts; their values, the rule that keeps the bounded wait below the host idle timeout (enforced by profile validation for the compiled profile and every override), and their Milestone 1 verification are defined in link:../timeouts/03-retention-host-config.adoc#host-integration[Timeouts & Budgets Specification, Host Integration] and link:../timeouts/01-job-budgets-and-waits.adoc#bounded-wait[Bounded Wait Window].

`connection.durable_cwd` records whether the host keeps its shell working directory across tool calls. When it is `false`, rendered dispatch prompts and vocabulary skills carry the directive to address files in the plan's worktree by absolute path, because a working directory set by an earlier call cannot be relied on.

=== Profile Override Hierarchy

At runtime, `pm-mcp` resolves a client profile by merging two layers in order of increasing precedence:

1. *Compiled Binary Baseline* (`classpath:/profiles/<client_id>.json`): Authoritative defaults compiled into the runtime binary (`pm-mcpd`).
2. *Machine-Wide Operator Overrides* (`<PM_MCP_BASE>/conf/profiles/<client_id>.json`): Optional partial JSON override allowing the operator to customize connection settings such as `connection.bounded_wait_seconds` across all repositories on the workstation. Model pins are not overridden here.

Model pins are resolved separately from the machine-local effort ladder (`effort_ladder` of the operator file `<PM_MCP_BASE>/projects/<project_id>/local-config.json`, link:../store-schemas/08-project-configuration-local.adoc#local-config[Store Schemas Specification, Operator Local Configuration]), with the profile's `models` as compiled default (link:../dispatch-and-effort.adoc[Dispatch & Effort Specification]). No git-tracked configuration carries client profile overrides or model pins (ADR-021); the closed team schemas admit no such key, so a `client_profiles` block in a team file is the finding `unknown_config_key` (`config_invalid`).
