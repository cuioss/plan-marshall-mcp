[#state-catalogue-other]
== Entity Units

Every model job runs on an entity scope in a state of an entity unit, reached through its job-bound connection, which admits only the entity's links; every entity unit declares `phase inherit`. No entity state waits on a question: a question leaves the entity at once and is answered on the plan scope. When the job ends, the return-evaluation primitive of the job state reads the entity's persisted records; an entity that did not reach its terminal raises `job_incomplete` (xref:01-conventions-generic-conditions.adoc#condition-job_incomplete[Condition job incomplete]). The bootstrap units `bootstrap-plan` and `bootstrap-epic` are entity units of the workspace scope, catalogued in xref:09-bootstrap-and-lessons.adoc#state-catalogue-bootstrap[Bootstrap].

|The kind's `submit` link (for epic decomposition and lesson review the kind's submit links, each validated on its own). Refine and outline authoring carry their open `questions` inside the `submit`; the plan scope turns them into question records.

[#state-catalogue-migrated]
== Migrated and Non-Conforming Identifiers

Identifiers that appear in the documents but are not catalogue states. None of them is migrated: `released-states.txt` is empty until the first `PM-MCP` release, and a state renamed after a release is resolved by its `migrate` declaration (link:../workflow-dsl/07-loop-back-diagrams-verification.adoc#_state_name_migration_registry_released_states_txt_gate_pm_mig_4[Workflow DSL Specification, State-Name Migration Registry]).

[cols="2,2,3"]
