== Plan Workflow

The plan workflow is one definition unit merged from `init.pmwf`, `refine.pmwf`, `outline.pmwf`, `plan.pmwf`, `execute.pmwf`, `land.pmwf`, and `finalize.pmwf`; its start state is `init.classify` (link:../workflow-dsl/02-units-jobs-decisions.adoc#workflow-definition-units[Workflow DSL Specification, Workflow Definition Units]). Each plan executes its own composed, versioned plan instance of these templates (link:../store-schemas/14-plan-instance-waivers-questions.adoc#plan-instance[Store Schemas Specification, Plan Instance]); version 1 is composed at `pm_start`. The lane topology is specified in link:../phase-workflows/01-planning-phases-1-2.adoc#_lifecycle_topology_phases_14[Phase Workflows Specification, Lifecycle Topology]. A plan of source `issue` reads its issue inside `pm_start` (a bounded `ci.issue-view` through the ingestion validator); an unreadable issue refuses `pm_start` with `issue_unavailable` and creates no plan, so no state waits for the fetch.

[#state-catalogue-init]
=== Phase 1: `init`

The init questions are server-raised question records of class `init` (xref:01-conventions-generic-conditions.adoc#_state_kinds[State Kinds, `awaiting_user`]). Every answer returns to the re-entrant `init.classify`, except an option whose effect is the `returned` route, which enters `plan.return`. On expiry the classifier's declared fallback is recorded as an assumption, or the plan takes `plan.return` where no safe default exists.
