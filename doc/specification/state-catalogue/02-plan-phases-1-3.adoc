== Plan Workflow

The plan workflow is one definition unit merged from `init.pmwf`, `refine.pmwf`, `outline.pmwf`, `plan.pmwf`, `execute.pmwf`, `land.pmwf`, and `finalize.pmwf`; its start state is `init.classify` (link:../workflow-dsl/02-units-jobs-decisions.adoc#workflow-definition-units[Workflow DSL Specification, Workflow Definition Units]). Each plan executes its own composed, versioned plan instance of these templates (link:../store-schemas/14-plan-instance-waivers-questions.adoc#plan-instance[Store Schemas Specification, Plan Instance]); version 1, with the posture prunes, is composed when its bootstrap creates the plan (`start.create-scope`, xref:09-bootstrap-and-lessons.adoc#state-catalogue-bootstrap[Bootstrap]). Every model state names a role of the default role set; the role per state and its fallback while unqualified are listed in link:../phase-workflows/01-planning-phases-1-2.adoc#phase-roles[Phase Workflows Specification, Model Work per State]. The lane topology is specified in link:../phase-workflows/01-planning-phases-1-2.adoc#_lifecycle_topology_phases_14[Phase Workflows Specification, Lifecycle Topology]. Every source is read, validated, and screened by its source unit before the plan exists (an issue by `source-issue`, a lesson and its premise by `source-lesson`), so no plan state waits for a source.

[#state-catalogue-init]
=== Phase 1: `init`

The init questions are server-raised question records of class `init` (xref:01-conventions-generic-conditions.adoc#_state_kinds[State Kinds, `awaiting_user`]). Every resolution (`answered`, `assumed`, `returned`) returns to the re-entrant `init.classify`, which reads the answer and decides; an option whose effect is the `returned` route, and an expiry where the classifier declares no safe default, leave it through its outcome `returned` into `plan.return`. On expiry the classifier's declared fallback is otherwise recorded as an assumption.

|`clean` -> `outline.gate`; `blocking` -> `outline.remediate-qgate`; `infeasible`, `lost` (no verdict) -> `plan.return`.

|[[state-outline.gate]]`outline.gate`
|`phase-3-outline`
|`auto`
|`outline.qgate` (`clean`), `outline.remediate-qgate` (`resolved`, `waived`), `outline.deep` (`bypass`), `outline.light` (`accepted`), `outline.recipe-confirm` (`confirmed`).
|Server gate, never a model or operator approval: passes when the outline Q-Gate returned `clean`, `resolved`, or `waived` (or does not apply: light lane, recipe, surgical bypass), the derivation dry-run passes, and no `3-outline` finding is pending. |`pass` -> `plan.derive-tasks` (phase `phase-4-plan`); `review` -> `outline.review`; `findings_pending` (a pending `3-outline` finding or a failing dry-run, filed as a blocking `3-outline` finding) -> `outline.remediate-qgate`.
