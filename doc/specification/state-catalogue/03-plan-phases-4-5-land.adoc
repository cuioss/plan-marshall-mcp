[#state-catalogue-execute]
== Phase 5: `execute`

Envelopes run serially as tasks of the writer role `implement`: a plan runs at most one writer worker at a time (link:../model-work/04-worker-launch.adoc#model-slots[Model Work Specification, Model Slots]). The plan state reacts only to the envelope task's end, whose return-evaluation primitive `execute.evaluate-envelope-return` declares the closed outcomes `question_pending`, `infeasible_pending`, `chain_tail`, `remediation_chain_tail`, `continue`, `all_complete`, taken in that precedence when several apply. A task that changes files inside the plan's worktree beyond its declared footprint is not reviewed: the server records `realized − declared` as unplanned changes with their provenance (task or loop-back) and lists them in the pull request body and the landing record; only a boundary breach raises `footprint_violation`.

|[[state-execute.verify-sweep]]`execute.verify-sweep`
|`phase-5-execute`
|`composite_job`
|`execute.envelope-ready` (`all_complete`); `execute.route-commit-cause` (`sweep`); `execute.route-build-cause` (`sweep`); `execute.replan` (`done` without a runnable task); `execute.exit-barrier` (`stale`).
|Runs the plan instance's Phase 5 verification steps (`module-tests`, `quality-gate`, `coverage`, `arch-gate`) with footprint-driven scope and the relocation override. |`all_green` -> `execute.exit-barrier`; `red` (plan-caused, or no verdict), `cancelled` (cancelled by the server or the operator) -> `execute.remediate-build` (fact `failed_build: sweep`).

|[[state-execute.exit-barrier]]`execute.exit-barrier`
|`phase-5-execute`
|`auto`
|`execute.verify-sweep` (`all_green`).
|Dual gate evaluated together: pending-tasks and clean-tree gate (every task terminal with its disposition, empty porcelain) and worktree freshness gate (`fresh`, `exempt`, `stale`, `undecidable` with `stale_reason`; a `baseline_red` row counts as passing for its `worktree_sha` only).
|`pass` -> `finalize.settle-commit` (phase `phase-6-finalize`, `settle_trigger` order `0`); `dirty` (a dirty tree, checked before open tasks) -> `execute.remediation-commit`; `stale` (freshness `stale`, or `undecidable` for a reason a build clears) -> `execute.verify-sweep`; freshness `undecidable` with `stale_reason` `unrecognized_build_notation`, `ledger_unreadable`, or `worktree_sha_unavailable`, which no sweep clears, raises xref:01-conventions-generic-conditions.adoc#condition-guard_indeterminate[`guard_indeterminate`] on this state; `runnable_open` (open tasks, runnable tasks remain) -> `execute.envelope-ready`; `none_runnable` (open tasks, none runnable) -> `execute.replan` (trigger `infeasible`).
|link:../phase-workflows/03-q-gate-and-execute.adoc#_phase_5_exit_barrier_dual_freshness_pending_tasks_gates[Phase Workflows Specification, Phase 5 Exit Barrier]

[#state-catalogue-land]
== Land Lane: `land`

Plans started from `local_changes` only. The `land.*` states run in phase `phase-5-execute`. The capture of `land.worktree-init` is one-shot and never repeated. No worker authors the landed change: the plan instance's composition rules prune task allocation, `loop_back`, and in-branch fixes with reason `land_lane` and bind every policy call with `actions: [retry]`; a failure the retries cannot clear hands the plan back, and the user fixes the branch after the run.
