[#state-catalogue-execute]
== Phase 5: `execute`

Envelopes run serially as model jobs: a plan runs at most one model job with write tools at a time (link:../dispatch-and-effort/05-model-job-launch.adoc#model-slots[Model Jobs & Effort Specification, Model Slots]). The plan state reacts only to the envelope job's end, whose return-evaluation primitive `execute.evaluate-envelope-return` declares the closed outcomes `question_pending`, `infeasible_pending`, `chain_tail`, `remediation_chain_tail`, `continue`, `all_complete`, taken in that precedence when several apply. A task that changes files inside the plan's worktree beyond its declared footprint is not reviewed: the server records `realized − declared` as unplanned changes with their provenance (task or loop-back) and lists them in the pull request body and the landing record; only a boundary breach raises `footprint_violation`.

[#state-catalogue-land]
== Land Lane: `land`

Plans started from `local_changes` only. The `land.*` states run in phase `phase-5-execute`. The capture of `land.worktree-init` is one-shot and never repeated. The model never authors the landed change: the plan instance's composition rules prune task allocation, `loop_back`, and in-branch fix links with reason `land_lane` and bind every policy call with `actions: [retry]`; a failure the retries cannot clear hands the plan back, and the user fixes the branch after the run.
