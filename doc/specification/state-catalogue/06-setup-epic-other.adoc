== Project Setup: `setup` (workspace)

Declared in `project-setup.pmwf` (`scope workspace`), hosted by the project's workspace scope; phase value `workspace`. The single start state `setup.entry` records `setup_run: first_run | reconcile` and routes every run by it. The unit has no terminal state: the workspace scope lives as long as the project's enrolment and rests in `setup.completed` between runs, whose `reconcile` link starts the next run. Enrolment (`pm-mcp operator enrol`) creates the workspace scope and is not a state of it; the first run creates `.marshall/` and `.marshall/config/` with the default workflow units, with no legacy input. `project-setup.pmwf` is compiled into the binary and never project-owned. A setup choice is taken on the channel of the store it writes: operator configuration (integration variant, commit identity, operator posture) only through the operator channel, team configuration as a workspace-scope question record (class `setup`). Every question state is preceded by an `auto` probe state that enters it only when something needs an answer. Every setup failure enters `setup.needs-repair`, never a condition (link:../domain-extensions/04-setup-state-machine.adoc#setup-probe-states[Domain Extensions Specification, Probe States]; link:../domain-extensions/04-setup-state-machine.adoc#setup-questions[Setup Choices by Owner]).

== Epic Workflow: `epic`

Declared in `epic.pmwf` (`scope epic`, start `epic.entry`); phase value `orchestrator` (DSL `phase orchestrate`) for every non-terminal state. The DSL excerpt is in link:../dispatch-and-effort/04-epic-coordination.adoc#epic-workflow[Dispatch & Effort Specification, Epic Workflow (`epic.pmwf`)]. No epic state waits for an operator decision; the operator stops an epic with `pm-mcp operator abort epic <epic_id> --reason`.

|[[state-epic.entry]]`epic.entry`
|`orchestrator`
|`auto`
|`pm_start` of an epic (the unit's start state).
|`auto epic.inspect-ledger`: routes by the state of the epic ledger `.marshall/orchestrator/<epic_id>/` in the shared epic worktree, never by a model choice. An unreadable ledger or row raises the `precondition_unmet` condition (`reason: ledger_unreadable`, naming the unreadable files and the parse diagnostic) with `retry` (xref:01-conventions-generic-conditions.adoc#condition-precondition_unmet[Condition precondition unmet]), which ends only when the ledger reads or by the operator's `abort`.

|`orchestrator`
|`link`
|`epic.entry`; `epic.commit-ledger` (every outcome); `epic.landing` (every outcome).
|The epic's resting state: `stage` (`submit`, a scope-wide link without entity: stages a plan as a queue row from `plan_slug` (becomes the `plan_id`; same grammar and phantom checks), `spec_section` (the anchor of a section in `spec.md`, `text[1..128]`), `surface_paths`, `surface_modules?`, `prerequisites?` (`plan_id` list), and `workstream_id?`; the server assigns the row's `ordinal`; refusals `surface_overlap`, `surface_undeclared`); `emit:<plan_id>` (`emit`, `noop`) for `staged` rows whose prerequisites are all `terminal.shipped`; `ingest:<message_id>` (`submit` with `kind: enum[transferred\|re-scoped\|left_alone]` and `note: text[1..2000]?`: claims and processes an inbox message, including intake of a transfer offer and the source disposition); `land-ledger` (`next`, `noop`: the epic landing); `archive` (`next`, `noop`). |A ledger write (`stage`, `emit`, `ingest`, `submit_landing`, `reconcile_landing`, `transfer_offer`) -> `epic.commit-ledger`; `land-ledger` -> `epic.landing`; `archive` -> `epic.archived`.

|`call`

|`done` -> `epic.active`; `stepped_out` -> `epic.active` (the write stays uncommitted and is committed with the next ledger write).

|`orchestrator`
|`job`
|`epic.active` (`land-ledger`).

[#state-catalogue-other]
== Entity Units

Every dispatched sub-agent runs on an entity scope in a state of an entity unit; every entity unit declares `phase inherit`. No entity state waits on a question: a question leaves the entity at once and is answered on the plan scope. The entity terminal feeds the return-evaluation primitive of the parent's `returned:<dispatch_id>` link, which settles the dispatch `RETURNED` only when the entity reached its terminal (otherwise `INCOMPLETE_SUBMISSION`).

[cols="2,1,1,2,3,2,2"]
|===
|State id |Phase value |Kind |Entered from |Offered links / outcomes |Exits to |Defined in

|[[state-entity.active]]`entity.active`
|inherit (entity scope)
|`link`
|The first entity-scoped `pm_state` of a single-submit dispatch (dispatch `ALLOCATED` -> `CLAIMED`): refine and outline authoring, Q-Gate validation (`qgate`), enrichment (`enrich-<module_id>`), simplify, security audit, lessons, spec re-grounding.
|The dispatch kind's one `submit` link. Refine and outline authoring carry their open `questions` inside the `submit`; the parent turns them into question records.
|`submitted` -> `entity.completed`.
|link:../dispatch-and-effort/01-task-envelopes.adoc[Dispatch & Effort Specification, Task Envelopes]; link:../dispatch-and-effort/03-escalation-roles-readers.adoc#question-record-creation[Entity Question Protocol]

|[[state-entity.completed]]`entity.completed`
|inherit (entity scope)
