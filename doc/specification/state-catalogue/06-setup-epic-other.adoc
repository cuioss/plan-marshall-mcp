[#state-catalogue-setup]
== Project Setup: `setup` (workspace)

Declared in `project-setup.pmwf` (`scope workspace`), hosted by the project's workspace scope; phase value `workspace`. The single start state `setup.entry` routes every run by server facts: a first run to `setup.prepare-workspace`, a reconcile run to `setup.reconcile-config`. The unit has no terminal state: the workspace scope lives as long as the project's enrolment and rests in `setup.completed` between runs, whose `reconcile` link starts the next run. Enrolment (`pm-mcp operator enrol`) creates the workspace scope and is not a state of it; the first run creates `.marshall/` and `.marshall/config/` with the default workflow units, with no legacy input. `project-setup.pmwf` is compiled into the binary and never project-owned.

== Epic Workflow: `epic`

Declared in `epic.pmwf` (`scope epic`, start `epic.entry`); phase value `orchestrator` (DSL `phase orchestrate`) for every non-terminal state. The DSL excerpt is in link:../dispatch-and-effort/04-epic-coordination.adoc#epic-workflow[Dispatch & Effort Specification, Epic Workflow (`epic.pmwf`)].

[cols="2,1,1,2,3,2,2"]
|===
|State id |Phase value |Kind |Entered from |Offered links / outcomes |Exits to |Defined in

|[[state-epic.entry]]`epic.entry`
|`orchestrator`
|`auto`
|`pm_start` of an epic (the unit's start state).
|`auto epic.inspect-ledger`: routes by the state of the epic ledger `.marshall/orchestrator/<epic_id>/` in the shared epic worktree, never by a model choice.
|`initialized` (no ledger: the ledger header is created) -> `epic.active`; `resumed` (a readable ledger) -> `epic.active`; an unreadable ledger _(to be specified)_.
|link:../dispatch-and-effort/04-epic-coordination.adoc#epic-workflow[Dispatch & Effort Specification, Epic Workflow]

|[[state-epic.active]]`epic.active`
|`orchestrator`
|`link`
|`epic.entry`; `epic.commit-ledger` (every outcome); `epic.landing` (every outcome); itself (`abort-epic` `resumed`).
|The epic's resting state: `stage` (`submit`, a scope-wide link without entity: stages a plan as a queue row from `plan_slug` (becomes the `plan_id`; same grammar and phantom checks), `spec_section` (the anchor of a section in `spec.md`, `text[1..128]`), `surface_paths`, `surface_modules?`, `prerequisites?` (`plan_id` list), and `workstream_id?`; the server assigns the row's `ordinal`; refusals `surface_overlap`, `surface_undeclared`); `emit:<plan_id>` (`emit`, `submit`) for `staged` rows whose prerequisites are all `terminal.shipped`; `ingest:<message_id>` (`submit` with `kind: enum[transferred\|re-scoped\|left_alone]` and `note: text[1..2000]?`: claims and processes an inbox message, including intake of a transfer offer and the source disposition); `land-ledger` (`next`, `noop`: the epic landing); `archive` (`next`, `noop`). Beside these, the epic links specified in the Dispatch & Effort Specification: `submit_landing:<plan_id>`, `reconcile_landing:<plan_id>`, `transfer_offer:<plan_id>`, `mailbox_send:<plan_id>`, spec re-grounding dispatches (read-only entity scope, draft `submit` only) or the inline fallback; and `abort` (rel `escalate`, the request `abort-epic`). Observes `launched` -> `running` from the child's entry record.
|A ledger write (`stage`, `emit`, `ingest`, `submit_landing`, `reconcile_landing`, `transfer_offer`) -> `epic.commit-ledger`; `land-ledger` -> `epic.landing`; `archive` -> `epic.archived`; `abort-epic` `aborted` -> `epic.aborted`, `resumed` -> this state.
|link:../dispatch-and-effort/04-epic-coordination.adoc#_why_epics_emit_plans_rather_than_dispatching_sub_agents[Dispatch & Effort Specification, Epic Plan Emission]; link:../dispatch-and-effort/04-epic-coordination.adoc#epic-surface-disjointness[Staging-Time Surface Disjointness]; link:../dispatch-and-effort/04-epic-coordination.adoc#cross-epic-transfer[Cross-Epic Intake & Transfer]; link:../dispatch-and-effort/04-epic-coordination.adoc#_server_derived_landing_facts_spec_re_grounding_cross_plan_locks[Server-Derived Landing Facts]

|[[state-epic.commit-ledger]]`epic.commit-ledger`
|`orchestrator`
|`call`
|`epic.active` (a ledger write).
|`call git.commit_and_push (message_mode=step_or_fallback, push_mode=never)` in the shared epic worktree on the fixed epic branch, staging only `.marshall/orchestrator/**`.
|`committed_local`, `committed_and_pushed`, `pushed_clean`, `in_sync`, `clean` -> `epic.active`; `aborted` -> `epic.active` (the write stays uncommitted and is committed with the next ledger write).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_call_site_reuse_matrix_across_workflows[Workflow DSL Specification, Call-Site Reuse Matrix]

|[[state-epic.landing]]`epic.landing`
|`orchestrator`
|`job`
|`epic.active` (`land-ledger`).
|The epic landing: one pull request from the epic branch for all pending ledger changes; repository-wide epics-worktree lock; ledger paths only; required CI checks only; waits for `merged`, `ejected`, `closed`, or `timed_out`; post-merge fast-forward and epic-branch resync. Implicit `wait:` / `cancel:` links. Its git steps are the primitives of the plan merge (`git.stage-and-commit`, `git.push`, `ci.pr-create`, `ci.merge` or `ci.enqueue` bound to the expected head SHA, `ci.pr-observe`) under the epics-worktree lock, with the stall-based queue bound of `finalize.merge-queue-wait`.
|`succeeded` (observed `merged`) -> `epic.active`; `failed` (`ejected`, `closed`, `timed_out`) and every other job outcome, `cancelled` included -> `epic.active` (worktree and branch unchanged, so `land-ledger` resumes).
|link:../dispatch-and-effort/04-epic-coordination.adoc#epic-landing[Dispatch & Effort Specification, Epic Landing]

|[[state-epic.archived]]`epic.archived`
|`completed`
|`terminal`
|`epic.active` (`archive`).
|`links[0]`. Declared `state epic.archived terminal archived success`; the `archive` link's primitive (`epic.archive-ledger`) moves the ledger directory to `.marshall/archived-orchestrators/<epic_id>-<YY-MM-DD>/` in the transaction that enters it.
|—
|link:../filesystem-layout.adoc#archives[Filesystem Layout Specification, Plan & Epic Archives]

|[[state-epic.aborted]]`epic.aborted`
|`aborted`
|`terminal`
|`epic.active` (`abort-epic`: `aborted`); the `ABORTED` outcome of an engine-raised decision on the epic scope (xref:01-conventions-generic-conditions.adoc#condition-blocked[Condition blocked]).
|`links[0]`. Declared `state epic.aborted terminal aborted failure`.
|—
|link:../workflow-dsl/02-units-jobs-decisions.adoc#decision-registry[Workflow DSL Specification, Decision Registry (`abort-epic`)]
