[#state-catalogue-other]
== Entity Units

Every task of a model state is worked on an entity scope in a state of an entity unit, reached through its worker's job-bound connection (or the entry session's connection, where the session takes the task as an optional worker), which admits only the entity's links and, read-only, the resources of the task's own project and `skill://pm/…` (link:../mcp-tools/01-core-workflow-tools.adoc[MCP Tools Specification, Core Workflow Tools]); every entity unit declares `phase inherit`. No entity state waits on a question: a question ends the task `asked` and is answered on the owning scope. An entity kind that submits once runs `entity.pmwf`, a kind that submits several times `entity-multi.pmwf`, a task envelope its envelope unit. When the task ends, the return-evaluation primitive of the model state reads the entity's persisted records; an attempt whose entity did not reach its terminal is offered again (`job_incomplete`, xref:01-conventions-generic-conditions.adoc#condition-job_incomplete[Condition job incomplete]). The bootstrap units `bootstrap-plan` and `bootstrap-epic` are entity units of the workspace scope, catalogued in xref:09-bootstrap-and-lessons.adoc#state-catalogue-bootstrap[Bootstrap].

[#state-catalogue-worker-task]
== Task Protocol Unit: `worker-task`

Declared in `worker-task.pmwf` (`scope subworkflow`, compiled only, start `task.queued`; link:../workflow-dsl/02-units-jobs-decisions.adoc#worker-task-unit[Workflow DSL Specification, Task Protocol Unit]). Every model state runs one instance per task in the task's own frame, recorded in the queue task record and never on the scope's `call_stack`; no unit calls it with `call`. Every state declares `phase inherit`: the phase value is that of the scope that owns the task. Every transition is an engine event or an `auto` primitive: the worker follows only `ack`, the links of the task's entity unit, and the `consult:<role>` links of the calling state. The terminal outcomes are the closed task outcomes, which the calling model state routes (xref:01-conventions-generic-conditions.adoc#_state_kinds[State Kinds]); leases, generations, and fencing are specified in link:../model-work/02-task-protocol.adoc[Model Work Specification, Task Protocol].
