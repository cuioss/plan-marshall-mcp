== Entity Units

Every model job runs on an entity scope in a state of an entity unit, reached through its job-bound connection, which admits only the entity's links and, read-only, the resources of the job's own project and `skill://pm/…` (link:../mcp-tools/01-core-workflow-tools.adoc[MCP Tools Specification, Core Workflow Tools]); every entity unit declares `phase inherit`. No entity state waits on a question: a question leaves the entity at once and is answered on the plan scope. An entity kind that submits once runs `entity.pmwf`, a kind that submits several times `entity-multi.pmwf`, a task envelope its envelope unit. When the job ends, the return-evaluation primitive of the job state reads the entity's persisted records; an entity that did not reach its terminal raises `job_incomplete` (xref:01-conventions-generic-conditions.adoc#condition-job_incomplete[Condition job incomplete]). The bootstrap units `bootstrap-plan` and `bootstrap-epic` are entity units of the workspace scope, catalogued in xref:09-bootstrap-and-lessons.adoc#state-catalogue-bootstrap[Bootstrap].

|[[state-envelope.task.active]]`envelope.task.active`
|inherit (entity scope)
|`link`
|The first entity-scoped `pm_state` of the model job of `envelope-M` (recorded as `connected_at`); itself after each `submit:TASK-i` that is neither the last task nor a chain tail.
|`submit:TASK-NNN`; `ask:TASK-NNN` (`question:schema[question-envelope]`: records a question record of class `task` and ends the entity); `infeasible:TASK-NNN`; `yield:envelope-M` (no parameter). `facts.task_id` names the current task. |Next task -> this state; the last task, a chain-tail task, `ask`, or `yield` -> `envelope.completed`; on every early end the remaining tasks, an asking task included, move to `envelope-(M+1)`, whose job carries a question's answer in `facts`.
