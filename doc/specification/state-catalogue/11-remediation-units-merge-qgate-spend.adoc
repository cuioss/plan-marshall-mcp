== Remediation Units: Merge Conflict, Q-Gate Findings & Spend
_See Requirement link:../../Requirements.adoc#PM-WF-16[PM-WF-16: Reusable Compound Sub-Workflows & Config-Driven Git Commit/Push]_

The units of this part follow the conventions, the contract, the decision rules, and the generic states of xref:08-remediation-units.adoc#state-catalogue-remediation[Remediation Units]; every state declares `phase inherit`.

[#state-catalogue-remediation-merge]
=== `remediation.merge-conflict`

The unit's action set is `retry` and `fix`. A merge conflict is not waivable, so `request_waiver` is never offered. With the shipped bindings (`actions=[fix]`, retry budget `0`) `decide` offers only `fix`, and the server takes it without a task.

|`composite_job remediation.gather-conflict-evidence`: first attempts the server rebase onto the observed remote head (a lease rejection without a content conflict needs no fix); a clean rebase settles `none`. |`retry` -> `remediation-merge.rerun`; `fix` -> `remediation-merge.apply-fix`; `lost` -> `remediation-merge.conservative`.
|link:../phase-workflows/01-planning-phases-1-2.adoc#_remediation_policy_calls[Phase Workflows Specification, Remediation Policy Calls]

|[[state-remediation-merge.rerun]]`remediation-merge.rerun`
|inherit
|`composite_job`
|`remediation-merge.decide`, `remediation-merge.choose`, `remediation-merge.conservative` (`retry`).
|`composite_job remediation.rerun-integration`: the retry waits the retry backoff (`TIME`, link:../timeouts/01-job-budgets-and-waits.adoc#server-retry-backoff[Timeouts & Budgets Specification, Server Retry Backoff]), then aborts the rebase in progress, fetches the base and the remote branch (`EXTERNAL_STATE`), and runs the integration again without a code change, charged to the retry budget; never a forced push over foreign commits. The unit's retry cycle therefore passes two job states and is no engine-chained cycle (Rule 11a).
|`rebased` -> `remediation-merge.resolved`; `conflict`, `cancelled` -> `remediation-merge.gather`.
|link:../workflow-dsl/08-remediation-units.adoc#unit-template[Workflow DSL Specification, Unit Template]

|[[state-remediation-merge.continue]]`remediation-merge.continue`
|inherit
|`auto`
|`remediation-merge.apply-fix` (`fixed`).
|`auto remediation.continue-integration`: continues the rebase with the resolved files, or rebases onto the observed remote head; never a forced push over foreign commits.
|`rebased` -> `remediation-merge.resolved`; `conflict` -> `remediation-merge.gather`.
|link:../phase-workflows/06-finalize-re-entry-and-merge.adoc#merge-path[Phase Workflows Specification, Merge Path]
|===

[#state-catalogue-remediation-qgate]
=== `remediation.qgate-findings`

The unit's action set is `fix`; the Q-Gate findings are waivable, so `decide` also offers `request_waiver` while `remediation.waiver-requestable` holds. With the shipped bindings (`actions=[fix]`, waiver wait `0`) `decide` offers only `fix`, and the server takes it without a task.

[cols="2,1,1,2,3,2,2"]
|===
|State id |Phase value |Kind |Entered from |Offered links / outcomes |Exits to |Defined in

|[[state-remediation-qgate.gather]]`remediation-qgate.gather`
|inherit
|`auto`
|`call` (start state).
|`remediation.gather-qgate-evidence`: the calling phase's blocking Q-Gate findings (including a filed derivation failure).
|`failures` -> `remediation-qgate.budget-check`; `none` -> `remediation-qgate.resolved`; `all_waived` (`qgate_findings:<phase>`; the findings dispositioned accepted by waiver) -> `remediation-qgate.waived`.
|link:../phase-workflows/03-q-gate-and-execute.adoc#_q_gate_validation_loop[Phase Workflows Specification, Q-Gate Validation Loop]

|[[state-remediation-qgate.decide]]`remediation-qgate.decide`
|inherit
|`auto`
|`remediation-qgate.budget-check` (`budget_left`).
|`auto remediation.offer-actions` (xref:08-remediation-units.adoc#remediation-decide[Deciding the Remedy]) over `fix` and `request_waiver` (`qgate_findings:<phase>`). A `fix` hands the findings in `facts.qgate_findings` to the caller's rework (a new authoring task, or `plan.revise-tasks`), where an unchanged artifact is refused `fix_unchanged` at its re-submission.
|`fix` -> `remediation-qgate.fix-requested`; `choice` -> `remediation-qgate.choose`.
|link:../workflow-dsl/08-remediation-units.adoc#unit-template[Workflow DSL Specification, Unit Template]

|[[state-remediation-qgate.choose]]`remediation-qgate.choose`
|inherit
|`job`
|`remediation-qgate.decide` (`choice`).
|`job llm remediation-decision role qgate` (xref:08-remediation-units.adoc#remediation-decide[Deciding the Remedy]): `facts`: the blocking findings with the artifact they rest on and the remaining fix budget. Skill `pm/plan/qgate-remediation`.
|`fix` -> `remediation-qgate.fix-requested`; `request_waiver` -> `remediation-qgate.waiver-wait`; `lost` -> `remediation-qgate.conservative`.
|link:../phase-workflows/03-q-gate-and-execute.adoc#_q_gate_validation_loop[Phase Workflows Specification, Q-Gate Validation Loop]

[#state-catalogue-remediation-spend]
=== `remediation.spend`

A degenerate unit: no `retry`, no `fix`, and no `decide`. The spend ceiling is not raisable: only a `met` waiver of the gate `spend` lets the plan pass, and `merge.gate-entry` is the single point that reads it; the unit's waiver wait, when bound, only waits for that waiver.

|State id |Phase value |Kind |Entered from |Offered links / outcomes |Exits to |Defined in

|[[state-remediation-spend.gather]]`remediation-spend.gather`
|inherit
|`auto`
|`call` (start state).
|`remediation.gather-spend-report`: cumulative finalize spend (`finalize.spend-ratio`) against the `spend` ceiling; it performs no waiver lookup.
|`within_ceiling` -> `remediation-spend.resolved`; `over` -> `remediation-spend.budget-check` (whose `exhausted_wait` enters the waiver wait only while `waiver_wait_seconds > 0`).
|link:../model-work/09-completion-usage-and-spend.adoc#spend-accounting-budget-anchors[Model Work Specification, Spend Accounting]
