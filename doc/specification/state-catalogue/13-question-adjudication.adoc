[#state-catalogue-adjudicate]
== Unit `question.adjudicate`
_See Requirement link:../../Requirements.adoc#PM-WF-18[PM-WF-18: Question Recommendation Score & Decision Quorum]_

The adjudication, its decision declarations, the blind input, the decision rule, and the record are specified in link:../model-work/10-decision-quorum.adoc#adjudication[Model Work Specification, Ask or Quorum]; the unit and its binding in link:../workflow-dsl/02-units-jobs-decisions.adoc#question-adjudicate-unit[Workflow DSL Specification, Adjudication Unit]. The unit (`question-adjudicate.pmwf`, project-owned; its `decide` lines declare per decision kind `ask` or a quorum, link:../model-work/10-decision-quorum.adoc#decision-declarations[Model Work Specification, Decision Declarations]) is run by every question state of every scope (a plan's question states run the project's copy, the question states of the project setup the default unit) (`awaiting_user`, among them `init.recipe-candidate`, `init.sibling-collision`, `init.domain-choice`, `refine.awaiting_answers`, `outline.awaiting_answers`, `outline.review`, `execute.task-question`, every `<state>.asked`, and the question states of the project setup) for the scope's new question set before it is delivered. Its states declare `phase inherit` and are named `adjudicate.<state>`; no state of the unit is a link state, and none asks the user or the operator. Exit contract: `decided` and `escalated`; the engine routes `stepped_out` like `escalated`.

|[[state-adjudicate.check]]`adjudicate.check`
|inherit
|`auto`
|Entering a question state (start state, the new question set bound).
|`question.check-adjudication`: the class's effective mode is `quorum`, and for every question of the set its kind is declared `quorum`, the declaration passes the validation and is calibrated, every listed role is available and qualified, and a listed asking role's confidence reaches the score. |`eligible` -> `adjudicate.vote`; `ineligible` (reason `kind_ask`, `quorum_invalid`, `calibration_failed`, `role_unavailable`, `role_unqualified`, or `below_score`) -> `adjudicate.escalated`.

|[[state-adjudicate.vote]]`adjudicate.vote`
|inherit
|`job`
|`adjudicate.check` (`eligible`).
|`job llm vote role each question.vote-roles`: one fresh task per listed role of the set's quorum declarations other than the asking role, each on its own entity `vote-<question_set>-<role>` with the blind facts of the questions whose declaration lists it and one closing link `submit:vote`; never offered to the entry session. The declared vote wait is the vote tasks' own deadline: a task still open when it passes closes `lost`, so the state awaits only the end of its tasks (`TASK_SETTLED`). The return evaluation records each answer; a task without a valid answer, a `lost` one included, is a missing vote. An empty list settles `collected` at once.
|`collected` -> `adjudicate.decide`; `lost` (no task of the list could be served) -> `adjudicate.escalated`.
|link:../model-work/10-decision-quorum.adoc#blind-input[Model Work Specification, Blind Input]; link:../timeouts/01-job-budgets-and-waits.adoc#vote-wait[Timeouts & Budgets Specification, Vote Wait]

|[[state-adjudicate.decide]]`adjudicate.decide`
|inherit
|`auto`
|`adjudicate.vote` (`collected`).
|`question.decide-agreement`: the decision rule per question of the set, over the votes of its declaration's listed roles (the asking role's recommendation where it is listed).
|`agreed` (every question decided) -> `adjudicate.decided`; `not_agreed` (reason `role_unavailable`, `disagreement`, or `below_score`) -> `adjudicate.escalated`.
|link:../model-work/10-decision-quorum.adoc#decision-rule[Model Work Specification, Decision Rule]

|[[state-adjudicate.decided]]`adjudicate.decided`
|inherit
|`terminal`
|`adjudicate.decide` (`agreed`).
|Terminal `decided` (class `success`): its transaction writes one `question.adjudicate` decision record per question (reason `agreement`, every vote), the set's `adjudicated` lines naming them, and answers every question with its agreed option, `channel: quorum`; the question state takes the resolution outcome of that answer.
|Returns `decided` to the question state.
|link:../model-work/10-decision-quorum.adoc#adjudication-record[Model Work Specification, Record, Delivery & Audit]

|[[state-adjudicate.escalated]]`adjudicate.escalated`
|inherit
|`terminal`
|`adjudicate.check` (`ineligible`); `adjudicate.vote` (`lost`); `adjudicate.decide` (`not_agreed`).
|Terminal `escalated` (class `success`): in mode `quorum` its transaction writes one `question.adjudicate` decision record per question with the reason and the votes taken, the set's `adjudicated` lines naming them, and sets the deadline from the delivery; the set is then delivered per its mode (`auto` handling in mode `quorum`).
|Returns `escalated` to the question state, which rests until the records resolve.
