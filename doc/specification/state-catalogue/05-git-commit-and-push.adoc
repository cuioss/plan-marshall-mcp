[#state-catalogue-git]
== Sub-Workflow `git.commit_and_push`

Declared in `git-commit-and-push.pmwf` (`scope subworkflow`, start `git.inspect-worktree`). Every state declares `phase inherit`: the phase value is the caller's. Callers: `execute.chain-tail-commit`, `execute.remediation-commit`, `finalize.settle-commit`, `finalize.push-barrier`, `setup.land-changes`, `epic.commit-ledger`. Every caller routes the terminal outcome `aborted` (class `aborted`) to one of its own `link` states, never to its scope's abort terminal (link:../workflow-dsl/04-ast-node-model.adoc#static-verification-rules[Workflow DSL Specification, Static Verification Rule 6]).

The sub-workflow has three operator escalations (`gitignore_oracle_failure`, `force_stale_push`, `force_push_with_lease`); each `approved` exit enters an `auto` state performing the approved action (link:../workflow-dsl/04-ast-node-model.adoc#static-verification-rules[Static Verification Rule 10]): `git.stage-under-oracle-override`, `git.push-under-freshness-override`, `git.push-with-lease`. A hook failure is never bypassed (`git.commit-fix`), and a rebase conflict is resolved by the model (`git.resolve-conflicts`). Every caller routes `in_sync` like `pushed_clean`.

|[[state-git.stage-under-oracle-override]]`git.stage-under-oracle-override`
|inherit
|`auto`

|`auto git.apply-oracle-override`, the approved action (Rule 10): records an override bound to the current `HEAD` naming the paths the `.gitignore` oracle could not classify; the next `git.stage-and-commit` stages them under it.
|`recorded` -> `git.resolve-message`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 2]; link:../workflow-dsl/02-units-jobs-decisions.adoc#decision-registry[Decision Registry]

|Resolves the deterministic message for `auto_deliverable` / `step_or_fallback`.
|`ready` -> `git.stage-and-commit`; `needs_interactive` -> `git.compose-message`.

|[[state-git.compose-message]]`git.compose-message`

|`commit` (`next`, `submit`, `message:text[1..2000]`, a `Co-Authored-By:` line is rejected); `abort` (`noop`). Skill `pm/git/commit-message`; `facts`: `git.diff-summary`.
|`valid` -> `git.stage-and-commit`; `aborted` -> `git.done-aborted`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 3]

|[[state-git.stage-and-commit]]`git.stage-and-commit`
|inherit
|`auto`
|`git.resolve-message` (`ready`); `git.compose-message`, `git.commit-fix` (`valid`).
|First, for every caller, the footprint check (worktree boundary and staging set, pinned build files, main checkout since `entry_baseline`); a violation raises the `footprint_violation` condition on this state (xref:01-conventions-generic-conditions.adoc#condition-footprint_violation[Condition footprint violation]) and nothing is committed. Then stages only the plan-derived staging set (and paths under a recorded oracle override); commits over `stdin` with the operator's `commit_identity` as author and the resolved agent identity as committer, identically in both variants; appends a `kind = "change"` ledger row; re-stamps `head_at_completion` and writes `freshness_reconcile` for Phase 6 `mutates_source` steps.
|`committed`, `nothing_to_commit` -> `git.evaluate-push-policy`; `hook_failed` -> `git.commit-fix`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 4]

|[[state-git.commit-fix]]`git.commit-fix`
|inherit
|`link`
|`git.stage-and-commit` (`hook_failed`); itself.
|`retry` (`noop`); `recompose` (`fix`, `submit`, `message`); `abort` (`noop`). No hook bypass exists. Reached only in the CLI variant, the only one that runs hooks. Skill `pm/git/commit-recovery`; `facts`: `git.hook-failure`.
|`ok` -> `git.evaluate-push-policy`; `hook_failed` -> `git.commit-fix`; `attempts_exhausted` (compiled cap: `3` failed commit attempts per identical staged change set, the staged tree id and the message; the counter resets when either changes through a fix, a hook rewrite, or `recompose`) -> `git.done-aborted`, whose `aborted` the caller routes to its `<phase>.commit-aborted`; `valid` -> `git.stage-and-commit`; `aborted` -> `git.done-aborted`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_declarative_dsl_definition_classpathworkflowsgit_commit_and_push_pmwf[Workflow DSL Specification, DSL Definition]

|[[state-git.evaluate-push-policy]]`git.evaluate-push-policy`
|inherit
|`auto`
|`git.inspect-worktree` (`clean_needs_push_check`), `git.stage-and-commit`, `git.commit-fix` (`ok`).
|Evaluates `push_mode` with the derived fact `push_remote` (no push remote: nothing is pushed, the plan runs local-only) and, for `post_pr_conditional`, the caller step's `order > 20`.
|`skip_push_committed` -> `git.done-committed-local`; `skip_push_clean` -> `git.done-clean`; `push_required` -> `git.verify-freshness`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 5]

|[[state-git.verify-freshness]]`git.verify-freshness`
|inherit
|`auto`
|`git.evaluate-push-policy` (`push_required`); `git.freshness-build-running` (`succeeded`); `git.sync-required`, `git.resolve-conflicts`, `git.sync-escalate` (`rebased`).
|`git.pre-commit-verify-freshness` over `change-ledger.jsonl` (`fresh`, `exempt`, or reconciled by `freshness_reconcile`).
|`fresh_or_exempt` -> `git.check-branch-parity`; `stale_or_undecidable` -> `git.freshness-blocked`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 5]

|[[state-git.freshness-blocked]]`git.freshness-blocked`
|inherit
|`link`
|`git.verify-freshness` (`stale_or_undecidable`); `git.freshness-build-running` (every non-success outcome).
|`run_verification_build` (`fix`, `noop`); `escalate` (`force_stale_push`). Skill `pm/finalize/push-barrier`; `facts`: `stale_reason`, `admitted_causes`, required notations, scope (the current `worktree_sha` stays in the ledger and audit record; the model makes no decision on it).
|`started` -> `git.freshness-build-running`; `approved` -> `git.push-under-freshness-override`; `denied` -> `git.done-aborted`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 5]

|[[state-git.freshness-build-running]]`git.freshness-build-running`
|inherit
|`job`
|`git.freshness-blocked` (`started`).
|`build.verify-worktree`; implicit `wait:` / `cancel:` links.
|`succeeded` -> `git.verify-freshness`; `failed`, `failed_unparsed`, `refused`, `cancelled`, `timed_out`, `killed`, `indeterminate` -> `git.freshness-blocked`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_declarative_dsl_definition_classpathworkflowsgit_commit_and_push_pmwf[Workflow DSL Specification, DSL Definition]

|[[state-git.push-under-freshness-override]]`git.push-under-freshness-override`
|inherit
|`auto`
|`git.freshness-blocked` (`force_stale_push`: `approved`).
|`auto git.push`, the approved action (Rule 10), under an override record bound to the current `HEAD` and the rendered `stale_reason`; sets or refreshes `branch_pushed_at`.
|`pushed_with_commit` -> `git.done-committed-and-pushed`; `pushed_clean_tree` -> `git.done-pushed-clean`; `up_to_date` -> `git.done-in-sync`; `rejected_non_ff`, `rejected_lease` -> `git.sync-required` (the outcome set of `git.push`, routed alike in all three push states).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 5]; link:../workflow-dsl/02-units-jobs-decisions.adoc#decision-registry[Decision Registry]

|[[state-git.check-branch-parity]]`git.check-branch-parity`
|inherit
|`auto`
|`git.verify-freshness` (`fresh_or_exempt`).
|`git.push-barrier-decision`: `first_push` when `branch_pushed_at` is unset; otherwise `git.branch-sync-state` (fetched) with `refire` only for `ahead` and for `never_pushed` (a `remote_absent_unverified` branch for which `ci.pr-find` found no pull request); a merged pull request makes it `remote_absent_landed`.
|`first_push`, `refire` -> `git.execute-push`; `skip` -> `git.done-in-sync`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 6]

|[[state-git.execute-push]]`git.execute-push`
|inherit
|`auto`
|`git.check-branch-parity` (`first_push`, `refire`).
|`git.push`; sets `branch_pushed_at` on the first successful push and refreshes it on every later one.
|`pushed_with_commit` -> `git.done-committed-and-pushed`; `pushed_clean_tree` -> `git.done-pushed-clean`; `up_to_date` -> `git.done-in-sync`; `rejected_non_ff`, `rejected_lease` -> `git.sync-required` (the outcome set of `git.push`, routed alike in all three push states).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 6]

|[[state-git.sync-required]]`git.sync-required`
|inherit
|`link`
|`git.execute-push`, `git.push-under-freshness-override`, `git.push-with-lease` (`rejected_non_ff`, `rejected_lease`).
|`sync_rebase` (`fix`, `noop`); `escalate` (`force_push_with_lease`). Skill `pm/git/sync-recovery`; `facts`: `git.branch-divergence`.
|`rebased` -> `git.verify-freshness`; `conflict` -> `git.resolve-conflicts`; `approved` -> `git.push-with-lease`; `denied` -> `git.done-aborted`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_declarative_dsl_definition_classpathworkflowsgit_commit_and_push_pmwf[Workflow DSL Specification, DSL Definition]

|[[state-git.push-with-lease]]`git.push-with-lease`
|inherit
|`auto`
|`git.sync-required` (`force_push_with_lease`: `approved`).
|`auto git.push`, the approved forced push (Rule 10), with an explicit lease: the `remote_sha` observed at the rejection, else the last recorded push (`branch_pushed_at`), re-read by `ls-remote` before the push; never the remote-tracking ref. Refreshes `branch_pushed_at`.
|`pushed_with_commit` -> `git.done-committed-and-pushed`; `pushed_clean_tree` -> `git.done-pushed-clean`; `up_to_date` -> `git.done-in-sync`; `rejected_non_ff`, `rejected_lease` -> `git.sync-required` (the outcome set of `git.push`, routed alike in all three push states).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 6]; link:../workflow-dsl/02-units-jobs-decisions.adoc#decision-registry[Decision Registry]

|[[state-git.resolve-conflicts]]`git.resolve-conflicts`
|inherit
|`link`
|`git.sync-required` (`sync_rebase`: `conflict`); `git.sync-escalate` (`retry`: `conflict`); itself (`conflict`).
|The model resolves the conflicted files in the checkout. `continue_rebase` (`fix`, `noop`, `git.rebase-continue`); `abort_rebase` (`alt`, `noop`, `git.rebase-abort`, restores the pre-rebase branch). Skill `pm/git/sync-recovery`; `facts`: `git.rebase-conflict` (the conflicted paths).
|`rebased` -> `git.verify-freshness`; `conflict` -> `git.resolve-conflicts`; `aborted` -> `git.sync-escalate`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_declarative_dsl_definition_classpathworkflowsgit_commit_and_push_pmwf[Workflow DSL Specification, DSL Definition]

|[[state-git.sync-escalate]]`git.sync-escalate`
|inherit
|`link`
|`git.resolve-conflicts` (`abort_rebase`: `aborted`).
|`retry` (`noop`, `git.rebase-onto-upstream`); `abort` (`noop`). No operator decision. `facts`: `git.rebase-conflict`.
|`rebased` -> `git.verify-freshness`; `conflict` -> `git.resolve-conflicts`; `aborted` -> `git.done-aborted` (the caller's `<phase>.commit-aborted` offers `abort-plan`).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_declarative_dsl_definition_classpathworkflowsgit_commit_and_push_pmwf[Workflow DSL Specification, DSL Definition]

|[[state-git.done-aborted]]`git.done-aborted`
|inherit
|`terminal`
|`abort` links of `git.artifact-review`, `git.compose-message`, `git.commit-fix`, and `git.sync-escalate`; `git.commit-fix` (`attempts_exhausted`); denied escalations.
|Returns outcome `aborted` (class `aborted`): it only leaves the sub-workflow and never ends the calling scope.
|The caller's `aborted` transition, into a `link` state of the caller: `execute.commit-aborted`, `finalize.commit-aborted` (xref:01-conventions-generic-conditions.adoc#state-phase.commit-aborted[Commit aborted]), `setup.commit-changes`, `epic.active`.
