== Sub-Workflow `git.commit_and_push`

Declared in `git-commit-and-push.pmwf` (`scope subworkflow`, start `git.inspect-worktree`). Every state declares `phase inherit`: the phase value is the caller's. Callers: `execute.chain-tail-commit`, `execute.remediation-commit`, `finalize.settle-commit`, `finalize.push-barrier`, `setup.land-changes`, `epic.commit-ledger`, `epic.commit-decomposition`, and the `commit-fix` states of the remediation units.

The unit has no `link` state: every state is server logic or a task of a role, so no session drives it and it offers no `step_out`. Its model states are `git.artifact-review` (role `artifact-review`), `git.compose-message` (role `commit-message`), `git.commit-fix` and `git.resolve-conflicts` (role `implement`, the writer role); each task runs in the caller's checkout (the plan worktree, the primary checkout at the enrolled `project_root` for `setup.land-changes`, or the shared epic worktree) and asks for one judgment or one piece of work, naming its skill section. Every recovery loop is bounded by a compiled attempt cap (link:../timeouts/01-job-budgets-and-waits.adoc#commit-attempt-caps[Timeouts & Budgets Specification, Commit Sub-Process Attempt Caps]) and the mechanical recoveries are the server's own: a non-fast-forward rejection is integrated by a server rebase (`git.sync-required`), and a stale freshness verdict by a verification build (`git.freshness-blocked`).

*Exit contract* (link:../workflow-dsl/04-ast-node-model.adoc#static-verification-rules[Workflow DSL Specification, Rule 6]): `done` with the result record `{commit: sha?, pushed: bool, landed: bool, clean: bool}`, where `pushed` means that the remote branch holds `HEAD` after the call (so a branch already in sync is `{commit: null, pushed: true, landed: false, clean: true}`) and `landed` that the remote branch is gone because its pull request merged (`pushed: false`), and the control outcome `stepped_out {by: server, cause, reason}`. Callers branch on the result by complementary guards (`guard result.pushed`, `guard result.landed`). The server steps out (`git.stepped-out`) after a spent attempt cap or oracle retry, when a rebase could not start, when the remote state of the branch cannot be established, and when a task of the unit ends `infeasible` or `lost` (its re-offers spent, or its role unqualified), except a task of `commit-message`, whose fallback is the template message (`git.template-message`). An indeterminate derived fact `push_remote` raises `precondition_unmet` (`push_remote_indeterminate`) with its bounded server retry; a spent condition budget unwinds every frame to the plan's fallback. A hook failure is never bypassed (`git.commit-fix`), and a lease-protected force push to the plan's own branch after a server rebase is routine (`git.push-with-lease`); any other force push is refused.

|[[state-git.stage-and-commit]]`git.stage-and-commit`
|inherit
|`auto`
|`git.resolve-message` (`ready`); `git.compose-message` (`valid`); `git.template-message` (`ready`); `git.commit-fix` (`fixed`).
|First, for every caller, the footprint check for boundary breaches (a path outside the plan's worktree, a pinned build file or protected path, a main-checkout change since `entry_baseline`); a breach raises the `footprint_violation` condition on this state (xref:01-conventions-generic-conditions.adoc#condition-footprint_violation[Condition footprint violation]) and nothing is committed. Paths inside the worktree beyond the declared footprint are staged and recorded as unplanned changes with their provenance. Commits over `stdin` with the operator's `commit_identity` as author and the resolved agent identity as committer, identically in both variants; appends a `kind = "change"` ledger row; re-stamps `head_at_completion` and writes `freshness_reconcile` for Phase 6 `mutates_source` steps. Counts failed commit attempts per identical staged change set (the staged tree id and the message), a counter that resets when either changes, and the `git.commit-fix` tasks of the call frame (compiled cap `3` per call, link:../timeouts/01-job-budgets-and-waits.adoc#commit-attempt-caps[Timeouts & Budgets Specification, Commit Sub-Process Attempt Caps]).
|`committed`, `nothing_to_commit` -> `git.evaluate-push-policy`; `hook_failed` (both caps left: the failed commit attempts per identical staged change set, link:../timeouts/01-job-budgets-and-waits.adoc#commit-fix-change-set-cap[Timeouts & Budgets Specification, `git.commit-fix` Change-Set Cap], and the `git.commit-fix` tasks per call, link:../timeouts/01-job-budgets-and-waits.adoc#commit-attempt-caps[Commit Sub-Process Attempt Caps]) -> `git.commit-fix`; `attempts_exhausted` (either cap spent) -> `git.stepped-out` (cause `attempts_exhausted`).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 4]

|[[state-git.commit-fix]]`git.commit-fix`
|inherit
|`job`
|`git.stage-and-commit` (`hook_failed`).
|`job llm commit-fix role implement`: `facts`: `git.hook-failure`; the worker fixes what the hook reports in the checkout and submits `fixed` (optional `message` to recompose the message, validated like `git.compose-message`). No hook bypass exists. Reached only in the CLI variant, the only one that runs hooks. Skill `pm/git/commit-recovery`.
|`fixed` -> `git.stage-and-commit`, which re-runs the footprint check and the commit; `infeasible`, `lost` -> `git.stepped-out` (cause `infeasible` or `lost`).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_declarative_dsl_definition_classpathworkflowsgit_commit_and_push_pmwf[Workflow DSL Specification, DSL Definition]

|[[state-git.evaluate-push-policy]]`git.evaluate-push-policy`
|inherit
|`auto`
|`git.inspect-worktree` (`clean_needs_push_check`), `git.stage-and-commit` (`committed`, `nothing_to_commit`).
|Evaluates `push_mode` with the derived fact `push_remote` (no push remote: nothing is pushed) and, for `post_pr_conditional`, the `order` of the persisted `settle_trigger` (`> 20`). An indeterminate `push_remote` is no outcome: it raises the `precondition_unmet` condition (`reason: push_remote_indeterminate`) on this state, whose server retry re-derives the fact within the condition budget; a spent budget takes the plan's fallback (xref:01-conventions-generic-conditions.adoc#condition-precondition_unmet[Condition precondition unmet]).
|`skip_push` -> `git.done`; `push_required` -> `git.verify-freshness`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 5]

|[[state-git.verify-freshness]]`git.verify-freshness`
|inherit
|`auto`
|`git.evaluate-push-policy` (`push_required`); `git.freshness-build-running` (`succeeded`); `git.sync-required`, `git.continue-rebase` (`rebased`).
|`git.pre-commit-verify-freshness` over `change-ledger.jsonl` (`fresh`, `exempt`, a `baseline_red` row of the same `worktree_sha`, or reconciled by `freshness_reconcile`).
|`fresh_or_exempt` -> `git.check-branch-parity`; `stale_or_undecidable` -> `git.freshness-blocked`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 5]

|[[state-git.freshness-blocked]]`git.freshness-blocked`
|inherit
|`auto`
|`git.verify-freshness` (`stale_or_undecidable`); `git.freshness-build-running` (every non-success outcome).
|`auto build.enqueue-verification`, the server's choice: while the compiled attempt cap of the freshness loop is left it enqueues the verification build over the scope the stale verdict names (`stale_reason`, `admitted_causes`, required notations); otherwise it steps out. Never a push under a stale verdict.
|`started` -> `git.freshness-build-running`; `attempts_exhausted` -> `git.stepped-out` (cause `attempts_exhausted`).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 5]

|[[state-git.freshness-build-running]]`git.freshness-build-running`
|inherit
|`job`
|`git.freshness-blocked` (`started`).
|`build.verify-worktree`, the job the preceding primitive enqueued.
|`succeeded` -> `git.verify-freshness`; `failed`, `failed_unparsed`, `refused`, `cancelled`, `timed_out`, `killed`, `indeterminate` -> `git.freshness-blocked`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_declarative_dsl_definition_classpathworkflowsgit_commit_and_push_pmwf[Workflow DSL Specification, DSL Definition]

|[[state-git.check-branch-parity]]`git.check-branch-parity`
|inherit
|`auto`
|`git.verify-freshness` (`fresh_or_exempt`).
|`git.push-barrier-decision`: `first_push` when `branch_pushed_at` is unset; `rewritten_by_rebase` when the recorded last push (`branch_pushed_at`) is no ancestor of `HEAD` because a server rebase rewrote the plan's own branch; otherwise `git.branch-sync-state` (fetched) with `refire` only for `ahead` and for `never_pushed` (a `remote_absent_unverified` branch for which `ci.pr-find` found no pull request). Only `synced` (the remote branch holds `HEAD`) returns `pushed: true`; a merged pull request makes the branch `remote_absent_landed` (`pushed: false`, `landed: true`); `remote_absent_unverified` with a pull request, and every unrecognised sync state, cannot be established.
|`first_push`, `refire` -> `git.execute-push`; `rewritten_by_rebase` -> `git.push-with-lease`; `synced`, `landed` -> `git.done`; `push_state_unknown` -> `git.stepped-out` (cause `push_state_unknown`).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 6]

|[[state-git.execute-push]]`git.execute-push`
|inherit
|`auto`
|`git.check-branch-parity` (`first_push`, `refire`).
|`git.push`; sets `branch_pushed_at` on the first successful push and refreshes it on every later one.
|`pushed`, `up_to_date` -> `git.done`; `rejected_non_ff`, `rejected_lease` -> `git.sync-required` (the outcome set of `git.push`, routed alike in both push states).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 6]

|[[state-git.push-with-lease]]`git.push-with-lease`
|inherit
|`auto`
|`git.check-branch-parity` (`rewritten_by_rebase`).
|`auto git.push-with-lease`, the routine forced push to the plan's own branch after a server rebase, with an explicit lease: the `remote_sha` observed at the rejection, else the last recorded push (`branch_pushed_at`), re-read by `ls-remote` before the push; never the remote-tracking ref. Refreshes `branch_pushed_at`.
|`pushed`, `up_to_date` -> `git.done`; `rejected_non_ff`, `rejected_lease` -> `git.sync-required`.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL Specification, Stage 6]

|[[state-git.sync-required]]`git.sync-required`
|inherit
|`auto`
|`git.execute-push`, `git.push-with-lease` (`rejected_non_ff`, `rejected_lease`).
|`auto git.rebase-onto-upstream`, the server's choice: while the compiled attempt cap of the sync loop (counted over push rejections) is left it fetches and rebases the branch onto the observed remote head; otherwise it steps out. `facts`: `git.branch-divergence`.
|`rebased` -> `git.verify-freshness`; `conflict` (the rebase stays in progress) -> `git.resolve-conflicts`; `rebase_failed` (the fetch or the rebase could not start) -> `git.stepped-out` (cause `rebase_failed`); `attempts_exhausted` -> `git.stepped-out` (cause `attempts_exhausted`).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_declarative_dsl_definition_classpathworkflowsgit_commit_and_push_pmwf[Workflow DSL Specification, DSL Definition]

|[[state-git.resolve-conflicts]]`git.resolve-conflicts`
|inherit
|`job`
|`git.sync-required` (`conflict`); `git.continue-rebase` (`conflict`, attempt cap left).
|`job llm conflict role implement`: `facts`: `git.rebase-conflict` (the conflicted paths and hunks with the commits that touched them); the worker resolves the conflicted files in the checkout and submits `resolved` (`summary`). Skill `pm/git/sync-recovery`.
|`resolved` -> `git.continue-rebase`; `infeasible`, `lost` -> `git.stepped-out` (cause `infeasible` or `lost`; the server aborts the rebase, restoring the pre-rebase branch, first).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_declarative_dsl_definition_classpathworkflowsgit_commit_and_push_pmwf[Workflow DSL Specification, DSL Definition]

|[[state-git.continue-rebase]]`git.continue-rebase`
|inherit
|`auto`
|`git.resolve-conflicts` (`resolved`).
|`auto git.rebase-continue`: continues the rebase with the resolved files.
|`rebased` -> `git.verify-freshness`; `conflict` (attempt cap left) -> `git.resolve-conflicts`; `attempts_exhausted` (the compiled attempt cap of the conflict loop spent; the server aborts the rebase first) -> `git.stepped-out` (cause `attempts_exhausted`).
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_declarative_dsl_definition_classpathworkflowsgit_commit_and_push_pmwf[Workflow DSL Specification, DSL Definition]

|[[state-git.done]]`git.done`
|inherit
|`terminal`
|`git.inspect-worktree` (`clean_skip_push`); `git.evaluate-push-policy` (`skip_push`); `git.check-branch-parity` (`synced`, `landed`); `git.execute-push`, `git.push-with-lease` (`pushed`, `up_to_date`).
|Returns outcome `done` (class `success`) with the result `{commit?, pushed, clean, landed}` of the path taken.
|The caller's `done` transition.
|link:../workflow-dsl/06-reusable-sub-workflows.adoc#_call_stack_execution_persistence_semantics[Workflow DSL Specification, Sub-Workflow Return]

|[[state-git.stepped-out]]`git.stepped-out`
|inherit
|`terminal`
|`git.stage-and-commit`, `git.artifact-review`, `git.freshness-blocked`, `git.sync-required`, `git.continue-rebase` (`attempts_exhausted`); `git.artifact-escalate` (`exhausted`); `git.sync-required` (`rebase_failed`); `git.check-branch-parity` (`push_state_unknown`); the `infeasible` and `lost` routes of `git.artifact-review`, `git.commit-fix`, `git.resolve-conflicts`.
|Returns the control outcome `stepped_out {by: server, cause, reason}`; it only leaves the sub-workflow and never ends the calling scope. An interrupted rebase is aborted before the frame unwinds.
|The caller's `stepped_out` transition: `finalize.hand-back` from the plan callers, the remediation unit's `remediation-<class>.budget-check`, `setup.commit-changes`, `epic.active`. A server step-out of cause `condition` is not returned here: it unwinds every frame to the plan's fallback.
