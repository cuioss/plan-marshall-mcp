[#state-catalogue-finalize]
== Phase 6: `finalize`

The start state of `finalize.pmwf` is `finalize.settle-commit`. The finalize steps are the step list of the plan instance in force, executed in `order` (link:../phase-workflows/04-finalize-step-bands.adoc#_normative_step_catalogue_across_ordering_bands[Phase Workflows Specification, Normative Step Catalogue]); every default step has one declared state, a template state that the instance composition includes or prunes (with its prune reason, for example `local_only`, `land_lane`, `posture`, `returned`). A `mutates_source` step always routes through `finalize.settle-commit`, whose `done` continues and whose `stepped_out` enters `finalize.hand-back`. Every `link` state asks for one judgment through one link naming its skill section. A project step (orders `71..899`, `900..989`) runs in a state of the project's own unit (`project.run-step`), published with the project's effective configuration and not catalogued here; its failure fates enter `finalize.step-failed`. The branch-cleanup step (order `70`) runs as the merge path, and the post-push ADR step, the post-run band (`900..999`), the landing, and the archive follow in xref:07-plan-finalize-merge-post-run.adoc#state-catalogue-finalize-merge[Merge Path & Post-Run Band]. A plan of source `pr` (lane `adopt`) enters Phase 6 through `finalize.adopt-pr`; its `sync-baseline` step only checks (action `noop` or `check`) and never rebases.

This part lists the start, the settle band (orders `3..10`), push and pull request (`11`, `20`), and the concurrent wait region (`22..40`). Remediation calls follow the fixed class order CI -> analysis -> review findings; after `resolved` or `waived`, verdict currency re-fires the wait region for every class that is stale at the new `HEAD`.

[#state-catalogue-fallback]
== Plan Fallbacks & Terminal States

The two fallback states are declared in `finalize.pmwf`. The transaction entering either of them records every begun, unsettled step `failed`, records the gap (`gate`, policy, evidence summary, `cause`: `exhausted`, `stepped_out`, `hand_back`, `condition`, `question_expired`, `provider_refused`, `auto_merge_off`, `local_only` (not a failure), with the reason or the spent budget; link:../store-schemas/14-plan-instance-waivers-questions.adoc#gap-record[Store Schemas Specification, Gap Record]), and composes a post-run-only plan instance version (composition event `fallback`; every step below order `900` pruned with reason `returned` or `handed_back`), which is in force from the transition entering the fallback state for the rest of its chain.

|State id |Phase value |Kind |Entered from |Offered links / outcomes |Exits to |Defined in

|[[state-plan.return]]`plan.return`
|`phase-6-finalize`
|`auto`
|Phases 1–4: `hand_back` links (`init.sibling-collision`, `refine.hypothesis-refuted`, `plan.revise-tasks`); `init.classify` (`returned`); `exhausted` / `stepped_out` of every `<phase>.remediate-qgate`; `outline.route-review` (`budget_spent`, `expired`); a spent condition budget in Phases 1–4.
|`auto plan.return`: the fallback of Phases 1–4. Without committed work it records `outcome: returned`; no pull request exists, and the planning artifacts are archived. A plan that came back from Phase 5 through `loop_back_outline` and whose plan branch has commits beyond the base is forwarded to `finalize.hand-back`, which delivers that work.

|`phase-6-finalize`
|`auto`
|Phase 5, the land lane, and Phase 6 before the merge: `hand_back` links; `plan.return` (`committed_work`); `exhausted` / `stepped_out` of the remediation calls and `stepped_out` of the `git.commit_and_push` calls; `finalize.restart-watch` (`exhausted`), `finalize.step-failed` (`before_merge`); `finalize.create-pr`, `finalize.adopt-blocked`, `finalize.merge-lease-interrupted` (`retry_spent`); `finalize.merge-gate` (`local_only`); `finalize.merge-sync` (`retry_spent`); `finalize.merge-barrier` (`pass_hand_back`, `retry_spent`); `finalize.merge-refused` (`provider_refused`, `retry_spent`); `finalize.merge-queue-exit` (`closed`, `budget_spent`); a spent condition budget.
|`auto finalize.hand-back`: settles uncommitted work (commit only, footprint-checked) and removes the worktree. Without a pull request it pushes the plan branch (when a push remote exists) and opens a *draft* pull request with the gap comment and the label `pm-mcp:handed-back`; with a pull request it posts the idempotent gap comment (hidden `plan_id` marker) and label and leaves it open. Local form (no push remote, `merge.gate-entry` outcome `local_only`, gap `cause: local_only`): captures the realized footprint, keeps the plan branch (the product), records `merge_outcome: local_only`, carries open findings out as late findings, and `completes default:branch-cleanup as done`. Ready form (the barrier passed under the operator's `merge.auto_merge: false`, gap `cause: auto_merge_off`): marks the existing pull request ready for review (never a draft), posts the idempotent hand-back comment and the label, leaves the pull request open for a human merge, and records `merge_outcome: awaiting_human_merge`. The comment names every expired waiver request. A `land` plan keeps its capture ref and owes `capture_ref_retained`. Where the fallback lacks what is missing (no push credential) it degrades to the local form.
|`handed_back` -> `finalize.next-step`; `returned` (the plan branch has no commit beyond the base) -> `finalize.next-step`.
