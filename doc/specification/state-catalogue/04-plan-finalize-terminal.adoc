[#state-catalogue-finalize]
== Phase 6: `finalize`

The start state of `finalize.pmwf` is `finalize.settle-commit`. The finalize steps of the manifest are executed in `order` (link:../phase-workflows/04-finalize-step-bands.adoc#_normative_step_catalogue_across_ordering_bands[Phase Workflows Specification, Normative Step Catalogue]); only the steps that have their own state are listed here. The branch-cleanup step (order `70`) runs as the merge path `finalize.merge-gate` -> `finalize.merge-lease` -> `finalize.merge-sync` -> `finalize.merge-evidence-wait` / `finalize.merge-barrier` -> `finalize.merge-gap` / `finalize.merge-dispatch` -> `finalize.merge-queue-wait`; its link states (`finalize.merge-lease-interrupted`, `finalize.merge-conflict`, `finalize.merge-sync-escalate`, `finalize.merge-remote-moved`, `finalize.merge-gap`, `finalize.merge-refused`, `finalize.merge-queue-exit`) hold no merge lease, and an unmerged plan leaves the path only through `abort-plan` or the approved `wind-down-unmerged` (`finalize.wind-down`). The `archive-plan` step (order `1100`) runs in `finalize.archive-plan`. A plan of source `pr` (lane `adopt`) enters Phase 6 through `finalize.adopt-pr`; its `sync-baseline` step (order `3`) only checks (it records the upstream commit count with action `noop` or `check` and never rebases), so the branch is rebased only in `finalize.merge-sync`. The state of every other manifest step (`sync-baseline`, `simplify`, `security-audit`, `pre-submission-self-review`, `architecture-refresh`, `pre-push-quality-gate`, `adr-propose`, the post-merge and post-run steps, `emit-landing`) is _(to be specified)_; a `mutates_source` step always routes through `finalize.settle-commit`. For a `land` plan every `loop_back` is replaced by `escalate`, `abort` (the request `abort-plan`), and `recapture`; the same holds for the model links of `finalize.merge-conflict` and `finalize.merge-remote-moved`. An `aborted` outcome of `git.commit_and_push` in a finalize `call` state enters `finalize.commit-aborted` (xref:01-conventions-generic-conditions.adoc#state-phase.commit-aborted[Commit aborted]).

|[[state-finalize.merge-sync]]`finalize.merge-sync`
|`phase-6-finalize`
|`auto`
|`finalize.merge-lease` (`succeeded`), holding the lease.
|`merge.sync-base`: fetches the base and rebases the plan branch onto `origin/<base_branch>`, then pushes it with an explicit lease (the last recorded push), only when the derived fact `branch_up_to_date_required` holds (an `indeterminate` fact counts as holding) or the base changed a path of the plan's realized footprint since the merge base; a base that is already an ancestor of `HEAD` is never rebased. Independently of a rebase, it pushes with the explicit lease whenever the local `HEAD` differs from the last recorded push (also when the base is already an ancestor), and such a push leads through the evidence wait. Records `action` and `upstream_commit_count`; a rebase re-stamps `main_sha`. On `conflict` and `rejected_lease` the lease is released first; on `rejected_lease` the branch is reset to its pre-rebase `HEAD`.
|`not_required` -> `finalize.merge-barrier`; `rebased`, `pushed` (the precondition push without a rebase) -> `finalize.merge-evidence-wait`; `conflict` -> `finalize.merge-conflict`; `rejected_lease` -> `finalize.merge-remote-moved`.
|link:../phase-workflows/06-finalize-re-entry-and-merge.adoc#merge-path[Phase Workflows Specification, Merge Path item 3]

|[[state-finalize.merge-queue-wait]]`finalize.merge-queue-wait`
|`phase-6-finalize`
|`job`
|`finalize.merge-dispatch` (`enqueued`: queue membership observed, lease released; `enqueued_indeterminate`: membership not yet observed, lease released); `finalize.merge-queue-exit` (`resume_wait`).
|Waits for a terminal queue outcome: `merged`, `ejected`, `closed`, `timed_out`; `merged` only from `ci.pr-observe` or `ci.queue-membership`. The bound is stall-based: every observed progress (a change of queue position or entry state) restarts the clock, and `timed_out` is reached only after no progress for twice the queue's check-response timeout (from `merge_queue_enforced`), else the compiled fallback `3600` s; `timed_out` is a no-verdict outcome. After `enqueued_indeterminate` the observation settles the wait: observed membership counts as progress, `merged` as `merged`, an open pull request that is not queued as `ejected`, and an unobservable queue lets the stall bound run out to `timed_out`.
