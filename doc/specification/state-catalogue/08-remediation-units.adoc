== Remediation Units
_See Requirement link:../../Requirements.adoc#PM-WF-16[PM-WF-16: Reusable Compound Sub-Workflows & Config-Driven Git Commit/Push]_

The self-remedy of a failure class is a sub-workflow unit per class (`scope subworkflow`), called by the phase units (link:../phase-workflows/01-planning-phases-1-2.adoc#_remediation_policy_calls[Phase Workflows Specification, Remediation Policy Calls]). The units are project-owned templates within compiled invariants; this catalogue documents the default units. Every state declares `phase inherit`.

*Contract*: Parameters `retry_budget`, `fix_budget`, `waiver_wait_seconds`, and `actions` (the subset of `retry`, `fix`, `loop_back` the call admits; the plan instance's composition rules may narrow it, for example `actions=[retry]` for a `land` plan), bounded by the compiled hard caps (link:../timeouts/01-job-budgets-and-waits.adoc#retry-budget[retry], link:../timeouts/01-job-budgets-and-waits.adoc#fix-budget[fix], link:../timeouts/01-job-budgets-and-waits.adoc#waiver-wait[waiver wait]); the plan instance carries the effective ceilings with their source. Budgets are counted per plan and class, persisted, and never reset (link:../store-schemas/14-plan-instance-waivers-questions.adoc#policy-counter[Store Schemas Specification, Remediation Budget Accounting]). The exit contract is the subset of the domain outcomes `resolved`, `waived`, `exhausted`, `fix_requested` the unit can reach, plus the control outcome `stepped_out`: `waived` only where the class has a waivable gate, `fix_requested` only where the fix runs in the caller. The gather state records the evidence as failure envelopes behind untrusted resources (link:../store-schemas/14-plan-instance-waivers-questions.adoc#evidence-directory[Store Schemas Specification, Evidence Directory]); a unit that ingests externally authored text (review comments and bot findings, analysis-provider messages) builds one `batch-v1` batch of the firing's new items after level-1 validation and screens its uncached items in one screener job per batch part (one part, unless the batch exceeds the screening split bound), and an item the screener flags `suspicious` is withheld: only its structured fields are delivered, it stays pending, and the unit ends through its budget and fallback unless a `met` waiver covers it (the hand-back report lists withheld items); `decide` asks for one judgment, the remedy, and offers the implicit `step_out`, never guarded by a budget. A nested `git.commit_and_push` that returns `stepped_out` routes back to `decide`, and the uncommitted fix is not charged; a server step-out of cause `condition` never reaches `decide`, because it unwinds every frame to the plan's fallback. No primitive writes a waiver: the waived path exists only as the `waived` terminal, produced by the gather state (`waiver.lookup`) or the waiver wait.

*`decide` validation* (common to every unit): `retry` (`submit`, `reason: enum[flaky|infra|timeout]`) is refused with `retry_not_applicable` when the same failure fingerprints already failed after a retry with the same reason; `fix` is charged only when its commit or revised artifact exists, and an empty commit or unchanged artifact is refused with `fix_unchanged`; `loop_back` (`submit`, `summary`) returns `fix_requested` and is charged like `fix`; `request_waiver` (`submit`, `rationale: text[1..2000]`, files a waiver request, not a decision) is offered only while `waiver_wait_seconds > 0` and the failing gate is waivable. Each link is offered only when the call's `actions` admit it and its budget is left.

=== Generic Remediation States

A generic state `remediation-<class>.x` stands for one concrete state per unit in which it occurs (for example `remediation-ci.budget-check`).

[cols="2,1,1,2,3,2,2"]
|===
|State id |Phase value |Kind |Entered from |Offered links / outcomes |Exits to |Defined in

|[[state-remediation.budget-check]]`remediation-<class>.budget-check`
|inherit
|`auto`
|The unit's gather state (`failures`, `over`, `cancelled`), screen state (`remediation-analysis`), triage state (`triaged_with_fix`), or waiver wait (`raised`).
|`auto remediation.check-budgets` against the effective ceilings; precedes `decide`, so `decide` is never entered without a remedy link.
|`budget_left` -> the unit's `decide` (not in `remediation-spend`, which has none); `exhausted_wait` (only in a unit with a waiver wait: `waiver_wait_seconds > 0` and the gate waivable; the server files the waiver request) -> `remediation-<class>.waiver-wait`; `exhausted` -> `remediation-<class>.exhausted`.
|link:../phase-workflows/01-planning-phases-1-2.adoc#_remediation_policy_calls[Phase Workflows Specification, Remediation Policy Calls]

|[[state-remediation.waiver-wait]]`remediation-<class>.waiver-wait`
|inherit
|`composite_job`
|The unit's `decide` (`request_waiver`); `remediation-<class>.budget-check` (`exhausted_wait`).
|`remediation.await-waiver`: a server timer bounded by `waiver_wait_seconds` plus a watch of the plan's waiver store (awaited events `OPERATOR_WAIVER`, `TIME`); no model turn; survives a gone host session; held by an integrity pause. The request is announced per the waiver-request channels and listed by `pm-mcp operator waivers --pending`.
|`raised` (an operator `--raise` of this class's `retry_budget` or `fix_budget`; never in `remediation-spend`, whose ceiling is not raisable) -> `remediation-<class>.budget-check`; `waived` (a `met` waiver of the failing gate) -> `remediation-<class>.waived`; `expired` -> `remediation-<class>.exhausted` (the request named in the hand-back comment); `interrupted` -> `remediation-<class>.budget-check`; `cancelled` (a followed `cancel:` link) -> `remediation-<class>.exhausted`.
|link:../store-schemas/14-plan-instance-waivers-questions.adoc#waiver-request-record[Store Schemas Specification, Waiver Request Record]

|[[state-remediation.screen]]`remediation-<class>.screen`
|inherit
|`job`
|The unit's gather state, when the firing's `batch-v1` batch holds items with no cached verdict (`remediation-analysis.gather` `failures`, `remediation-review.gather` `untriaged`).
|`job llm screen role screen.effort each screen.batch-parts`: a fan-out over the parts of the batch's uncached items (link:../workflow-dsl/02-units-jobs-decisions.adoc#model-job-states[Workflow DSL Specification, Model Job States] item 6; one part, unless the batch exceeds the screening split bound), one zero-tool screener job per part through the model slots, each in the empty `cwd/` subdirectory of its job-private directory, without project files; the state completes when every part has its verdict; verdicts cached per scope by the SHA-256 of the cleaned text; an unparseable or missing verdict counts as `suspicious`. A launch the harness cannot serve raises `precondition_unmet` (`harness_capability_missing`).
|`clean`, `suspicious` (the flagged items withheld: only their structured fields and `withheld: flagged by screener` are delivered) -> the unit's judgment: `remediation-analysis.budget-check`, `remediation-review.triage`.
|link:../dispatch-and-effort/06-untrusted-text-screening.adoc#screener[Model Jobs & Effort Specification, Screener Job]; link:../dispatch-and-effort/06-untrusted-text-screening.adoc#batch-v1[Batch Format]

|[[state-remediation.resolved]]`remediation-<class>.resolved`
|inherit
|`terminal`
|The unit's gather, await, rerun, or `decide` state (class passed).
|Declared `terminal resolved success`.
|The caller's `resolved` transition.
|link:../hypermedia-format/03-composite-wait-and-encoder.adoc#policy-unit-returns[Hypermedia Format Specification, Policy Unit Returns]

|[[state-remediation.waived]]`remediation-<class>.waived`
|inherit
|`terminal`
|The unit's gather state (`all_waived`: every failure covered by a `met` waiver, consumption logged) or waiver wait (`waived`).
|Declared `terminal waived success`; the caller completes its begun step `waived` with the waiver id (`remediation-spend`: the caller's `merge.gate-entry` reads and consumes the `spend` waiver).
|The caller's `waived` transition.
|link:../store-schemas/14-plan-instance-waivers-questions.adoc#waiver-record[Store Schemas Specification, Waiver Record]

|[[state-remediation.exhausted]]`remediation-<class>.exhausted`
|inherit
|`terminal`
|`remediation-<class>.budget-check` (`exhausted`), `remediation-<class>.waiver-wait` (`expired`, `cancelled`).
|Declared `terminal exhausted failure`; the gap record names the spent budget (`cause: exhausted`). An interrupted rebase is aborted first.
|The caller's `exhausted` transition, always a fallback state.
|link:../store-schemas/14-plan-instance-waivers-questions.adoc#gap-record[Store Schemas Specification, Gap Record]

|[[state-remediation.fix-requested]]`remediation-<class>.fix-requested`
|inherit
|`terminal`
|The unit's `decide` (`loop_back`; for `remediation-build` and `remediation-qgate` also `fix`).
|Declared `terminal fix_requested unsettled`; the fix runs in the caller (a new authoring job, a task revision, or Phase 5 remediation tasks), which calls the unit again after the next verification on the same counter.
|The caller's `fix_requested` transition.
|link:../phase-workflows/01-planning-phases-1-2.adoc#_remediation_policy_calls[Phase Workflows Specification, Remediation Policy Calls]

[#state-catalogue-remediation-spend]
=== `remediation.spend`

A degenerate unit: no `retry`, no `fix`, and no resting link state (so it never returns `stepped_out`). The spend ceiling is not raisable: only a `met` waiver of the gate `spend` lets the plan pass, and `merge.gate-entry` is the single point that reads it; the unit's waiver wait, when bound, only waits for that waiver.
