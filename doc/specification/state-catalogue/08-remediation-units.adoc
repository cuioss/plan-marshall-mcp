== Remediation Units
_See Requirement link:../../Requirements.adoc#PM-WF-16[PM-WF-16: Reusable Compound Sub-Workflows & Config-Driven Git Commit/Push]_

The self-remedy of a failure class is a sub-workflow unit per class (`scope subworkflow`), called by the phase units (link:../phase-workflows/01-planning-phases-1-2.adoc#_remediation_policy_calls[Phase Workflows Specification, Remediation Policy Calls]). The units are project-owned templates within compiled invariants; this catalogue documents the default units. Every state declares `phase inherit`. No state of a unit is a `link` state: the server gathers the evidence and takes a single admissible remedy itself; where several are admissible a task of the unit's triage role chooses one (`choose`); a task of the writer role `implement` does an in-branch fix; the server runs everything else (link:../workflow-dsl/08-remediation-units.adoc#unit-template[Workflow DSL Specification, Unit Template]).

*Contract*: Parameters `retry_budget`, `fix_budget`, `waiver_wait_seconds`, and `actions` (the subset of `retry`, `fix`, `loop_back` the call admits; the plan instance's composition rules may narrow it, for example `actions=[retry]` for a `land` plan), bounded by the compiled hard caps (link:../timeouts/01-job-budgets-and-waits.adoc#retry-budget[retry], link:../timeouts/01-job-budgets-and-waits.adoc#fix-budget[fix], link:../timeouts/01-job-budgets-and-waits.adoc#waiver-wait[waiver wait]); the plan instance carries the effective ceilings with their source. Budgets are counted per plan and class, persisted, and never reset (link:../store-schemas/14-plan-instance-waivers-questions.adoc#policy-counter[Store Schemas Specification, Remediation Budget Accounting]). The terminals are the reachable subset of `resolved`, `waived`, `exhausted`, `fix_requested`: `waived` only where the class has a waivable gate, `fix_requested` only where the fix runs in the caller. A unit has no step-out terminal; its call sites still route `stepped_out`, which keeps the exit contract of every sub-workflow uniform. The gather state records the evidence as failure envelopes behind untrusted resources (link:../store-schemas/14-plan-instance-waivers-questions.adoc#evidence-directory[Store Schemas Specification, Evidence Directory]); a unit that ingests externally authored text (review comments and bot findings, analysis-provider messages) builds one `batch-v1` batch of the firing's new items after level-1 validation and screens its uncached items in one screener task per batch part, and an item the screener flags `suspicious`, or whose verdict is missing, is withheld: only its structured fields are delivered, it stays pending, and the unit ends through its budget and fallback unless a `met` waiver covers it (the hand-back report lists withheld items). A nested `git.commit_and_push` that returns `stepped_out`, or `done` without a commit, returns to `budget-check`; a server step-out of cause `condition` never reaches the unit, because it unwinds every frame to the plan's fallback. No primitive writes a waiver: the waived path exists only as the `waived` terminal, produced by the gather state (`waiver.lookup`) or the waiver wait.

[#remediation-decide]
*Deciding the remedy*: `decide` (`auto remediation.offer-actions`) computes the admissible remedies: each action the call binds whose budget is left (`loop_back` only `in_worktree`), and `request_waiver` while `waiver_wait_seconds > 0`, the failing gate is waivable, and no request is pending. One admissible remedy is taken without a task (`retry` -> `rerun`, an in-branch `fix` -> `apply-fix`, a `fix` that runs in the caller and `loop_back` -> `fix-requested`), each charged by the primitive that takes it; several -> `choose`. The admissible set follows only from the call's bindings and the budgets left, so no unit hard-wires whether a task decides (link:../workflow-dsl/08-remediation-units.adoc#remediation-invariants[Workflow DSL Specification, `INV-REM-7`]); with the shipped bindings the server takes `fix` in `remediation-merge` and `remediation-qgate`. `choose` (`job llm remediation-decision role <triage role>`, the facts carrying the evidence the decision rests on) offers one closing submit per admissible remedy, each defined once in `facts.options`: `retry` (`reason: enum[flaky|infra|timeout]`, refused with `retry_not_applicable` when the same fingerprints already failed after a retry with the same reason), `fix` (`summary: text[1..500]`), `loop_back` (`remediation_summary: text[1..2000]`), `request_waiver` (rel `escalate`, `rationale: text[1..2000]`); `fix` and `loop_back` are refused with `fix_unchanged` when the worktree or the artifact is unchanged since the previous attempt. A decision or fix task of the unit that closes `lost` (its re-offers spent, or its role undefined, unqualified, or unavailable) or ends `infeasible` enters `conservative`, which takes the bound `retry` once per unit instance and otherwise `exhausted` (`PM-WORK-6`); in `remediation-qgate`, which has no `retry`, it ends `exhausted`.
