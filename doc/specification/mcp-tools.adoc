== Overview

This document defines the normative Model Context Protocol (MCP) tool schemas, resource URI templates, skill delivery surface, and error/result envelope contracts for *plan-marshall-mcp* (`PM-MCP`). It specifies the JSON Schema (Draft 2020-12) definitions for the core workflow verbs (`pm_start`, `pm_state`, `pm_do`), orthogonal service tools (`pm_build`, `pm_lsp`), and tool-based skill retrieval (`pm_skill`, `pm_skills`, `pm_skill_file`), alongside the strict separation between MCP protocol faults (`isError: true`) and domain workflow failure states (`isError: false`).

=== Architectural Constraints

1. *Small, Stable Verb Set*: PM-MCP exposes a fixed set of top-level MCP tools (`pm_start`, `pm_state`, `pm_do`, `pm_plans`, `pm_epics`, `pm_build`, `pm_lsp`, `pm_skills`, `pm_skill`, `pm_skill_file`) rather than one tool per workflow step or script. Across all phases and domains, the resident tool surface remains constant, and privileged operator actions are strictly excluded from the MCP tool surface (`PM-SEC-3`).
2. *Portable Naming Convention*: Every tool name conforms to `^pm_[a-z0-9_]+$`, ensuring identical identifiers across Claude Code, OpenCode, Antigravity, Codex, and raw model tool-calling APIs without escaping or translation.
3. *Closed Top-Level Schemas*: Every tool `inputSchema` conforms to JSON Schema Draft 2020-12 (`https://json-schema.org/draft/2020-12/schema`) and declares `"additionalProperties": false` at the top-level object boundary.
4. *TOON Text Output Only (No `outputSchema`)*: Tools intentionally omit `outputSchema` and `structuredContent`. Every tool result is returned in a single MCP `TextContent` block (`type: "text"`) encoded in deterministic TOON (link:hypermedia-format.adoc[Hypermedia Format Specification]). This avoids resident output-schema token overhead while optimizing token density on every turn.
5. *Zero Client-Supplied Filesystem Paths*: No workflow or service tool accepts absolute filesystem paths or worktree locations from the model. Worktrees, branches, and configuration files are resolved server-side from `plan_id` or `epic_id`.
6. *On-Demand Preloading*: For hosts configured with `schema_residency: "on_demand"` in their client profile, the user entry command preloads `pm_start`, `pm_state`, and `pm_do` so workflow execution incurs zero schema-lookup round trips.

=== `pm_start` — Initialize a Plan Scope

Creates a new plan directory from one of the four supported initialization sources (`request`, `issue_number`, `lesson_id`, or `recipe_id`) following a plan-mode `pm-mcp enter` invocation, relocates the project-level `mcp/entry.json` record into `.plan/local/plans/<plan_id>/mcp/entry.json`, initializes `mcp/status.json`, and returns the initial TOON hypermedia representation.

[source,json]
----
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "pm_start",
  "description": "Create a new plan from a request, issue, lesson, or recipe and return its initial hypermedia representation.",
  "type": "object",
  "properties": {
    "request": {
      "type": "string",
      "minLength": 1,
      "maxLength": 65536,
      "description": "Free-form user request or problem statement for the new plan."
    },
    "issue_number": {
      "type": "integer",
      "minimum": 1,
      "description": "GitHub/GitLab issue number to fetch via the enrolled CI CLI as the plan source."
    },
    "lesson_id": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_.-]{1,63}$",
      "description": "Lesson-learned identifier to convert into a remediation plan (runs premise check and relocates the lesson file into the plan)."
    },
    "recipe_id": {
      "type": "string",
      "pattern": "^[a-z][a-z0-9_-]{1,63}$",
      "description": "Registered recipe identifier (e.g., 'simplify-codebase', 'security-audit'); appends a deterministic UTC timestamp suffix to plan_id."
    },
    "recipe_params": {
      "type": "object",
      "default": {},
      "description": "Optional recipe scope/thoroughness parameters validated against the recipe's input schema."
    },
    "slug": {
      "type": "string",
      "pattern": "^[a-z0-9]+(-[a-z0-9]+){0,7}$",
      "maxLength": 64,
      "description": "Optional short kebab-case slug used to derive the plan_id (rejected if shaped like a UUID or lesson_id)."
    },
    "epic_id": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$",
      "description": "Optional parent orchestrator epic_id when launching a staged plan."
    },
    "base_branch": {
      "type": "string",
      "pattern": "^[A-Za-z0-9_./-]+$",
      "maxLength": 128,
      "description": "Optional target base branch override (defaults to repository default branch)."
    }
  },
  "oneOf": [
    { "required": ["request"] },
    { "required": ["issue_number"] },
    { "required": ["lesson_id"] },
    { "required": ["recipe_id"] }
  ],
  "additionalProperties": false
}
----

=== `pm_state` — Query Authoritative Hypermedia State

Returns the current hypermedia representation (`state`, `summary`, `guidance` skill URI, domain `facts`, and valid `links`) for a `plan_id`, `epic_id`, or `steward` scope. When `entity` (and optional `scope: "entity"`) is supplied by a dispatched sub-agent, returns the leaf-scoped representation for that entity (e.g., task envelope `envelope-2` or finding `F-12`) and claims `dispatch_id` if provided.

[source,json]
----
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "pm_state",
  "description": "Return the current TOON hypermedia representation and valid links for a plan, epic, steward, or sub-agent entity.",
  "type": "object",
  "properties": {
    "scope": {
      "type": "string",
      "enum": ["plan", "epic", "entity", "steward"],
      "description": "Optional explicit scope discriminator (inferred from plan_id/epic_id/entity when omitted)."
    },
    "plan_id": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$",
      "description": "Identifier of the target plan scope. Mutually exclusive with epic_id."
    },
    "epic_id": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$",
      "description": "Identifier of the target orchestrator epic scope. Mutually exclusive with plan_id."
    },
    "entity": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_.:-]{0,63}$",
      "description": "Optional entity identifier within the plan or epic (e.g., 'envelope-1', 'F-12') for sub-agent scope."
    },
    "dispatch_id": {
      "type": "string",
      "pattern": "^(dsp-[A-Za-z0-9_.-]+-[0-9]{4}-[0-9a-f]{6}|d-[0-9a-f]{4,16})$",
      "description": "Optional dispatch tracking identifier supplied by a dispatched sub-agent on its initial call."
    }
  },
  "oneOf": [
    { "required": ["plan_id"] },
    { "required": ["epic_id"] },
    { "properties": { "scope": { "const": "steward" } }, "required": ["scope"] }
  ],
  "additionalProperties": false
}
----

NOTE: Companion zero-argument discovery tools `pm_plans` and `pm_epics` accept `{"type": "object", "properties": {}, "additionalProperties": false}` and return a tabular TOON listing of active plans or epics in the enrolled workspace.

=== `pm_do` — Follow a Hypermedia Link

The sole state transition verb in PM-MCP. Executes the transition identified by `link` from the current representation of `plan_id`, `epic_id`, or `steward`, passing any judgment parameters in `args`.

[source,json]
----
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "pm_do",
  "description": "Follow a hypermedia link from the current representation with its required free parameters.",
  "type": "object",
  "properties": {
    "scope": {
      "type": "string",
      "enum": ["plan", "epic", "entity", "steward"],
      "description": "Optional explicit scope discriminator."
    },
    "plan_id": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$",
      "description": "Identifier of the target plan scope. Mutually exclusive with epic_id."
    },
    "epic_id": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$",
      "description": "Identifier of the target orchestrator epic scope. Mutually exclusive with plan_id."
    },
    "entity": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_.:-]{0,63}$",
      "description": "Optional entity identifier when invoked by a dispatched leaf sub-agent."
    },
    "link": {
      "type": "string",
      "pattern": "^[a-z][a-z0-9_-]*(:[A-Za-z0-9_.-]+)?$",
      "maxLength": 128,
      "description": "Link identifier from the current representation (e.g., 'push', 'triage:F-12', 'wait:b-2291', 'returned:dsp-PLAN-042-0001-a9f3c2')."
    },
    "args": {
      "type": "object",
      "default": {},
      "description": "Free parameters required by the target link, validated server-side against the link's closed parameter schema."
    },
    "dispatch_id": {
      "type": "string",
      "pattern": "^(dsp-[A-Za-z0-9_.-]+-[0-9]{4}-[0-9a-f]{6}|d-[0-9a-f]{4,16})$",
      "description": "Optional dispatch identifier when invoked by a dispatched leaf sub-agent."
    }
  },
  "required": ["link"],
  "oneOf": [
    { "required": ["plan_id", "link"] },
    { "required": ["epic_id", "link"] },
    { "properties": { "scope": { "const": "steward" } }, "required": ["scope", "link"] }
  ],
  "additionalProperties": false
}
----

==== Two-Stage Schema Validation for `pm_do`

1. *Stage 1 (MCP Protocol Boundary)*: Validates that the incoming payload conforms to the `pm_do` JSON Schema above (`additionalProperties: false`, valid `plan_id`/`epic_id`, syntactic `link` pattern, `args` is a JSON object).
2. *Stage 2 (Workflow Engine Link Schema)*: Under the scope's exclusive lock, the engine resolves the active `LinkSpec` for `link` in the current state and validates `args` against the link's dynamically derived closed JSON Schema (`additionalProperties: false`, exact required free parameter keys, closed enum values, string length bounds, and integer ranges). If `args` fails Stage 2 validation or `link` is not offered in the current state, the engine returns `isError: false` with a structured `rejected` block and the fresh representation (see <<protocol-errors-vs-domain-workflow-failure-states>>).

=== `pm_build` — Enrolled Build Execution

Submits or awaits a build job in the plan's worktree (or the primary repository checkout when `plan_id` is omitted) using one of the project's canonical build verbs (`compile`, `test`, `module-tests`, `quality-gate`, `verify`, `coverage`, `format-check`). The model never supplies shell commands or flags.

[source,json]
----
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "pm_build",
  "description": "Execute a canonical project build verb in the plan's worktree (or primary checkout when plan_id is omitted) via the integrated build runner.",
  "type": "object",
  "properties": {
    "plan_id": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$",
      "description": "Optional plan scope whose worktree the build runs in. When omitted, runs in the primary repository checkout (orchestrator/workspace scope)."
    },
    "command": {
      "type": "string",
      "enum": ["compile", "test", "module-tests", "quality-gate", "verify", "coverage", "format-check"],
      "description": "Closed build verb resolved against the project's domain configuration and enrolled wrapper."
    },
    "module": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_./:-]{0,127}$",
      "description": "Optional logical module identifier discovered in the project (never an arbitrary filesystem path)."
    },
    "test_filter": {
      "type": "string",
      "pattern": "^[A-Za-z0-9_.$#*-]{1,256}$",
      "description": "Optional test class or method filter when command is 'test' or 'module-tests'."
    },
    "job_id": {
      "type": "string",
      "pattern": "^b-[0-9a-f]{4,16}$",
      "description": "Optional running build job_id when polling or waiting on a previously started ad-hoc build."
    }
  },
  "required": ["command"],
  "additionalProperties": false
}
----

==== `pm_build` TOON Output Contract

`pm_build` never returns raw console output. It returns a structured TOON result containing:

* `job_id`: unique build job identifier (e.g., `b-2291`)
* `status`: closed enum (`passed`, `failed`, `failed_unparsed`, `running`, `cancelled`, `timed_out`)
* `worktree_sha`: 64-character SHA-256 freshness digest of `HEAD` + staged + unstaged + untracked files, simultaneously appended to `change-ledger.jsonl` (`kind: "build"`)
* `summary`: counts of total/passed/failed/skipped tests and compiler/linter errors
* `failures`: tabular TOON array of located compiler errors or test failures (`file`, `line`, `column`, `rule_or_test`, `message`)
* `log_uri`: `pm://plan/{plan_id}/builds/{job_id}/log` (or `pm://workspace/builds/{job_id}/log` when `plan_id` is omitted; accompanied by the last 50 lines / 4 KB tail when `status == "failed_unparsed"`, `PM-IMPL-6`)

=== `pm_lsp` — Warm Language Server Operations

Queries or applies verified workspace edits against the session's warm LSP pool keyed by `(worktree, language)`.

[source,json]
----
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "pm_lsp",
  "description": "Execute a language-server operation against the warm LSP pool for a plan's worktree.",
  "type": "object",
  "properties": {
    "plan_id": {
      "type": "string",
      "pattern": "^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$",
      "description": "Plan scope identifying the target worktree."
    },
    "op": {
      "type": "string",
      "enum": [
        "workspace_symbol",
        "document_symbol",
        "definition",
        "references",
        "hover",
        "diagnostics",
        "rename"
      ],
      "description": "Closed LSP operation to execute."
    },
    "file": {
      "type": "string",
      "minLength": 1,
      "maxLength": 512,
      "pattern": "^(?!/)(?!.*\\.\\.)[A-Za-z0-9_./-]+$",
      "description": "Worktree-relative file path (required for document_symbol, definition, references, hover, diagnostics, rename)."
    },
    "line": {
      "type": "integer",
      "minimum": 1,
      "description": "1-based line number (required for definition, references, hover, rename)."
    },
    "character": {
      "type": "integer",
      "minimum": 1,
      "description": "1-based column offset (required for definition, references, hover, rename)."
    },
    "query": {
      "type": "string",
      "minLength": 1,
      "maxLength": 256,
      "description": "Symbol search query (required for workspace_symbol)."
    },
    "new_name": {
      "type": "string",
      "pattern": "^[A-Za-z_$][A-Za-z0-9_$]*$",
      "maxLength": 128,
      "description": "Replacement identifier for 'rename' operation."
    }
  },
  "required": ["plan_id", "op"],
  "allOf": [
    {
      "if": { "properties": { "op": { "const": "workspace_symbol" } } },
      "then": { "required": ["query"] }
    },
    {
      "if": { "properties": { "op": { "enum": ["document_symbol", "diagnostics"] } } },
      "then": { "required": ["file"] }
    },
    {
      "if": { "properties": { "op": { "enum": ["definition", "references", "hover"] } } },
      "then": { "required": ["file", "line", "character"] }
    },
    {
      "if": { "properties": { "op": { "const": "rename" } } },
      "then": { "required": ["file", "line", "character", "new_name"] }
    }
  ],
  "additionalProperties": false
}
----

==== Warm LSP Pool Lifecycle (`PM-SVC-2`)

* *Pool Keying & Lazy Spawn over `stdio`*: Each `pm-mcp serve` instance maintains a warm in-memory pool of LSP server child processes keyed by `(canonical_worktree_path, language_id)` using language servers enrolled in `~/.plan-marshall/mcp/enrolments.json` and managed via `org.eclipse.lsp4j:org.eclipse.lsp4j` over `stdio`. Processes start lazily on the first `pm_lsp` or Axis C symbol-edge query and shut down automatically after `idle_timeout_seconds` (default 900s), when the plan worktree is removed, or when the `pm-mcp serve` session exits.
* *Server-Applied `WorkspaceEdit` (`rename`)*: When `op == "rename"`, `pm-mcp` validates that every target URI in the LSP `WorkspaceEdit` resolves inside the plan's worktree (`PM-SEC-2`), applies the text edits atomically on disk, notifies the warm LSP server (`textDocument/didChange`), and appends all modified file paths to the plan's `references.json` realized footprint.

=== Selective Upstream MCP Proxy & `_meta` Provenance (`PM-SVC-3`)
_See Requirement link:../Requirements.adoc#PM-SVC-3[PM-SVC-3: Selective Upstream MCP Proxy & Provenance Tagging]_

When a project configures upstream MCP integrations (such as external issue trackers or documentation indexes), `pm-mcp` acts as a selective filter and provenance boundary:

1. *Allowlisted Tool Re-Exposure & Schema Narrowing*: Only upstream tools explicitly listed in the project configuration are re-exposed on the `pm-mcp` tool surface, with unused optional parameters stripped from their `inputSchema` to conserve resident context budget. Upstream skills are never re-exposed as PM-MCP vocabulary skills.
2. *Provenance Tagging (`_meta.source`)*: Every tool result or resource proxied from an upstream MCP server is wrapped with `_meta: {"source": "upstream_mcp:<server_id>", "trusted": false}` and routed through the untrusted-ingestion validator (`PM-SEC-1`) before any candidate data can enter plan stores.
3. *Credential Isolation*: Upstream MCP connections authenticate using server-specific credentials resolved from `CredentialStore` (`<project>/mcp-<server_id>`) over `de.cuioss:cui-http` (or isolated `stdio` subprocess pipes); tokens from other providers are never forwarded.

=== Pure Vocabulary Skills & Dynamic Context Injection (`PM-SKILL-1`, `PM-SKILL-2`, `PM-SKILL-4`)

* *Pure Vocabulary Contract (`PM-SKILL-1`)*: All procedural sequencing, CLI invocations, file path templates, and phase transition rules live exclusively in the compiled workflow engine. Vocabulary skills (`skill://pm/<domain>/<topic>/SKILL.md`) contain strictly domain standards, quality rubrics, architectural principles, and judgment criteria.
* *Server-Generated & Client-Cached Catalogue (`PM-SKILL-2`)*: Vocabulary skills are compiled into the `pm-mcp` binary, filtered by the project's enabled domains in `.plan/marshal.json`, and translated on the fly for the active client profile (`PM-CLIENT-2`). Every rendered skill includes a deterministic `_meta.sha256` content digest (`SHA-256(canonical_skill_bytes + client_profile_digest + domain_config_digest)`) enabling client-side caching and invalidation via standard MCP `notifications/resources/list_changed`.
* *Dynamic State Context Injection (`PM-SKILL-4`)*: Live plan facts (`plan_id`, `worktree_sha`, active task summary, findings count, and valid `_links`) are injected into the turn's TOON hypermedia representation (`guidance` + `facts` + `links`), never baked into static `SKILL.md` files.

  "additionalProperties": false
}
----

=== Companion Catalogue, Supporting File Tools & MCP Resource Parity (`pm_skills`, `pm_skill_file`, `resources/read`)

* `pm_skills`: Accepts optional `plan_id` or `epic_id` (`additionalProperties: false`) and returns the tabular TOON catalogue of all vocabulary skills active for the project's enabled domains (`uri`, `name`, `description`, `sha256`).
* `pm_skill_file`: Accepts required `uri` (`^skill://pm/[a-z0-9/_-]+/[a-zA-Z0-9_.-]+\.(md|adoc|json|toon)$`) and optional `plan_id`/`epic_id` (`additionalProperties: false`) to retrieve progressive-disclosure reference files linked from a `SKILL.md`.
* *Standard MCP Resource Template Parity (`PM-SKILL-3`)*: `pm-mcp` simultaneously exposes `skill://pm/{domain}/{topic}/SKILL.md` and `skill://pm/{domain}/{topic}/{file}` via standard MCP `resources/templates/list` and `resources/read`. Unadopted draft custom RPC methods (`skills/list`, `skills/get`) are not exposed.

[#protocol-errors-vs-domain-workflow-failure-states]
== Protocol Errors (`isError: true`) vs Domain Workflow Failure States (`isError: false`)
_See Requirement link:../Requirements.adoc#PM-TOOL-4[PM-TOOL-4: Domain Failures as Valid Workflow States]_

_See Requirement link:../Requirements.adoc#PM-TEST-4[PM-TEST-4: End-to-End Workflow Scenario & Replay Harness]_

A foundational invariant of PM-MCP is that *domain failures and transition rejections are workflow states, not MCP protocol errors*.

=== Normative Classification Matrix

[cols="2,1,2,3"]
|===
|Condition |MCP `isError` |Response Structure |Model Recovery Path

|Valid transition succeeds (`pm_do`)
|`false`
|Next state's TOON representation (`state`, `facts`, `links`).
|Follow one of the new `links`.

|Build fails, tests fail, or quality gate turns red
|`false`
|TOON representation in a remediation state (e.g., `execute.verify.failed`, `finalize.ci-failed`) with structured failure facts and `fix`, `retry`, `loop_back`, or `escalate` links.
|Inspect failure facts (or `log_uri`), apply code fixes, and follow `fix` / `retry` / `loop_back`.

|Git push rejected (non-fast-forward) or merge conflict
|`false`
|TOON representation in `finalize.sync-required` or `finalize.conflict` with `sync` / `fix` / `escalate` links.
|Follow the offered `sync` or `escalate` link.

|Host tool modifies files outside the plan's worktree
|`false`
|TOON representation in `<phase>.footprint-violation` naming the offending files and offering `fix` and `escalate` links.
|Revert unauthorized changes and follow `fix`, or `escalate` to operator.

|Stale link followed, entity no longer in accepting state, or `args` fails link parameter validation
|`false`
|Authoritative *current* TOON representation plus a top-level `rejected` block (`reason`, `link`, `detail`).
|Read the current representation and follow one of its valid `links` with corrected `args`.

|Operator approval required or loop-back limit reached
|`false`
|TOON representation in `*.blocked` or `finalize.loop-limit-reached` offering `wait` or `escalate`.
|Follow `escalate` or `wait` for operator action.

|Malformed JSON-RPC, unknown tool name, or top-level tool `inputSchema` violation
|`true`
|Standard JSON-RPC / MCP `CallToolResult` with `isError: true`, closed `error_code: "schema_validation_failed"`, and `audit_id`.
|Fix top-level tool invocation syntax.

|Unknown `plan_id` / `epic_id`, unenrolled workspace, or internal server exception
|`true`
|MCP `CallToolResult` with `isError: true`, closed `error_code` (`scope_not_found`, `project_not_enrolled`, `internal_fault`), and `audit_id`.
|Halt or invoke discovery (`pm_plans` / `pm_epics`) or notify operator with `audit_id`.
|===

=== Rejected Transition Representation (`isError: false`)

When `pm_do` is called with a stale link or invalid free parameter `args`, the server returns `isError: false` with a `rejected` block prepended to the current authoritative representation:

[source,toon]
----
scope: plan
plan_id: PLAN-X
state: finalize.push-barrier
phase: finalize
summary: tasks 11/11 done, freshness gate green, branch not pushed
rejected:
  link: commit
  reason: invalid_link_args
  detail: "parameter 'message' length 0 is below minimum 1"
skill: skill://pm/finalize/push-barrier/SKILL.md
facts:
  branch: feature/PLAN-X
  commits_ahead: 4
  gate.freshness: green
links[3]{rel,link,form,free}:
  next,push,noop,""
  alt,commit,submit,"message:text[1..2000]"
  escalate,escalate,escalate,"reason:text[1..500]"
----

=== Sanitized Protocol Error Envelope (`isError: true`)

When an actual MCP protocol or server error occurs (`isError: true`), the `TextContent` payload is strictly sanitized — stack traces, Java class names, filesystem paths, and credentials are never emitted:

[source,toon]
----
error: true
error_code: scope_not_found
audit_id: aud-20260925-004192
message: "Plan scope 'PLAN-UNKNOWN' does not exist in the enrolled workspace."
----

Closed `error_code` enumeration for `isError: true`:

* `schema_validation_failed` — Top-level MCP tool arguments violated the tool's JSON Schema.
* `scope_not_found` — Referenced `plan_id`, `epic_id`, or `entity` does not exist.
* `project_not_enrolled` — The target repository is not enrolled in `~/.plan-marshall/mcp/enrolments.json`.
* `entry_record_missing` — `pm_start` was called without a preceding `pm-mcp enter` record in the project.
* `rate_limit_exceeded` — Client exceeded per-client tool call rate limits.
* `internal_fault` — Unexpected server exception; full diagnostics are written exclusively to `audit.jsonl` under `audit_id`.

=== End-to-End STDIO Integration Testing (`McpStdioTestClient` in `*IT.java`)

Failsafe integration tests (`*IT.java`) spawn the packaged `pm-mcp` runner JAR or GraalVM native executable as a real child process over `stdin`/`stdout` via `McpAssured.newStdioClient()`:

[source,java]
----
McpStdioTestClient client = McpAssured.newStdioClient()
    .setCommand(List.of(pmMcpBinaryPath.toString(), "serve"))
    .setWorkingDirectory(tempWorkspaceRoot)
    .setEnvironment(Map.of("PLAN_MARSHALL_HOME", tempMarshallHome.toString()))
    .setStderrHandler(lines -> stderrAuditBuffer.addAll(lines))
    .build()
    .connect();

client.when()
    .toolsList(page -> {
        assertThat(page.tools())
            .extracting(ToolInfo::name)
            .containsExactlyInAnyOrder(
                "pm_start", "pm_state", "pm_do", "pm_plans", "pm_epics",
                "pm_build", "pm_lsp", "pm_skills", "pm_skill", "pm_skill_file");
    })
    .toolsCall("pm_start", Map.of("request", "Add JSpecify null-safety to service layer", "slug", "null-safety"), response -> {
        assertThat(response.isError()).isFalse();
        assertThat(response.content().getFirst().asText().text())
            .contains("scope: plan")
            .contains("phase: init");
    })
    .thenAssertResults();
----

=== Normative `McpAssured` Verification Requirements

1. *Tool & Resource Schema Conformance*: Every `@Tool` and `@ResourceTemplate` is asserted via `client.when().toolsList(...)` and `client.when().resourcesTemplatesList(...)` to verify closed JSON Schema Draft 2020-12 `inputSchema` definitions (`additionalProperties: false`) and exact URI template registrations.
2. *Domain Failure vs Protocol Error Assertions*: Every `pm_do` rejection and domain failure state is asserted with `assertThat(response.isError()).isFalse()`, while top-level schema violations and unknown scope queries are asserted with `assertThat(response.isError()).isTrue()` and sanitized `error_code` + `audit_id` payloads.
3. *`stdout` Stream Hygiene & `stderr` Separation*: `setStderrHandler(...)` captures all diagnostic output on `stderr` while `McpStdioTestClient` parses every `stdout` line as a strict JSON-RPC 2.0 frame, proving zero `stdout` pollution across concurrent `pm_build` and `pm_lsp` executions (`PM-SEC-4`, `PM-TEST-5`).
