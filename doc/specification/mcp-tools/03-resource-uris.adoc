== Read-Only MCP Resource URI Surface
_See Requirement link:../../Requirements.adoc#PM-TOOL-3[PM-TOOL-3: Read-Only MCP Resource URI Surface]_

_See Requirement link:../../Requirements.adoc#PM-EXT-3[PM-EXT-3: Module Discovery, Build Map & Architecture Enrichment]_

Large artifacts, logs, architecture views, and ledgers are never inlined into hypermedia representations; instead, representations emit canonical `pm://` and `skill://pm/` resource URIs that the model or host reads on demand via MCP `resources/read`. No compatibility URI aliases are supported.

=== Normative Resource URI Templates
_Implementation watch: link:../../implementation-watch/domain-extensions.adoc#PM-WATCH-EXT-25[PM-WATCH-EXT-25], link:../../implementation-watch/mcp-tools.adoc#PM-WATCH-TOOL-8[PM-WATCH-TOOL-8], link:../../implementation-watch/mcp-tools.adoc#PM-WATCH-TOOL-9[PM-WATCH-TOOL-9]_

[cols="2,1,1,3"]
|===
|URI Template |MIME Type |Scope |Payload Description

|`pm://plan/{plan_id}/state`
|`text/toon`
|Plan
|Current TOON hypermedia representation (identical to `pm_state(plan_id)`).

|`pm://plan/{plan_id}/status`
|`text/toon`
|Plan
|TOON projection of persisted `mcp/status.json` phase and step metadata.

|`pm://plan/{plan_id}/request`
|`text/markdown`
|Plan
|The plan's `request.md` document.

|`pm://plan/{plan_id}/outline`
|`text/markdown`
|Plan
|The validated solution outline (`outline.md`).

|`pm://plan/{plan_id}/task/{task_id}`
|`text/toon`
|Plan
|Structured definition, acceptance criteria, and step status for task `{task_id}` (e.g., `TASK-001`).

|`pm://plan/{plan_id}/findings`
|`text/toon`
|Plan
|Tabular TOON projection of `findings.jsonl` for `{plan_id}`.

|`pm://plan/{plan_id}/builds/{job_id}/log`
|`text/plain`
|Plan
|Complete raw console log output captured for build job `{job_id}` (supports `?tail=N` and `?offset=B&limit=L`).

|`pm://workspace/status`
|`text/toon`
|Workspace
|TOON projection of the workspace scope's `mcp/status.json` (state of the workflows it hosts, such as `project-setup`).

|`pm://workspace/findings`
|`text/toon`
|Workspace
|Tabular TOON projection of the workspace scope's `findings.jsonl` (findings of plan-less builds).

|`pm://workspace/questions`
|`text/toon`
|Workspace
|The fold of the workspace scope's question records (`questions.jsonl`, the setup choices that write team configuration), with the same fields as `pm://plan/{plan_id}/questions`.

|`pm://workspace/decisions`
|`text/toon`
|Workspace
|The workspace scope's decision records (`decisions.jsonl`), with the same fields as `pm://plan/{plan_id}/decisions`.

|`pm://workspace/lessons`
|`text/toon`
|Workspace
|The project's active, unclaimed lessons (`lesson_id`, `title`, `category`, `created_at`), most recent first, with the count of all lessons and the numbers excluded as claimed or retired: the full list behind the lesson candidates of the bootstrap's `start.choose`, whose `facts` carry at most ten (xref:01-core-workflow-tools.adoc#bootstrap-entries[Bootstrap Entries]). Lesson bodies are not served; a lesson that fails its digest check is listed with `unreadable` instead of its title.

|`pm://workspace/recipes`
|`text/toon`
|Workspace
|Every recipe the project can start (`recipe_key`, `title`, `origin`: `built_in`, `domain`, or `project`, and whether it declares a `parameters_schema`), for the enabled domains and the project-local recipes under `.marshall/recipes/` (link:../domain-extensions.adoc[Domain Extensions Specification], Recipes): the full list behind the recipe candidates of `start.choose`. A project-local recipe that fails validation is listed with its finding, never silently omitted.

|`pm://workspace/builds/{job_id}/log`
|`text/plain`
|Workspace
|Raw console log of a plan-less `pm_build` job run in the primary checkout (`plan_id: "NO_PLAN"`); same query parameters.

|`pm://plan/{plan_id}/diagram`
|`text/markdown`
|Plan
|Generated Mermaid/ASCII state machine diagram of the plan instance in force (link:../workflow-dsl/09-plan-instance.adoc#plan-instance[Workflow DSL Specification, Plan Instance]): the active state and the call path highlighted, pruned steps shown with their prune reason, waived gates with their waiver id. The v1 diagram composed in the bootstrap's commit transaction is the posture preview.

|`pm://plan/{plan_id}/instance` +
`pm://plan/{plan_id}/instance/{version}`
|`text/plain`
|Plan
|The DSL text and header of the plan instance in force, or of instance version `{version}` (`plan.v<N>.pmwf`, immutable): the digests of every input, the sub-units by id and digest, each call site's bound arguments with their provenance, the pruned steps with reason and source fact, and the composition event that produced the version. `{version}` is a positive integer not above the plan's `instance_version`; any other value is answered with `scope_not_found`.

|`pm://plan/{plan_id}/evidence/{evidence_id}`
|`text/plain`
|Plan
|One remediation evidence record of the plan's evidence directory (a CI log excerpt, a build failure, an analysis provider result, merge-conflict hunks), referenced by the `excerpt_uri` of a failure envelope (link:../hypermedia-format/01-representation-and-link-forms.adoc#remediation-evidence-facts[Hypermedia Format Specification, Remediation Evidence]). The payload is *untrusted* external content, marked so in the resource's `_meta`, and is never inlined into a representation beyond the envelope's `message`; supports `?tail=N` and `?offset=B&limit=L` like a build log. `evidence_id` follows its link:../identifiers.adoc[Identifier Registry] grammar; a separator or traversal is refused with `path_traversal_rejected`.

|`pm://plan/{plan_id}/questions`
|`text/toon`
|Plan
|The fold of the plan's question records (`questions.jsonl`): every record with `question_id`, class, origin, closure (`open`, `answered`, `assumed`, `cancelled`), and, once closed, the chosen `branch_key`, the answer's `channel`, and the `decision_id` of the decision taken.

|`pm://plan/{plan_id}/decisions`
|`text/toon`
|Plan
|The plan's decision records (`decisions.jsonl`, link:../model-work/11-decision-records.adoc#decision-visibility[Model Work Specification, Decision Records]): every decision with `decision_id`, decision point, subject, kind, decider, confidence, measurements with their thresholds and sources, choice, reason, and its corrections folded in order. Rationales are model- or user-authored text, marked untrusted in the resource's `_meta`; facts snapshots are not served.

|`pm://plan/{plan_id}/waivers`
|`text/toon`
|Plan
|The plan's waiver records (`waivers.jsonl`: gate, mode, value, reason, `revoked_at`) with their consumptions, and its waiver requests (`waiver_requests[]` with outcome). Read-only; waivers are written only through the operator channel.

|`pm://epic/{epic_id}/state`
|`text/toon`
|Epic
|Current TOON hypermedia representation of orchestrator epic `{epic_id}`.

|`pm://epic/{epic_id}/spec` +
`pm://epic/{epic_id}/spec/{section}`
|`text/markdown`
|Epic
|The epic specification document (`spec.md`) or a specific workstream/plan section.

|`pm://epic/{epic_id}/ledger`
|`text/toon`
|Epic
|Tabular TOON projection of workstreams and staged/active plans assembled from the per-file epic layout (`epic.json` and `queue/<plan_id>.json`).

|`pm://epic/{epic_id}/inbox` +
`pm://epic/{epic_id}/inbox/{message_id}`
|`text/toon`
|Epic
|The epic inbox as the fold of its event log (`inbox.jsonl`): every message with its current state (`pending`, `claimed`, `processed`), or one message by its store-assigned `message_id`. A plan's representation points at the messages it sent (link:../model-work/08-epic-coordination.adoc#plan-scope-outbox-link[Model Work Specification, Plan-Scope Outbox Link]). `message_id` must match the link:../identifiers/02-registry-stores-to-web.adoc#id-message-id[`message_id` grammar]; a separator or traversal is refused with `path_traversal_rejected`; reading never changes a message's state.

|`pm://plan/{plan_id}/mailbox` +
`pm://plan/{plan_id}/mailbox/{message_id}`
|`text/toon`
|Plan
|The plan's own mailbox (`mcp/mailbox.jsonl`, messages from its parent epic) with `mailbox_state`, `delivery_state`, and per-message consumption (link:../model-work/08-epic-coordination.adoc#plan-mailbox[Model Work Specification, Plan Mailbox]).

|`pm://project/config`
|`text/toon`
|Project
|The project's effective configuration (link:../store-schemas/07-project-configuration.adoc#project-configuration-store[Store Schemas Specification, Project Configuration]): `config_hash`; every effective value with its key, `source` (`compiled_default`, `derived`, `team`, `operator`), file, and, for a derived value, the fact `state`; the project's workflow units with their origin, `default_revision`, digest, and verification outcome; and every validation finding with file, pointer or line, and reason. Read-only; the model and the operator never read the raw configuration files.

|`pm://project/owed`
|`text/toon`
|Project
|Undischarged owed items of every active and archived plan of the project, derived from their `owed[]` (link:../store-schemas/03-findings-and-review-records.adoc#owed-item-record[Store Schemas Specification, Owed Item Record]), with per-root coverage.

|`pm://epic/{epic_id}/landings`
|`text/toon`
|Epic
|Verified landing analysis records (`landings.jsonl`).

|`pm://epic/{epic_id}/decisions`
|`text/toon`
|Epic
|The epic scope's decision records (`decisions.jsonl`), with the same fields as `pm://plan/{plan_id}/decisions`.

|`pm://architecture/overview`
|`text/toon`
|Project
|High-level module inventory, build systems, active domains, and enrichment status.

|`pm://architecture/modules/{module_id}`
|`text/toon`
|Project
|Detailed module descriptor, dependencies, key packages, and enriched responsibility for `{module_id}`.

|`pm://architecture/files` +
`pm://architecture/files?path={rel_path}`
|`text/toon`
|Project
|Without `path`: the file inventory (file categories with counts) and a coverage block `{files_scanned, excluded{reason: n}, complete}`; a zero count is honest only with `files_scanned > 0` and `complete: true`. With `path`: owning module, domain attribution (Axis D), and verification route (Axis B) for `{rel_path}`. Content search stays with the host's search tool.

|`pm://architecture/files/{+path}/neighbours`
|`text/toon`
|Project
|File-level neighbours of one repository-relative file: its resolved imports (`unresolved[]` for imports that resolve to no file), its paired test or production file, and its owning module. Read by the light gate `init.light-gate` (link:../phase-workflows/02-planning-lanes-phases-3-4.adoc#light-gate[Phase Workflows Specification, Light Gate]).

|`pm://architecture/graph`
|`text/toon`
|Project
|Full inter-module dependency DAG with Axis C edge provenance (`_derivation_merge`).

|`pm://architecture/neighbours/{module_id}`
|`text/toon`
|Project
|Direct upstream dependencies and downstream dependents of `{module_id}`.

|`pm://architecture/impact?modules={csv}`
|`text/toon`
|Project
|Transitive impact closure and required verification commands for a comma-separated module list.

|`pm://architecture/drift`
|`text/toon`
|Project
|Structural drift report comparing current build descriptors against the structural module snapshot, the derived fact `module_discovery` of the project's `derived-facts.json` (link:../domain-extensions.adoc[Domain Extensions Specification]): `changed[]` and `indeterminate[]{module, reason}`; a comparison the hash surface cannot certify is `indeterminate`, never `changed`.

|`skill://pm/{+path}/SKILL.md`
|`text/markdown`
|Project / Client
|Vocabulary skill Markdown rendered for the calling connection's client profile, with the `_meta["de.cuioss.pm-mcp/sha256"]` digest of the rendered bytes; the same resource the Skills Extension manifests name (xref:02-service-and-skill-tools.adoc#skills-extension[MCP Skills Extension & Tool Mirror]).
|===

*Resource Contract*: Every resource template documents its arguments, its payload, and its zero-result and error semantics (the `pm://architecture/*` details are in link:../domain-extensions.adoc[Domain Extensions Specification]). A resource that returns no rows states what it examined, so an empty result is distinguishable from a result that could not be computed; an unknown scope or entity is answered with the JSON-RPC resource error `-32002` (resource not found) whose `data` carries `error_code: scope_not_found` (sanitized as in xref:04-errors-and-testing.adoc#protocol-errors-vs-domain-workflow-failure-states[Protocol Errors, Tool Execution Errors (`isError: true`) & Domain Workflow Failure States (`isError: false`)]; the refusal is audited, its `audit_id` is not returned), never with an empty payload; a resource path resolving outside its permitted root is answered the same way with `error_code: path_traversal_rejected`. `ReadResourceResult` has no `isError`, so resource errors are always JSON-RPC errors.

*Read Access Within the Project*: Every resource is readable, read-only, by every scope of its own project; the project boundary (`PM-SEC-2`) is the only access boundary, and there are no per-scope read restrictions on inbox, mailbox, or findings resources. Representations still point each scope at its own resources. The same holds on a worker connection: `resources/list` and `resources/read` serve every resource of the worker's own project and `skill://pm/…`, read-only, without a task restriction (xref:01-core-workflow-tools.adoc#job-bound-connections[Worker Connections]); a worker of the `zero_tool` class has no connection and reads none.
