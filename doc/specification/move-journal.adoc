== Overview

This document specifies the technical design, data structures, and crash-recovery protocols for the PM-MCP **Write-Ahead Move Journal** (`move-journal.json`). It guarantees that relocating plan state directories between the repository primary checkout and dedicated git worktrees (`PM-ARCH-7`) is strictly atomic, crash-proof, and resilient against sudden process termination or machine power failures.

== Relocation Protocol State Machine

[source,text]
----
   ┌─────────────┐
   │ INITIALIZED │  (Acquire exclusive file lock on plan)
   └──────┬──────┘
          │ 1. Write journal (TARGET_PREPARED) & fsync
          ▼
┌──────────────────┐
│ TARGET_PREPARED  │  (Target parent dirs created, same filesystem verified)
└─────────┬────────┘
          │ 2. Atomic Files.move(source, target, ATOMIC_MOVE)
          ▼
      ┌───────┐
      │ MOVED │       (Directory successfully placed at target)
      └───┬───┘
          │ 3. Update status.json location pointer & fsync
          ▼
    ┌───────────┐
    │ COMMITTED │     (Delete move-journal.json, release lock)
    └───────────┘
----

=== Step-by-Step Protocol

1. *Locking*: Acquire the plan lock `<main>/.plan/local/locks/plan-<plan_id>.lock`, which lies outside both the source and the target directory (`PM-IMPL-7`). Every writer of a plan store takes this lock, including the parent epic when it appends to the plan mailbox `mcp/mailbox.jsonl` (link:dispatch-and-effort.adoc#plan-mailbox[Dispatch & Effort Specification, Plan Mailbox]), so no append lands in the source location after the rename and the mailbox always moves with the directory.
2. *Journal Creation (`TARGET_PREPARED`)*: Verify that `source_path` and `target_path` reside on the same filesystem partition (`Files.getFileStore(source).equals(Files.getFileStore(target.getParent()))`). Write `move-journal.json` to `source_path/move-journal.json` with `phase_state: "TARGET_PREPARED"`, and flush and sync to disk using `FileChannel.force(true)`.
3. *Atomic Rename (`MOVED`)*: Execute `java.nio.file.Files.move(sourcePath, targetPath, StandardCopyOption.ATOMIC_MOVE)`. Because both paths reside within `<repo>/.plan/local/`, this executes as a single POSIX `rename(2)` syscall.
4. *Commit & State Update (`COMMITTED`)*: Update `status.json` inside the newly moved target directory (`location: "WORKTREE"` or `"MAIN_CHECKOUT"`, update `worktree_path` to the canonical absolute path of the worktree root, and increment state update timestamp) and fsync `status.json`. On relocation to `MAIN_CHECKOUT`, `worktree_path` is set to `null` in the same `status.json` write; no other store keeps a claim on the worktree that is about to be removed.
5. *Journal Cleanup*: Delete `target_path/move-journal.json` and release the plan lock.

== Startup Crash Recovery Protocol

Whenever the PM-MCP runtime starts up, or on the first call addressing a plan, the recovery scanner acquires that plan's lock (`<main>/.plan/local/locks/plan-<plan_id>.lock`) and then checks for the presence of `move-journal.json` in the locations below. Only the runtime performs moves, and it performs them under the same lock, so a journal found while holding the lock always belongs to an interrupted move, never to one in progress:

* `<workspace>/.plan/local/plans/<plan_id>/move-journal.json`
* `<workspace>/.plan/local/worktrees/<plan_id>/.plan/local/plans/<plan_id>/move-journal.json`

If an active journal is detected, recovery executes according to the following idempotent decision tree:

[cols="1,2,3"]
|===
|Recorded `phase_state` |Physical Directory Condition |Recovery Action

|`TARGET_PREPARED`
|`source_path` exists on disk; `target_path` does *not* exist.
|*Rollback*: Directory was not moved. Remove empty target parent directories if created. Delete `move-journal.json`. Log recovery event in `audit.jsonl`. Leave plan at `source_path`.

|`TARGET_PREPARED`
|`source_path` does *not* exist; `target_path` *does* exist.
|*Roll-forward*: `rename(2)` completed immediately before crash, before journal was updated. Update `status.json` at `target_path` to reflect new location. Delete `move-journal.json`. Log recovery event.

|`MOVED`
|`target_path` exists on disk.
|*Roll-forward*: Update `status.json` at `target_path` to reflect current location (`WORKTREE` or `MAIN_CHECKOUT`). Delete `move-journal.json`. Log recovery event.

|Any state
|Both `source_path` and `target_path` exist on disk simultaneously.
|*Invariant Violation*: Raise immediate `indeterminate` operational alert to operator. Refuse automatic mutation. Provide operator CLI repair command `pm-mcp operator repair-plan <plan_id>`.
|===

This recovery protocol guarantees zero lost work, zero duplicate directories, and deterministic location resolution across process restarts.
