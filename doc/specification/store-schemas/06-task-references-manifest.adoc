*Task Status*: `pending` (not yet in an envelope) and `in_progress` (in the envelope of a running model job) are open; a change beyond the declared footprint never blocks a task (it is recorded as an unplanned change, <<_references_footprint_store_schema_references_json>>); a task whose dependencies are not yet satisfied stays `pending`. `completed`, `infeasible`, and `removed` are terminal; no task status `skipped` exists, and no verb skips a task:

* `completed`: the server's independent verification of `submit:TASK-NNN` passed (link:../phase-workflows/03-q-gate-and-execute.adoc#_task_envelope_execution_independent_server_verification[Phase Workflows Specification]).
* `infeasible`: set by the sub-agent's `infeasible:TASK-NNN` with its evidence (`disposition.by: sub_agent`, `disposition.evidence`).
* `removed`: the task's deliverable was removed by the outline gate or by the model's `remove_deliverable:<deliverable_id>` in `execute.infeasible-review` (`disposition.by: model`, with the model's reason); `disposition.by` names which.

A task in `infeasible` or `removed` carries a non-null `disposition`; a task in any other status carries none. Step status is `pending`, `completed`, `skipped`, or `failed`.

*Dependencies (`depends_on`)*: Phase 4 writes the task graph into `depends_on` (link:../phase-workflows/02-planning-lanes-phases-3-4.adoc#_deterministic_task_derivation_dag_cycle_detection[Phase Workflows Specification]). At every task creation or amendment the server checks that every referenced task exists in the plan and that the graph stays acyclic; otherwise the write is refused (`invalid_link_args`, `detail` `task_dependency_unresolved` or `task_dependency_cycle`, naming the tasks) and no task file is written. A dependency is satisfied only by a task in status `completed`.

A deliverable may declare several verification command and criterion pairs; the task carries them all in `verification`. A task with profile `implementation`, `module_testing`, or `integration_testing` requires at least one command and at least one criterion. An empty or truncated criterion rejects task creation; it is never downgraded to a warning.
