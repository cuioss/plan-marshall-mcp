*Task Status*: `pending` (not yet dispatched), `in_progress` (yielded to a dispatched sub-agent), and `blocked` (a submitted scope deviation awaits the operator's decision) are open; a task whose dependencies are not yet satisfied stays `pending`. `completed`, `skipped`, `infeasible`, and `removed` are terminal:

* `completed`: the server's independent verification of `submit:TASK-NNN` passed (link:../phase-workflows/03-q-gate-and-execute.adoc#_task_envelope_execution_independent_server_verification[Phase Workflows Specification]).
* `skipped`: set by the operator only, with a recorded reason (`disposition.by: operator`); never offered to the model.
* `infeasible`: set by the sub-agent's `infeasible:TASK-NNN` with its evidence (`disposition.by: sub_agent`, `disposition.evidence`).
* `removed`: the task's deliverable was removed by the outline gate, by a `split`, or by the operator after an `infeasible` (`disposition.by` names which).

A task in `skipped`, `infeasible`, or `removed` carries a non-null `disposition`; a task in any other status carries none. Step status is `pending`, `completed`, `skipped`, or `failed`.

*Dependencies (`depends_on`)*: Phase 4 writes the task graph into `depends_on` (link:../phase-workflows/02-planning-lanes-phases-3-4.adoc#_deterministic_task_derivation_dag_cycle_detection[Phase Workflows Specification]). At every task creation or amendment the server checks that every referenced task exists in the plan and that the graph stays acyclic; otherwise the write is refused (`invalid_link_args`, `detail` `task_dependency_unresolved` or `task_dependency_cycle`, naming the tasks) and no task file is written. A dependency is satisfied only by a task in status `completed` or `skipped`.

A deliverable may declare several verification command and criterion pairs; the task carries them all in `verification`. A task with profile `implementation`, `module_testing`, or `integration_testing` requires at least one command and at least one criterion. An empty or truncated criterion rejects task creation; it is never downgraded to a warning.

=== Execution Manifest Store Schema (`execution-manifest.json`)

Composed deterministically in-process by `ExecutionManifestResolver` during Phase 4 (`plan`). Records both the active Phase 5/Phase 6 step lists and the structured `dropped_steps` audit list so prune decisions are inspectable directly from JSON without scraping free-text logs.

----

  "title": "ExecutionManifestRecord",
  "type": "object",
  "required": [
    "format_version",
    "posture",
    "phase_5",
    "phase_6",
    "composed_at"

  "additionalProperties": false,
  "properties": {
    "format_version": { "type": "integer", "const": 1 },

    "phase_5": {
      "type": "object",
      "required": ["verification_steps"],
      "additionalProperties": false,
      "properties": {
        "verification_steps": { "type": "array", "items": { "type": "string" } }
      }
    },
    "phase_6": {
      "type": "object",
      "required": ["steps", "dropped_steps"],
      "additionalProperties": false,
      "properties": {
        "steps": { "type": "array", "items": { "type": "string" } },

          "type": "object",
