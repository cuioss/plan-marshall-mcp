[#local-config]
== Operator Local Configuration (`<PM_MCP_BASE>/projects/<project_id>/local-config.json`)
_Implementation watch: link:../../implementation-watch/domain-extensions.adoc#PM-WATCH-EXT-29[PM-WATCH-EXT-29]_

Operator posture and machine-local bindings of one project, written only through the operator channel (`pm-operator config --project <project_id>`, or an elicitation link of the setup workflow), never by the model. Sparse like the team files; each key of `$defs/settings` falls back to `machine-config.json` `project_defaults` and then to the compiled default. `$defs/settings` is shared with `project_defaults` (xref:12-machine-stores.adoc#machine-config[Machine Configuration Store (`<PM_MCP_BASE>/machine-config.json`)]).

Three keys are per project only, outside `$defs/settings`, with neither a machine-wide default nor a compiled default:

* `integrations.<integration>.variant` (`native` or `cli`) for the integrations `git`, `github`, and `gitlab`, set in `setup.select-integration-variants` (link:../domain-extensions/04-setup-state-machine.adoc#setup-integration-variants[Domain Extensions Specification, Integration Variants]). The setup applies `native` without asking unless the derived fact `git_native_capability` finds a feature the project uses that the native variant cannot serve; only then is the choice required, and it is taken through the operator channel only (elicitation where the connection supports it, otherwise `pm-operator config --project <project_id>`, named in the state's `facts`), never as a question record and never from a model-relayed answer. One value holds for every operation of the integration; there is no per-operation or per-family override. An entry that is absent while the choice is required means undecided, and every operation of that integration refuses with `integration_variant_unset`. A `cli` value requires the integration's host tool (`git`, `gh`, `glab`) in the project's enrolment (xref:11-enrolment-store.adoc#enrolment-store[Project Enrolment Store (`<PM_MCP_BASE>/enrolments/<project_id>.json`)]), otherwise the finding `cli_tool_not_enrolled`. Sonar has no entry: it has only the native variant. The effective value carries `source: operator` and enters `config_hash`; it is served on demand by the operator surfaces (`pm-operator config --project <project_id>`, `pm-operator status`, `pm://project/config`) and never pushed into a representation or tool result (link:../hypermedia-format/01-representation-and-link-forms.adoc#model-facing-minimality[Hypermedia Format Specification, Model-Facing Minimality]).
* `commit_identity {name, email}`: the author of every server commit (the operator, who is responsible for the change), captured in `setup.select-integration-variants` through the operator channel only, like the variant choice; the committer is the agent identity resolved from the provider credential (derived fact `agent_identity`), else the fixed `plan-marshall-mcp` noreply identity (link:../domain-extensions/04-setup-state-machine.adoc#setup-verify-credentials[Domain Extensions Specification, Credential Verification]). While it is absent, a commit refuses with `identity_missing`. The `commit_trailer` below stays a separate key.
* `upstream_mcp`: the upstream MCP allowlist of the project (`PM-SVC-3`, link:../mcp-tools/02-service-and-skill-tools.adoc#_selective_upstream_mcp_proxy_meta_provenance_pm_svc_3[MCP Tools Specification, Selective Upstream MCP Proxy]): per `server_id` the server's HTTPS `url`, its credential key `mcp-<server_id>` where the server is authenticated, the re-exposed tools, and the call timeouts. Its only writer is the operator verb `pm-operator upstream allow|deny` (the runtime writes under `local-config.lock`); `pm-operator config` does not change it, and repository content never adds a server or a tool. Upstream servers are remote HTTPS servers reached through `cui-http`; there is no `stdio` subprocess variant. Absent means no upstream server.

*Remediation Budgets Are Not Configuration*: `retry_budget`, `fix_budget`, `waiver_wait_seconds`, and the allowed `decide` actions of a remediation policy are call arguments of the project-owned phase units (`.marshall/config/*.pmwf`, link:../workflow-dsl/04-ast-node-model.adoc#project-owned-units[Workflow DSL Specification, Project-Owned Workflow Units]), bound with their source in the plan instance (xref:14-plan-instance-waivers-questions.adoc#plan-instance[Plan Instance]) and capped by the compiled hard limits (link:../timeouts/01-job-budgets-and-waits.adoc#remediation-budgets[Timeouts & Budgets Specification, Remediation Budgets]); no JSON configuration file holds them, and the operator raises one only by a `raise` waiver for one plan.

*Decision Parameters Are Not Configuration Keys*: The panel roles, quorum, minimum score, decidable kinds, panel wait, and panel qualification level of the question adjudication, and the trigger thresholds, budget, and prerequisite wait of the re-planning, are declarations of the project-owned units `question-adjudicate.pmwf` and `replan.pmwf` within compiled bounds (link:../workflow-dsl/02-units-jobs-decisions.adoc#unit-declarations[Workflow DSL Specification, Unit Declarations]); this file holds only who answers questions (`questions.mode`) and how long (`questions.wait_seconds`).

*Roles Are Not Configuration Keys*: The harness, model, effort, form, count, and recycling of model work belong to the role artifacts of the operator's role sets (`<PM_MCP_BASE>/roles/`, `<PM_MCP_BASE>/projects/<project_id>/roles/`, link:../model-work/01-roles-and-configuration.adoc[Model Work Specification, Roles & Configuration]; paths in link:../filesystem-layout.adoc#machine-store[Filesystem Layout Specification, Per-Project Machine Store]); neither this file nor `project_defaults` holds a key for them.
