[#local-config]
== Operator Local Configuration (`<PM_MCP_BASE>/projects/<project_id>/local-config.json`)
_Implementation watch: link:../../implementation-watch/domain-extensions.adoc#PM-WATCH-EXT-29[PM-WATCH-EXT-29]_

Operator posture and machine-local bindings of one project, written only through the operator channel (`pm-mcp operator config --project <project_id>`, or an elicitation link of the setup workflow), never by the model. Sparse like the team files; each key of `$defs/settings` falls back to `machine-config.json` `project_defaults` and then to the compiled default. `$defs/settings` is shared with `project_defaults` (xref:12-machine-stores.adoc#machine-config[Machine Configuration Store (`<PM_MCP_BASE>/machine-config.json`)]).

Two keys are per project only, outside `$defs/settings`, with neither a machine-wide default nor a compiled default:

* `integrations.<integration>.variant` (`native` or `cli`) for the integrations `git`, `github`, and `gitlab`: the operator's explicit choice of `setup.select-integration-variants` (link:../domain-extensions/04-setup-state-machine.adoc#setup-integration-variants[Domain Extensions Specification, Integration Variants]). One value holds for every operation of the integration; there is no per-operation or per-family override. An absent entry means undecided, and every operation of that integration refuses with `integration_variant_unset`; it never resolves to `native`. A `cli` value requires the integration's host tool (`git`, `gh`, `glab`) in the project's enrolment (xref:11-enrolment-store.adoc#enrolment-store[Project Enrolment Store (`<PM_MCP_BASE>/enrolments/<project_id>.json`)]), otherwise the finding `cli_tool_not_enrolled`. Sonar has no entry: it has only the native variant. The effective value carries `source: operator` and enters `config_hash`; it is served on demand by the operator surfaces (`pm-mcp operator config --project <project_id>`, `pm-mcp status`, `pm://project/config`) and never pushed into a representation or tool result (link:../hypermedia-format/01-representation-and-link-forms.adoc#model-facing-minimality[Hypermedia Format Specification, Model-Facing Minimality]).
* `commit_identity {name, email}`: the author of every server commit (the operator, who is responsible for the change), captured in `setup.select-integration-variants`; the committer is the agent identity resolved from the provider credential (derived fact `agent_identity`), else the fixed `plan-marshall-mcp` noreply identity (link:../domain-extensions/04-setup-state-machine.adoc#setup-verify-credentials[Domain Extensions Specification, Credential Verification]). While it is absent, a commit refuses with `identity_missing`. The `commit_trailer` below stays a separate key.
