[#local-config]
== Operator Local Configuration (`<PM_MCP_BASE>/projects/<project_id>/local-config.json`)
_Implementation watch: link:../../implementation-watch/domain-extensions.adoc#PM-WATCH-EXT-29[PM-WATCH-EXT-29]_

Operator posture and machine-local bindings of one project, written only through the operator channel (`pm-mcp operator config --project <project_id>`, or an elicitation link of the setup workflow), never by the model. Sparse like the team files; each key of `$defs/settings` falls back to `machine-config.json` `project_defaults` and then to the compiled default. `$defs/settings` is shared with `project_defaults` (xref:12-machine-stores.adoc#machine-config[Machine Configuration Store (`<PM_MCP_BASE>/machine-config.json`)]).

Two keys are per project only, outside `$defs/settings`, with neither a machine-wide default nor a compiled default:

* `integrations.<integration>.variant` (`native` or `cli`) for the integrations `git`, `github`, and `gitlab`, set in `setup.select-integration-variants` (link:../domain-extensions/04-setup-state-machine.adoc#setup-integration-variants[Domain Extensions Specification, Integration Variants]). The setup applies `native` without asking unless the derived fact `git_native_capability` finds a feature the project uses that the native variant cannot serve; only then is the choice required, and it is taken through the operator channel only (elicitation where the connection supports it, otherwise `pm-mcp operator config --project <project_id>`, named in the state's `facts`), never as a question record and never from a model-relayed answer. One value holds for every operation of the integration; there is no per-operation or per-family override. An entry that is absent while the choice is required means undecided, and every operation of that integration refuses with `integration_variant_unset`. A `cli` value requires the integration's host tool (`git`, `gh`, `glab`) in the project's enrolment (xref:11-enrolment-store.adoc#enrolment-store[Project Enrolment Store (`<PM_MCP_BASE>/enrolments/<project_id>.json`)]), otherwise the finding `cli_tool_not_enrolled`. Sonar has no entry: it has only the native variant. The effective value carries `source: operator` and enters `config_hash`; it is served on demand by the operator surfaces (`pm-mcp operator config --project <project_id>`, `pm-mcp status`, `pm://project/config`) and never pushed into a representation or tool result (link:../hypermedia-format/01-representation-and-link-forms.adoc#model-facing-minimality[Hypermedia Format Specification, Model-Facing Minimality]).
* `commit_identity {name, email}`: the author of every server commit (the operator, who is responsible for the change), captured in `setup.select-integration-variants` through the operator channel only, like the variant choice; the committer is the agent identity resolved from the provider credential (derived fact `agent_identity`), else the fixed `plan-marshall-mcp` noreply identity (link:../domain-extensions/04-setup-state-machine.adoc#setup-verify-credentials[Domain Extensions Specification, Credential Verification]). While it is absent, a commit refuses with `identity_missing`. The `commit_trailer` below stays a separate key.

*Remediation Budgets Are Not Configuration*: `retry_budget`, `fix_budget`, `waiver_wait_seconds`, and the allowed `decide` actions of a remediation policy are call arguments of the project-owned phase units (`.marshall/config/*.pmwf`, link:../workflow-dsl/04-ast-node-model.adoc#project-owned-units[Workflow DSL Specification, Project-Owned Workflow Units]), bound with their source in the plan instance (xref:14-plan-instance-waivers-questions.adoc#plan-instance[Plan Instance]) and capped by the compiled hard limits (link:../timeouts/01-job-budgets-and-waits.adoc#remediation-budgets[Timeouts & Budgets Specification, Remediation Budgets]); no JSON configuration file holds them, and the operator raises one only by a `raise` waiver for one plan. The `reader` keys are unchanged.
