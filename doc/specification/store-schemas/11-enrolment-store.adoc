[#enrolment-store]
== Project Enrolment Store (`<PM_MCP_BASE>/enrolments/<project_id>.json`)

One file per enrolled project, `<PM_MCP_BASE>/enrolments/<project_id>.json`, holding the operator-authorized project root, build wrappers with their pinned files, pinned host tools, the canonical and discovery command templates, provider verification overrides, language servers, approved out-of-process project scripts, operator budgets, the Landlock write paths, and the captured build environment (`PM-EXEC-2`, `PM-EXEC-3`, `PM-EXT-5`, `PM-EXT-6`). Written exclusively via the operator channel (`pm-mcp operator enrol`, link:../cli-and-security/02-credentials-and-operator.adoc#enrolment-lifecycle-release[CLI, Coordination & Security Specification]). The set of enrolled projects is the directory listing; the operator-owned `enrolments/` directory is separate from the server-owned `projects/`.

* *Integrity*: Every write of an enrolment file (an operator verb, executed by the runtime on the CLI's request; the CLI writes no store) runs under its own lock `<PM_MCP_BASE>/locks/enrolments/<project_id>.lock`, and the runtime also writes its sidecar `<PM_MCP_BASE>/enrolments/<project_id>.json.hmac`, the lowercase-hex HMAC-SHA-256 over the exact bytes of the canonical file the runtime wrote, keyed with the operator-lane secret from the OS keyring (service `de.cuioss.pm-mcp`; on hosts without a keyring `<PM_MCP_BASE>/state/enrolment-hmac.key`, mode `0600`), which only `pm-mcpd` reads; the key never leaves the runtime. The runtime verifies a project's file before serving the project for the first time after start and before every verify-not-resolve check, and refuses with `enrolment_tampered` on mismatch (link:../cli-and-security/02-credentials-and-operator.adoc#enrolment-integrity[CLI, Coordination & Security Specification, Enrolment Integrity]).
* *Isolation*: A tampered, unreadable, or schema-invalid enrolment file blocks only its own project; every other project is served. `project_root` is unique across all enrolment files; the operator CLI checks it at every enrolment write and the runtime at start, and a duplicate root blocks both projects with `enrolment_root_conflict` until the operator resolves it.
* *Closed and Exact*: The schema is closed at every level (`additionalProperties: false`), and a file whose `format_version` is not the binary's is refused (`format_outdated` or `format_newer`, naming the file, xref:01-format-and-session-log.adoc#format-versioning[Format Versioning & Atomic Write Discipline]).
* *Templates Decide What Runs*: A build job runs the canonical template of its build system and verb (`build.canonical_templates`), or the compiled default when none is enrolled; there is no goal allowlist per wrapper. The typed placeholder `{module}`, the only one, is validated at job time; a verb that needs a build profile names it literally in its template (for example `"integration-tests": ["verify", "-Pintegration-tests", "-pl", "{module}"]`) (link:../domain-extensions/06-configuration.adoc#enrolled-argument-templates[Domain Extensions Specification, Tier 2]).

[#project-store-identity]
=== Project Store Identity (`<PM_MCP_BASE>/projects/<project_id>/store.json`)
_Implementation watch: link:../../implementation-watch/cli-and-security.adoc#PM-WATCH-CLI-23[PM-WATCH-CLI-23]_

The per-project machine store records the main checkout it belongs to. `pm-mcp operator enrol` writes `store.json` once, when it creates the store; nothing changes it afterwards. `pm-mcp operator unenrol` removes only the enrolment file and its sidecar and leaves the store with this record in place (link:../cli-and-security/02-credentials-and-operator.adoc#enrolment-lifecycle-release[CLI, Coordination & Security Specification]). Enrolling the same `project_id` again reuses the store only when the new `project_root` equals the recorded one; otherwise the enrolment is refused (`project_store_root_mismatch`), naming both roots.

[source,json]
----
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://cuioss.de/plan-marshall-mcp/schemas/project-store.json",
  "title": "ProjectStoreIdentity",
  "type": "object",
  "required": ["format_version", "project_id", "project_root", "created_at"],
  "additionalProperties": false,
  "properties": {
    "format_version": { "type": "integer", "const": 1 },
    "project_id": { "type": "string", "pattern": "^[a-z0-9][a-z0-9-]{1,62}[a-z0-9]$", "description": "Equals the store directory name." },
    "project_root": { "type": "string", "minLength": 1, "description": "Canonical absolute path of the main checkout at the enrolment that created the store." },
    "created_at": { "type": "string", "format": "date-time" }
  }
}
