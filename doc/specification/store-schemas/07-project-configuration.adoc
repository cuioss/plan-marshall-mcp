[#project-configuration-store]
== Project Configuration (`.marshall/config/`, `local-config.json`, Effective Configuration; `PM-EXT-6`, `PM-EXT-7`)
_Implementation watch: link:../../implementation-watch/domain-extensions.adoc#PM-WATCH-EXT-21[PM-WATCH-EXT-21], link:../../implementation-watch/store-schemas.adoc#PM-WATCH-STORE-13[PM-WATCH-STORE-13], link:../../implementation-watch/store-schemas.adoc#PM-WATCH-STORE-25[PM-WATCH-STORE-25]_

Configuration is split by owner class (link:../domain-extensions/06-configuration.adoc#config-split[Domain Extensions Specification, Configuration Split]): four git-tracked *team* files and the project-owned workflow units under `.marshall/config/`, one machine-local *operator* file per project (xref:08-project-configuration-local.adoc#local-config[Operator Local Configuration (`<PM_MCP_BASE>/projects/<project_id>/local-config.json`)]), and the machine-wide operator defaults `project_defaults` of `machine-config.json` (xref:12-machine-stores.adoc#machine-config[Machine Configuration Store (`<PM_MCP_BASE>/machine-config.json`)]). No file mixes owner classes and no key exists in two owner classes. Binary versions, fingerprints, migration ledgers, and "offered" lists never land in a team file. `PM-MCP` never reads a legacy `.plan/marshal.json` and imports nothing from it (`PM-MIG-2`); the project setup workflow creates `.marshall/config/` on its first run.

[cols="2,1,2,3"]
|===
|File |Owner |Writer |Content

|`.marshall/config/project.json`
|team
|project-setup links (validated), committed edits
|Repository and collaboration policy: base branch, branch prefix, the `merge_method` and `ci_provider` overrides, integrations (Sonar coordinates), review bots, the project's review-bot registry records, review currency.

|`.marshall/config/workflow.json`
|team
|project-setup links, committed edits
|Plan workflow policy: minimum planning lane, refine compatibility and simplicity, per-deliverable verification verbs and final verification, lane and parameters of optional finalize steps, project finalize step descriptors. No team file names a role, a harness, a model, or an effort: those live only in the operator's role artifacts (link:../model-work/01-roles-and-configuration.adoc[Model Work Specification, Roles & Configuration], `PM-WORK-1`).

|`.marshall/config/domains.json`
|team
|project-setup links, committed edits
|Overrides of the derived domain detection: forced enable or disable, `always_on`, `file_globs`, disabled profiles.

|`.marshall/config/build-map.json`
|team
|`setup.seed-build-map` (write-once), `customize_routes`, `setup.reseed-build-map`, committed edits
|The file-to-build route table (link:../domain-extensions/03-module-discovery.adoc#_build_map_deterministic_derive_verification_adr_004[Domain Extensions Specification, Build Map]); seeded, not sparse.

|`.marshall/config/*.pmwf`
|team
|`setup.prepare-workspace` (copy of the binary's default units), `setup.offer-new-steps` (adopted default changes), committed edits
|The project-owned phase workflow and sub-workflow units, the re-planning and adjudication units with their declared decision parameters among them (link:../workflow-dsl/02-units-jobs-decisions.adoc#unit-declarations[Workflow DSL Specification, Unit Declarations]), verified on every load against the compiled invariants (link:../workflow-dsl/04-ast-node-model.adoc#project-owned-units[Workflow DSL Specification, Project-Owned Workflow Units & Compiled Invariants]).

|`<PM_MCP_BASE>/projects/<project_id>/local-config.json`
|operator
|`pm-operator config --project <project_id>`, operator-channel links (elicitation) of the setup workflow
|Operator posture and machine-local bindings of one project (xref:08-project-configuration-local.adoc#local-config[Operator Local Configuration (`<PM_MCP_BASE>/projects/<project_id>/local-config.json`)]).
|===

. *Sparse Files*: A team file and `local-config.json` hold only deviations from the effective default; an absent file means "no deviation" (except `build-map.json`, whose absence is `build_map_unseeded`). There is no default seeding into files, no default sync, no key sorting, and no key normalization: a new compiled default reaches every project with the binary, while in-flight plans stay protected by the plan instance snapshot (item 6). A key whose value equals the effective default without it is reported as the advisory finding `redundant_config_key`.
. *Version*: Every JSON configuration file carries `format_version` and is accepted only at the binary's current version (xref:01-format-and-session-log.adoc#format-versioning[Format Versioning & Atomic Write Discipline]); an outdated or newer team file refuses the project's scope creations (re-checked in a bootstrap's `start.create-scope` transaction) and phase handshakes with `format_outdated` or `format_newer` naming the file, and is never rewritten by a reader.
. *Closed Schemas, Validated on Every Read*: The schemas below are closed at every level (`additionalProperties: false`). Every computation of the effective configuration validates the files against them and against the server-side rules named in their descriptions. An undeclared key is the finding `unknown_config_key` naming the file and JSON pointer, never a silently kept setting; a setup or configuration link that would write an undeclared key is refused (`invalid_link_args`). A team file or workflow unit that fails validation is a verification finding in the workspace scope and refuses the project's scope creations and phase handshakes with `config_invalid` naming the file and pointer (for a workflow unit: file and line); an operator file that fails validation is reported with source `invalid` and never folded into the defaults. A non-object root fails before any field access.
. *Effective Configuration and Sources*: The server computes the effective configuration; neither the model nor the operator reads raw files. A team key resolves *team file → derived value (xref:09-derived-facts-and-build-timings.adoc#derived-facts[Derived Facts Store (`<PM_MCP_BASE>/projects/<project_id>/derived-facts.json`)]) → compiled default*; an operator key resolves *`local-config.json` → `machine-config.json` `project_defaults` → compiled default*; no key is resolvable from both chains. Every effective value carries its `source`: `compiled_default`, `derived`, `team`, or `operator` (with the file for `team` and `operator`, and the fact `state` for `derived`). The effective key of a value is `<file_stem>.<dotted path>` (for example `project.review.currency`, `workflow.plan.phase-2-refine.compatibility`, `local-config.merge.auto_merge`, `derived.push_remote`); workflow guards name configuration keys in this form (`depends_on_config`, link:../workflow-dsl/01-grammar.adoc#_formal_ebnf_grammar_for_the_workflow_dsl[Workflow DSL Specification]).
. *Published View*: The effective configuration is served as the read-only resource `pm://project/config` (link:../mcp-tools/03-resource-uris.adoc#_normative_resource_uri_templates[MCP Tools Specification]): `config_hash`; `entries[]` of `{key, value, source, file?, fact_state?}`; `units[]` of `{unit, file, digest, origin: default|project, default_revision, verification: verified|refused, findings[]}`; and `findings[]` (every validation finding with file, pointer or line, and reason).
. *Snapshot of In-Flight Plans (`config_hash`)*: `config_hash` is the SHA-256 over the canonical serialization of the effective configuration: every effective value with its source, the digests of the process DSL units the project loads (<<project-configuration-store>> row `*.pmwf`), the derived facts the values rest on (value and `input_digest`), the team files, the operator file, and the digest of the compiled defaults. It is never computed over raw file bytes alone, so a binary upgrade that changes a default, a changed derived fact, or an edited workflow unit changes it. The plan instance header records it in `inputs.config_hash` (xref:14-plan-instance-waivers-questions.adoc#plan-instance[Plan Instance]); a difference at a phase handshake raises `config_drift` (`adopt` / `keep`, link:../phase-workflows/02-planning-lanes-phases-3-4.adoc#_planning_transition_guards_real_world_invariants[Phase Workflows Specification, Outside-World Invariants]).

The pinned compiled defaults (for example the review rate-window values) live in the compiled default table that every effective-configuration computation starts from; a test pins that table (`PM-WATCH-STORE-13`).

[#config-project-json]
=== Team File `project.json`

[source,json]
----
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://cuioss.de/plan-marshall-mcp/schemas/config-project.json",
  "title": "ProjectConfigFile",
  "description": "Sparse team file .marshall/config/project.json: only deviations from the derived and compiled defaults.",
  "type": "object",
  "required": ["format_version"],
  "additionalProperties": false,
  "properties": {
    "format_version": { "type": "integer", "const": 1 },
    "base_branch": {
      "type": "string",
      "pattern": "^[A-Za-z0-9_./-]+$",
      "maxLength": 128,
      "description": "Integration branch of plans. Default derived from origin/HEAD (derived fact base_branch_default), fallback main. Server rule: the branch exists on the remote (base_branch_unknown)."
    },
    "branch_prefix": {
      "type": "string",
      "pattern": "^[a-z0-9][a-z0-9/_-]*/$",
      "maxLength": 64,
      "default": "feature/",
      "description": "The server names every plan branch <branch_prefix><plan_id>."
    },
    "merge_method": {
      "type": "string",
      "enum": ["squash", "merge", "rebase"],
      "description": "Override of the derived merge method (one method allowed by the repository -> that one; several -> squash). Server rule: allowed by the repository settings (merge_method_not_allowed)."
    },
    "ci_provider": {
      "type": "string",
      "enum": ["github", "gitlab"],
      "description": "Override of the CI provider derived from the remote host (derived fact ci_provider), for self-hosted remotes. Server rule: the matching host tool is enrolled."
    },
    "integrations": {
      "type": "object",
      "additionalProperties": false,
      "properties": {
        "sonar": {
          "type": "object",
          "required": ["organization", "project_key", "credential_key"],
          "additionalProperties": false,
          "properties": {
            "organization": { "type": "string", "minLength": 1, "maxLength": 255 },
            "project_key": { "type": "string", "minLength": 1, "maxLength": 400 },
            "credential_key": {
              "type": "string",
              "pattern": "^[a-z0-9][a-z0-9-]{1,62}[a-z0-9]$",
              "description": "Names the operator credential entry (for example sonar; identifiers.adoc, credential_key); the token is sent only to that entry's url origin (PM-CRED-5), never to a value of this file."
            }
          }
        }
      }
    },
    "review": {
      "type": "object",
      "additionalProperties": false,
      "properties": {
        "required_bots": {
          "type": "array",
          "items": { "$ref": "#/$defs/bot_kind" },
          "uniqueItems": true,
          "description": "Default []. Server rule: every token resolves in the review-bot registry (unregistered_kind); disjoint from optional_bots."
        },
        "optional_bots": {
          "type": "array",
          "items": { "$ref": "#/$defs/bot_kind" },
          "uniqueItems": true,
          "description": "Default []."
        },
        "bot_registry": {
          "type": "array",
          "items": { "$ref": "https://cuioss.de/plan-marshall-mcp/schemas/review-bot-registry.json" },
          "description": "Project review-bot registry records (Review-Bot Registry Record); a bot_kind that collides with a compiled record is refused."
        },
        "currency": {
          "type": "string",
          "enum": ["exact_sha", "after_last_push"],
          "default": "after_last_push",
          "description": "Strictness of the review currency test of the pre-merge barrier (phase-workflows.adoc, Predicate 2)."
        }
      }
    }
  },
  "$defs": {
    "bot_kind": { "type": "string", "pattern": "^[a-z0-9][a-z0-9-]{0,31}$" }
  }
}
----

[#config-workflow-json]
=== Team File `workflow.json`

Which finalize steps exist is decided by the project's `finalize.pmwf` unit, never by this file: `steps` only sets the lane and parameters of an optional step the unit contains, and a `steps` entry for a step the unit does not contain is the finding `config_step_not_in_unit`.

[source,json]
----
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://cuioss.de/plan-marshall-mcp/schemas/config-workflow.json",
  "title": "WorkflowConfigFile",
  "description": "Sparse team file .marshall/config/workflow.json.",
  "type": "object",
  "required": ["format_version"],
  "additionalProperties": false,
  "properties": {
    "format_version": { "type": "integer", "const": 1 },
    "plan": {
      "type": "object",
      "additionalProperties": false,
      "properties": {
        "phase-1-init": {
          "type": "object",
          "additionalProperties": false,
          "properties": {
            "minimum_lane": {
              "type": "string",
              "enum": ["light", "deep"],
              "default": "light",
              "description": "deep: every plan runs the deep lane. light: the initial router decides and the light -> deep ratchet always applies. A forced light lane does not exist."
            }
          }
        },
        "phase-2-refine": {
          "type": "object",
          "additionalProperties": false,
          "properties": {
            "compatibility": { "type": "string", "enum": ["breaking", "deprecation", "smart_and_ask"], "default": "breaking" },
            "simplicity": { "type": "string", "enum": ["lean", "pragmatic", "defensive"], "default": "lean" }
          }
        },
        "phase-5-execute": {
          "type": "object",
          "additionalProperties": false,
          "properties": {
            "per_deliverable_verbs": {
              "type": "array",
              "minItems": 1,
              "uniqueItems": true,
              "items": { "$ref": "#/$defs/build_verb" },
              "description": "Default [\"compile\", \"module-tests\"]. Server rule: each verb renderable by the project's effective canonical template."
            },
            "final_verification": {
              "type": "array",
              "uniqueItems": true,
              "items": { "$ref": "#/$defs/step_id" },
              "description": "End-of-phase-5 verification steps; default derived from the build systems' verbs. Server rule: each id a shipped verification step or an enrolled project step."
            }
          }
        },
        "phase-6-finalize": {
          "type": "object",
          "additionalProperties": false,
          "properties": {
            "steps": {
              "type": "object",
              "propertyNames": { "$ref": "#/$defs/step_id" },
              "additionalProperties": {
                "type": "object",
                "additionalProperties": false,
                "properties": {
                  "lane": {
                    "type": "string",
                    "enum": ["off", "minimal", "standard", "full"],
                    "description": "Lowest execution posture at which the optional step runs, or off. Server rule: only optional steps; a mandatory step is refused (mandatory_step_not_configurable)."
                  },
                  "params": {
                    "type": "object",
                    "description": "Step parameters, validated by the server against the closed parameter schema of the step descriptor (FinalizeStepDescriptor.configurable)."
                  }
                }
              }
            },
            "project_steps": {
              "type": "object",
              "propertyNames": { "pattern": "^project:[a-z][a-z0-9-]{0,63}$" },
              "additionalProperties": {
                "type": "object",
                "required": ["order", "project_script_id"],
                "additionalProperties": false,
                "properties": {
                  "order": { "type": "integer", "minimum": 1, "maximum": 1099, "description": "Band position; validated by FinalizePipelineValidator with the rest of the roster." },
                  "lane": { "type": "string", "enum": ["off", "minimal", "standard", "full"] },
                  "project_script_id": {
                    "type": "string",
                    "pattern": "^[a-z][a-z0-9-]{0,63}$",
                    "description": "Server rule: enrolled with binding worker_kind finalize_step whose target is this step id; the step exists only when the unit, this descriptor, and the enrolment agree."
                  }
                }
              }
            }
          }
        }
      }
    }
  },
  "$defs": {
    "step_id": { "type": "string", "pattern": "^[a-z][a-z0-9-]{0,31}:[a-z][a-z0-9-]{0,63}$" },
    "build_verb": {
      "type": "string",
      "enum": ["clean", "compile", "test-compile", "module-tests", "integration-tests", "e2e", "coverage", "benchmark", "quality-gate", "arch-gate", "verify", "install", "clean-install", "package"]
    }
  }
}
----
