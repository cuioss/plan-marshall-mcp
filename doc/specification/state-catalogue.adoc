== Overview

This document is the central catalogue of every workflow state of *plan-marshall-mcp* (`PM-MCP`). Every state identifier used anywhere in the requirements, the specifications, the roadmap, or the implementation watch is defined here exactly once, in one row of one table, with its phase value, its kind, where it is entered from, what it offers, where it exits to, and the section that specifies its behaviour. Other documents describe behaviour; they name a state only by its identifier and link to its row here (anchor `state-<state id>`, xref:state-catalogue/01-conventions-generic-conditions.adoc#_state_identifier_grammar[State Identifier Grammar]).

The catalogue is normatively equal to the state table that the diagram generator produces from the workflow definitions (`renderAsciiDocTables`, link:workflow-dsl/07-loop-back-diagrams-verification.adoc#_automated_mermaid_asciidoc_table_and_ascii_diagram_generation[Workflow DSL Specification, Diagram Generation], `PM-IMPL-5`). Once the `*.pmwf` definitions exist, a build test (`StateCatalogueDriftTest`) compares the generated columns (state identifier, phase value, kind, entered from, offered links and outcomes, exits to) with this catalogue and fails the build when they differ, beside the `WorkflowDiagramDriftTest` (link:workflow-dsl/07-loop-back-diagrams-verification.adoc#_build_time_drift_gate[Workflow DSL Specification, Build-Time Drift Gate]). The *Defined in* column is maintained by hand; the same test verifies that every link in it resolves. Until the definitions exist, this catalogue is the reference the definitions are written against: a state that is not in the catalogue does not exist, and a new state is added here before any other document uses it.

*Default units*: The phase and sub-workflow units are project-owned: a project runs its own copies in `.marshall/config/*.pmwf` (link:workflow-dsl/04-ast-node-model.adoc#project-owned-units[Workflow DSL Specification, Project-Owned Workflow Units & Compiled Invariants]). This catalogue documents the *default* units the binary ships, and `StateCatalogueDriftTest` compares it with the default units only. A project unit may differ within the compiled invariants (for example by omitting an optional finalize step or adding a project step's state); its states are published with the project's effective configuration (`pm://project/config`), never added to this catalogue.

No state waits for an operator decision: every blocking situation has a bounded self-remedy (a remediation unit or a condition's self-remedy links) and a defined fallback to the plan outcomes `handed_back` or `returned`; the operator influences a running plan only through waivers and the operator verbs (link:state-catalogue/01-conventions-generic-conditions.adoc#exits-and-fallbacks[Exits, Step-Outs & Fallbacks]). Every row is fully specified; a behaviour without a specification is not catalogued.
