== Overview

Improvements deliberately deferred: the first iteration accepts a known limitation, and the improvement is planned but not scheduled in a milestone of the link:roadmap.adoc[Roadmap]. Each entry names why it is deferred, the accepted limitation, and the improvement. An entry moves into a milestone when it is scheduled; it is removed here in the same change.

Status legend as in the link:roadmap.adoc#_status_legend[Roadmap].

== Operator Channel

=== L-1: Operator Proof Beyond the CLI Checks

_Deferred because:_ the CLI checks keep an honest model out; a proof against a model that deliberately defeats them needs a user secret or OS user presence, which the first iteration does not ask for.

_Accepted limitation:_ An operator verb is accepted when the operator CLI `pm-operator` passes its local checks (terminal attached, no agent environment markers, host deny rules as defence in depth). A model shell that deliberately defeats these checks (pseudo-terminal, cleared environment, indirect invocation) can run operator verbs, including waivers, aborts and credential changes. Because the daemon cannot verify the checks of `pm-operator`, any same-user process that holds the runtime token can call the operator endpoints of the API directly (for example `curl --unix-socket`).

* [ ] Require a user proof the model cannot produce: an operator passphrase (PBKDF2-HMAC-SHA256 hash in `<PM_MCP_BASE>/state/operator.json`) exchanged for an operator session with idle and absolute limits, presented as `Authorization: Bearer` on operator verbs
* [ ] Offer OS user presence as an alternative way to obtain the operator session (macOS LocalAuthentication/Touch ID, Linux polkit)
* [ ] Device roles for the web adapter (`viewer` default, `operator` only by explicit pairing) and step-up with the operator session before operator actions from a browser; until then every paired device has operator rights

== Web Adapter

=== L-2: OAuth for the Web Adapter

_Deferred because:_ the web access serves one operator on their own devices; an identity provider pays off only for several users.

_Accepted limitation:_ Browsers authenticate with per-device bearer secrets obtained through one-time-code pairing by the operator CLI (`pm-operator web pair`); no identity provider, no token rotation.

* [ ] Validate OAuth access tokens with Token-Sheriff behind the web adapter's authentication seam, coexisting with device tokens during migration (routing by token shape)
* [ ] Define and integrate the role of API-Sheriff
* [ ] Authorization Code + PKCE in the web app with the access token kept in memory; evaluate BFF or token-mediating backend per RFC 10017 (BCP 212)
* [ ] Token rotation and absolute expiry for device tokens until OAuth replaces them
* [ ] Sender-constrained tokens: non-extractable WebCrypto key in IndexedDB and signed requests (DPoP), so script injection can use but not steal the credential
* [ ] A local certificate authority (mkcert-style, installed on paired devices) for the LAN listener, removing the self-signed certificate warning

== Git and Providers

=== L-3: Native Support for Repository Features Now Served by the CLI Variant

_Deferred because:_ the CLI variant serves these repositories, and each native feature needs its own library support and verification.

_Accepted limitation:_ Repositories that need hooks, commit signing, filters including LFS, submodules, or SHA-256, partial or sparse repositories are refused by the native variant with `capability_missing` and must use the CLI variant.

* [ ] Native commit signing with an agent-owned key once a provider attributes the key to the agent identity
* [ ] Native execution of repository hooks and filter drivers through confined jobs
* [ ] Native LFS, submodules, and SHA-256 / partial / sparse repositories where the library supports them

== Workflow Composition

=== L-5: Team Overrides of Templates and Composition Rules

_Deferred because:_ the phase units and the sub-workflow units `git-commit-and-push.pmwf`, the remediation policy units, `replan.pmwf`, and `question-adjudicate.pmwf` are project-owned copies already; overriding the composition rules and the compiled-only units needs a validation against the compiled invariants first.

_Accepted limitation:_ Plan instances are composed from the project-owned units (`.marshall/config/*.pmwf`, copied from the defaults) and the shipped default composition rule file only. Teams cannot override or add composition rules, and cannot override the units that stay compiled only (the workspace unit `project-setup.pmwf` with the lesson maintenance unit `lessons.pmwf`, the epic unit `epic.pmwf`, the entity units with the task envelope, the task protocol unit `worker-task.pmwf`, and the plan and epic bootstraps with their source units `source-*.pmwf`; link:specification/workflow-dsl/04-ast-node-model.adoc#project-owned-units[Workflow DSL Specification, Project-Owned Workflow Units]).

* [ ] Team-authored composition rules (for example lane or posture prunes) in the project-owned configuration
* [ ] Team overrides of the compiled-only units where a team need is shown
* [ ] Composition rules validated against the compiled invariants on load, so no team rule can remove a mandatory step, a non-waivable guard or the operator boundary
* [ ] Provenance of every team override in the plan instance header and diagram

== Plan Bootstrap

=== L-6: Issue and Pull-Request Candidates in the Plan Bootstrap

_Deferred because:_ listing remote candidates costs provider calls and screening on every bootstrap, while a named number serves the same purpose.

_Accepted limitation:_ The bootstrap's choice state lists only local candidates (live plans or epics, active unclaimed lessons, recipes, local changes, launched epic rows). Issues and pull requests are not listed; the user names a number, which the bootstrap's `issue` or `pr` source then fetches.

* [ ] List open issues and pull requests through the provider module as bootstrap candidates, within the provider's rate limits and with the same model-facing bound as the local listings
* [ ] Screen the listed titles through the guard for external text before they reach the model

== Security

=== L-7: Local Prompt-Injection Classifier

_Deferred because:_ no local classifier runtime works under GraalVM native image at an acceptable size.

_Accepted limitation:_ The deterministic level-1 validator recognizes injection only by its own rule table; semantic injection is judged by the level-2 screener, a model job that costs a harness run and is available only on a harness that can run without tools. Local classifier runtimes (ONNX Runtime, DJL) lack GraalVM native-image support and need models of 100–700 MB.

* [ ] Evaluate a local prompt-injection classifier as an additional risk signal of level 1 once a runtime works under native image at an acceptable size
* [ ] Measure it against the same attack corpora as the validator and the screener before it influences any delivery

== Network

=== L-8: Authenticated Proxies

_Deferred because:_ proxy credentials need a place in the credential store and a redaction path, which no current deployment needs.

_Accepted limitation:_ Outbound connections (`cui-http` and the git transport of the native variant) use only an unauthenticated HTTPS proxy, set by the operator in the `proxy` object of `machine-config.json` (`https_proxy` as a URL without embedded credentials, `no_proxy`). A proxy that requires authentication is not supported.

* [ ] Proxy credentials through the credential store, never in `machine-config.json`

== Host Bundles

=== L-9: Plain Entry Command Names

_Deferred because:_ the `plan-marshall` plugin owns the plain names and may be installed side by side.

_Accepted limitation:_ The entry commands are `/mcp-plan-marshall`, `/mcp-plan-orchestrator` and `/mcp-marshall-steward` (`$mcp-…` skills on Codex) while the `plan-marshall` plugin, which owns the plain names, may be installed side by side. The prefix keeps the two command sets apart and lets the three commands complete together in the harness.

* [ ] Rename the entry commands to `/plan-marshall`, `/plan-orchestrator` and `/marshall-steward` once the `plan-marshall` plugin is withdrawn
* [ ] Have the bundle update remove the prefixed artifacts in the same install that places the plain ones
