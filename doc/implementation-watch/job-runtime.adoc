== Overview

Watch items for the link:../specification/job-runtime.adoc[Job Runtime Specification]: job outcome derivation, git
and CI subprocesses, bounded waits, build output parsers and timeout verdicts. The sections mirror the
specification. Item format and lifecycle: link:../ImplementationWatch.adoc[Implementation Watch].

== Verify-Not-Resolve Execution Pipeline

[#PM-WATCH-JOB-1]
=== PM-WATCH-JOB-1: Job outcomes are derived at the boundary

Anchor:: link:../specification/job-runtime.adoc#_verify_not_resolve_execution_pipeline[Job Runtime § Verify-Not-Resolve Execution Pipeline],
link:../specification/domain-extensions.adoc#_standard_output_payload_stdout[Domain Extensions § Standard Output Payload],
link:../Requirements.adoc#PM-EXEC-4[PM-EXEC-4]
Hazard:: Two vocabularies (`indeterminate` in the wrapper, `unknown` at the boundary) named one state, and a wrapper
could claim a status the boundary never derived.
Guard:: The runtime derives job outcomes itself; a `project_script` output `status` is validated against the
observed exit and parse evidence and never adopted blindly.
Source:: truthful-signals PLAN-TRUTH-155 D5.

== Subprocess Lifecycle & Process-Group Isolation

[#PM-WATCH-JOB-2]
=== PM-WATCH-JOB-2: Test and production git seams share one environment policy

Anchor:: link:../specification/job-runtime.adoc#_process_group_creation_via_the_job_exec_shim[Job Runtime § Process-Group Creation via the `job-exec` Shim],
link:../Requirements.adoc#PM-SEC-5[PM-SEC-5], link:../Requirements.adoc#PM-EXEC-5[PM-EXEC-5]
Hazard:: The test fixture scrubbed environment-injected git configuration, but about 20 production scripts did not.
Guard:: The runtime clears the child environment and applies the allowlist while keeping file-based developer git
configuration; a test launches the runtime with `GIT_DIR`, `GIT_WORK_TREE`, `GIT_CONFIG_COUNT`,
`GIT_CONFIG_KEY_0` and `GIT_CONFIG_VALUE_0` set and asserts that no git job sees them, exercising the production
seam, not a test-only scrub.
Fixture:: CodeRabbit finding `5ed953` (PR #1585).
Source:: orchestrator-refactor epic Open Defect (PLAN-08).

[#PM-WATCH-JOB-3]
=== PM-WATCH-JOB-3: A git timeout is not a refusal

Anchor:: link:../specification/job-runtime.adoc#_process_termination_cancellation_protocol[Job Runtime § Process Termination & Cancellation Protocol],
link:../Requirements.adoc#PM-EXEC-4[PM-EXEC-4]
Hazard:: A git timeout was treated like a refusal and answered with `--force`; a timed-out worktree removal could
leave a partially deleted tree.
Guard:: `timed_out` git jobs never trigger `--force`; a timed-out `worktree remove` is re-checked for partial
deletion before a retry; git timeouts adapt for large checkouts.
Fixture:: the 60 s budget fired twice on one plan.
Source:: code-intelligence-substrate PLAN-CIS-052 fold-N6.

[#PM-WATCH-JOB-4]
=== PM-WATCH-JOB-4: A worktree is never removed from inside itself

Anchor:: link:../specification/filesystem-layout.adoc#_plan_directory_relocation_sequence[Filesystem Layout § Plan Directory Relocation Sequence],
link:../Requirements.adoc#PM-ARCH-5[PM-ARCH-5]
Hazard:: A forked finalize agent inherited the worktree as its working directory and could not finish
branch-cleanup.
Guard:: The branch-cleanup job spec runs `git worktree remove` with the main checkout as working directory; a test
asserts it, and a relay or host started inside the worktree does not affect it (jobs never inherit the host's
working directory).
Fixture:: forked finalize agent with its working directory inside `.plan/local/worktrees/<plan_id>/` (lesson
`2026-09-20-08-010`).
Source:: process-compliance PLAN-13 D3.

[#PM-WATCH-JOB-5]
=== PM-WATCH-JOB-5: Bounded waits are wall-clock and say what happened

Anchor:: link:../specification/job-runtime.adoc#_bounded_long_poll_progress_reset_waiting_primitives_pm_wf_8_pm_impl_4[Job Runtime § Bounded Long-Poll & Progress-Reset Waiting Primitives],
link:../Requirements.adoc#PM-IMPL-4[PM-IMPL-4]
Hazard:: A wait budget passed as an iteration count expired in seconds and reported a bot "absent" while it was
running; a wait at its ceiling could not tell waiting from re-polling finished work; wait cost was invisible.
Guard:: Wait jobs use monotonic wall-clock deadlines (test with fast pollers); an exhausted poll is `unproven`, not
absent; a bounded wait returning `running` reports whether the job state changed during the window; a wait on an
already-settled job returns immediately. The wait population below is the baseline for bounded-wait metrics.
Fixture:: 600 s budget burned in seconds ("CodeRabbit absent" while running); 2,051 wait calls, 14,423,580 ms:
build_server 27.4%, ci 27.3%, ci_complete_precondition 23.1% (77.8% together).
Source:: review-apparatus PLAN-PR-048 D2; lessons-routing lesson 2026-09-23-05-003; post-run-quality PLAN-PRQ-11 D0.

[#PM-WATCH-JOB-6]
=== PM-WATCH-JOB-6: A verdict is bound to its job identity

Anchor:: link:../specification/job-runtime.adoc#_bounded_long_poll_progress_reset_waiting_primitives_pm_wf_8_pm_impl_4[Job Runtime § Bounded Long-Poll & Progress-Reset Waiting Primitives],
link:../Requirements.adoc#PM-TOOL-2[PM-TOOL-2]
Hazard:: Re-attaching to a build wait returned a previous job's verdict.
Guard:: Every wait and `pm_build` result carries the job id and the `worktree_sha` it was computed for; a test
re-attaches after a runtime restart and after a second job for the same command started.
Source:: truthful-signals PLAN-TRUTH-150 D1.

[#PM-WATCH-JOB-7]
=== PM-WATCH-JOB-7: A silent non-zero exit is its own outcome

== Adaptive Build Timeouts, Coverage Parsers & Gate Honesty

[#PM-WATCH-JOB-15]
=== PM-WATCH-JOB-15: A timeout over a passing build is no verdict

Anchor:: link:../specification/job-runtime.adoc#_adaptive_timeout_learning[Job Runtime § Adaptive Timeout Learning],
link:../Requirements.adoc#PM-EXEC-6[PM-EXEC-6]
Hazard:: Timeouts were read as failures.
Guard:: Matched tests: a failing build stays `failed`; a timeout over a build that would pass yields no verdict; an
unlearned budget is visible as `budget_derivation: floor_default` and its timeout offers `retry` with the escalated
budget instead of failing the gate.
Fixture:: job `dbbc60f9` (an integration test that normally takes 1250–1800 s timed out at 300 s, then at 750 s).
Source:: truthful-signals PLAN-TRUTH-169 D3, D4.

[#PM-WATCH-JOB-16]
=== PM-WATCH-JOB-16: A timed-out or residue-poisoned run never inflates the learned budget

Anchor:: link:../specification/job-runtime.adoc#_adaptive_timeout_learning[Job Runtime § Adaptive Timeout Learning],
link:../Requirements.adoc#PM-EXEC-6[PM-EXEC-6]
Hazard:: A module test timed out on a worktree full of build residue; blending the timeout into the learned value
re-tiered every later run of the command.
Guard:: Scenario test: a timed-out run leaves `L` unchanged and sets a one-shot escalation budget that the next
finished run clears; a run started over residue above the threshold is stored `poisoned` and not blended while clean
observations exist; the job facts show `observations`, `poisoned`, `escalated`, `imported`.
Fixture:: module-tests timed out at 873 s on 52,704 residue files (450 MB), green in 529 s after cleanup;
quality-gate 968 s and module-tests 1473 s re-tiered against 360 s and 501 s earlier.
Source:: truthful-signals PLAN-TRUTH-150 F-0913.

[#PM-WATCH-JOB-17]
=== PM-WATCH-JOB-17: A red baseline never fails the plan

Anchor:: link:../specification/job-runtime.adoc#_gate_honesty_verification[Job Runtime § Gate Honesty Verification] (Baseline Separation),

Hazard:: A whole-tree gate red on the unmodified base branch blocked every finalize, and standing coverage debt in a

Guard:: Fixture repository whose base already fails the whole-tree gate while the plan's diff is clean: the outcome

Fixture:: whole-tree gate red on a pristine `origin/main` scratch worktree (3×), per-bundle gates green, CI green;
Token-Sheriff #744 (JaCoCo 0.70 / 0.57 against 0.80) fanning out into 5 findings.
Source:: process-compliance inbox `truth-179-opencode-target-detection-landed-005`; truthful-signals
