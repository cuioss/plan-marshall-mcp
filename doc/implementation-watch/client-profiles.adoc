== Normative Client Profile JSON Schema

[#PM-WATCH-CLIENT-8]
=== PM-WATCH-CLIENT-8: A writable harness path never covers a managed settings or hook file

Anchor:: link:../specification/client-profiles/01-profile-schema.adoc#_normative_client_profile_json_schema[Client Profiles § Normative Client Profile JSON Schema] (Writable paths)
Hazard:: A `headless.writable_paths` entry that names a harness home as a whole, or a directory holding the settings
or hook file the bundle installed, puts that file into the Landlock write set of every model job: a job rewrites the
host's deny rules or hooks, and the operator's next session runs without them.
Guard:: Profile validation refuses a `headless.writable_paths` entry that equals, contains, or lies under a settings,
hook, command, or MCP registration file the client's bundle manifest manages; a build-time test runs the rule over
every shipped profile against its own bundle manifest; negative fixture: a profile with the entry `~/.claude` and one
with the path of the managed settings file are each refused naming the entry and the managed file; runtime control:
a model job's write to the managed settings file fails.
Source:: design review.

== Three-Tier Environment Detection Matrix & Mismatch Auditing

[#PM-WATCH-CLIENT-4]
=== PM-WATCH-CLIENT-4: Consumers of the session-start hook stay independent

Anchor:: link:../specification/client-profiles/02-placeholders-and-detection.adoc#host-integration-table[Client Profiles § Host Integration Table],
link:../specification/client-profiles/02-placeholders-and-detection.adoc#session-lifecycle-hook[Client Profiles § Session Lifecycle Hook & Scope Pointer],
link:../Requirements.adoc#PM-DIST-1[PM-DIST-1], link:../Requirements.adoc#PM-DIST-4[PM-DIST-4], link:../Requirements.adoc#PM-CLIENT-6[PM-CLIENT-6]
Hazard:: In plan-marshall, title rendering and session-id capture shared the session-start hook, so adding a payload
risked altering them. In PM-MCP the same seam carries the bundle-drift check and the scope pointer.
Guard:: A test runs the hook with every combination (drift none/`bundle_outdated`/`bundle_modified` × scope
live/none/unreadable), with the runtime not running, and asserts that each consumer's output is independent and
stable, that the pointer never suppresses the drift notice, that the exit code is `0`, and that no runtime was
started (no `runtime.json`, no socket afterwards) and no file was written.
Source:: plan-marshall defect instrumentation-substrate PLAN-06 § Claim Labels (REFUTED: the seam's consumer is not only the terminal title).

== Embedded Client Bundle `bundle-manifest.json` Schema

[#PM-WATCH-CLIENT-5]
=== PM-WATCH-CLIENT-5: Host-side enforcers are scope-bound; only server gates travel with every session

Anchor:: link:../specification/client-profiles/03-bundle-manifest.adoc#_embedded_client_bundle_bundle_manifest_json_schema[Client Profiles § Embedded Client Bundle `bundle-manifest.json` Schema],
link:../Requirements.adoc#PM-DIST-2[PM-DIST-2], link:../Requirements.adoc#PM-ARCH-1[PM-ARCH-1]
Hazard:: plan-marshall's hooks lived only in git-ignored machine-local configuration, so fresh clones and cloud
sessions ran with zero mechanical enforcement while documents claimed the rules were enforced.
Guard:: Server gates are the only enforcement claimed as universal. Every host-side enforcer (`permission_rule` and
`hook_entry` elements) is declared in a scope section of the bundle manifest and recorded with its scope in
`install-records.json`; `pm-operator client status` reports which enforcers are installed and in which scope; documents
never call a host-side enforcer universal.
Fixture:: plan-marshall's checked-in `.claude/settings.json` has no `hooks` key; all 6 hook events live in the
git-ignored `settings.local.json`.
Source:: plan-marshall defect instrumentation-substrate PLAN-08 deliverable 4 and § Claim Labels (hook surface machine-local only).

[#PM-WATCH-CLIENT-6]
=== PM-WATCH-CLIENT-6: Every artifact an emitted instruction references is emitted too

Anchor:: link:../specification/client-profiles/02-placeholders-and-detection.adoc#_rendering_invariants[Client Profiles § Rendering Invariants],
link:../Requirements.adoc#PM-SKILL-2[PM-SKILL-2], link:../Requirements.adoc#PM-CLIENT-2[PM-CLIENT-2]
Hazard:: A target emitter shipped a routing table whose referenced documents were not part of that target's unit.
Guard:: Build-time test: for every client profile and representative enabled-domain set, every `skill://pm/...` URI
referenced from a rendered skill, auxiliary file or state representation resolves through `pm_skill` or
`pm_skill_file` for that client and domain set; every installed bundle file referenced by another bundle file is in
the same `bundle-manifest.json`.
Fixture:: an opencode unit whose routing table referenced 8 `workflow/` documents that were not emitted (also
`phase-5-execute`).
Source:: plan-marshall defect process-compliance inbox module-budget-campaign-completion-008.

[#PM-WATCH-CLIENT-7]
=== PM-WATCH-CLIENT-7: A permission wildcard ends the rule

Anchor:: link:../specification/client-profiles/03-bundle-manifest.adoc#_ownership_digest_verification_on_installupdateremove[Client Profiles § Ownership & Digest Verification on Install/Update/Remove],
link:../Requirements.adoc#PM-DIST-1[PM-DIST-1]
Hazard:: A mid-rule `*` crossed an argument boundary and pre-approved inserted options.
Guard:: The bundle-manifest validator rejects any rendered permission rule (every `permission_rule` element of every
scope section) whose `*` is neither terminal nor `:*`;
malformed grammar is counted apart from dangerous targets, and the check reports the rules scanned and files
resolved.
Fixture:: `Bash(cp -r .plan/project-architecture/* /tmp/arch-snap)` and its fixed form
`Bash(cp -r .plan/project-architecture /tmp/arch-snap)`.
Source:: plan-marshall defect truthful-signals PLAN-TRUTH-165 D1.

[#PM-WATCH-CLIENT-9]
=== PM-WATCH-CLIENT-9: Bundle artifacts carry the `mcp-` command names and never a `plan-marshall` name

Anchor:: link:../specification/client-profiles/03-bundle-manifest.adoc#_ownership_digest_verification_on_installupdateremove[Client Profiles § Ownership & Digest Verification on Install/Update/Remove] (Side-by-Side with Legacy `plan-marshall`),
link:../Requirements.adoc#PM-CLIENT-1[PM-CLIENT-1]
Hazard:: A command or skill file whose name differs from the entry command the profile renders leaves
`{{command:*}}` pointing at a command the host does not have; a bundle file named `plan-marshall`,
`plan-orchestrator`, or `marshall-steward` shadows or is shadowed by the `plan-marshall` plugin's command in a mixed
installation, so the user's entry runs the other system.
Guard:: Bundle manifest test per client: every entry in `commands.entries` of the profile has exactly one command
or skill file in the manifest whose `target_name`, without its extension, is the command name without its sigil (`mcp-plan-marshall`,
`mcp-plan-orchestrator`, `mcp-marshall-steward`), and no `target_name` of any scope equals a `plan-marshall` command name
(`plan-marshall`, `plan-orchestrator`, `marshall-steward`, with or without extension); control: a fixture manifest
with an unprefixed command file fails the build.
Source:: design review.
