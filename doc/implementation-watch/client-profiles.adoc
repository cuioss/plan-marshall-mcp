[#PM-WATCH-CLIENT-1]
=== PM-WATCH-CLIENT-1: Format-accuracy evidence is secondhand

Anchor:: link:../specification/client-profiles.adoc#_rendering_invariants[Client Profiles § Rendering Invariants],
link:../specification/client-profiles.adoc#calibration-decision[Client Profiles § Calibration Decision],
link:../Requirements.adoc#PM-TOOL-5[PM-TOOL-5], link:../Requirements.adoc#PM-IMPL-2[PM-IMPL-2],

Hazard:: The TOON wire form is a settled design decision, but its parse fidelity per client runtime is unmeasured;
the only format-accuracy figures in circulation are secondhand (an up-to-40% drop from generic Markdown, a
model-specific optimal format, parsing accuracy YAML 51.9% / JSON 43.1% / XML 33.8%). A runtime that parses TOON
poorly degrades silently.
Guard:: Keep the decision. Before revisiting TOON or the Calibration Decision, read the primary source (Ouyang et al.
2026, _SkCC_, arXiv 2605.03353) and record what it measured; never cite the figures in a specification before
that. The `PM-TEST-6` baseline of every client includes a TOON representation-parsing scenario (the model extracts
`links` and `facts` from a `pm_state` result), link:../specification/workflow-dsl.adoc#behavioural-conformance-harness[Workflow DSL § Behavioural Conformance Harness].
Fixture:: the figures above, marked unverified.

== Three-Tier Environment Detection Matrix & Mismatch Auditing

[#PM-WATCH-CLIENT-4]
=== PM-WATCH-CLIENT-4: Consumers of the session-start hook stay independent

Anchor:: link:../specification/client-profiles.adoc#host-integration-table[Client Profiles § Host Integration Table],
link:../specification/client-profiles.adoc#session-lifecycle-hook[Client Profiles § Session Lifecycle Hook & Scope Pointer],
link:../Requirements.adoc#PM-DIST-1[PM-DIST-1], link:../Requirements.adoc#PM-DIST-4[PM-DIST-4], link:../Requirements.adoc#PM-CLIENT-6[PM-CLIENT-6]
Hazard:: In plan-marshall, title rendering and session-id capture shared the session-start hook, so adding a payload
risked altering them. In PM-MCP the same seam carries the bundle-drift check and the scope pointer.
Guard:: A test runs the hook with every combination (drift yes/no × scope live/none/unreadable) and asserts that each
consumer's output is independent and stable; the pointer never suppresses the drift notice.
Source:: instrumentation-substrate PLAN-06 06.C1.

== Embedded Client Bundle `bundle-manifest.json` Schema

[#PM-WATCH-CLIENT-5]
=== PM-WATCH-CLIENT-5: Host-side enforcers are scope-bound; only server gates travel with every session

Anchor:: link:../specification/client-profiles.adoc#_embedded_client_bundle_bundle_manifest_json_schema[Client Profiles § Embedded Client Bundle `bundle-manifest.json` Schema],
link:../Requirements.adoc#PM-DIST-2[PM-DIST-2], link:../Requirements.adoc#PM-ARCH-1[PM-ARCH-1]
Hazard:: plan-marshall's hooks lived only in git-ignored machine-local configuration, so fresh clones and cloud
sessions ran with zero mechanical enforcement while documents claimed the rules were enforced.
Guard:: Server gates are the only enforcement claimed as universal. Every host-side enforcer (deny rules, hooks)
records its install scope in the bundle manifest; `pm-mcp client status` reports which enforcers are installed and
in which scope; documents never call a host-side enforcer universal.
Fixture:: plan-marshall's checked-in `.claude/settings.json` has no `hooks` key; all 6 hook events live in the
git-ignored `settings.local.json`.
Source:: instrumentation-substrate PLAN-08 08.D4 and 08.C-portability.

[#PM-WATCH-CLIENT-6]
=== PM-WATCH-CLIENT-6: Every artifact an emitted instruction references is emitted too

Anchor:: link:../specification/client-profiles.adoc#_rendering_invariants[Client Profiles § Rendering Invariants],
link:../Requirements.adoc#PM-SKILL-2[PM-SKILL-2], link:../Requirements.adoc#PM-CLIENT-2[PM-CLIENT-2]
Hazard:: A target emitter shipped a routing table whose referenced documents were not part of that target's unit.
Guard:: Build-time test: for every client profile and representative enabled-domain set, every `skill://pm/...` URI
referenced from a rendered skill, auxiliary file or state representation resolves through `pm_skill` or
`pm_skill_file` for that client and domain set; every installed bundle file referenced by another bundle file is in
the same `bundle-manifest.json`.
Fixture:: an opencode unit whose routing table referenced 8 `workflow/` documents that were not emitted (also
`phase-5-execute`).
Source:: process-compliance inbox module-budget-campaign-completion-008.

=== PM-WATCH-CLIENT-7: A permission wildcard ends the rule

Hazard:: A mid-rule `*` crossed an argument boundary and pre-approved inserted options.
