== Token-Lane Credential Architecture & OS Keyring Integration

[#PM-WATCH-CLI-2]
=== PM-WATCH-CLI-2: Repository identity is the remote, never the checkout path

Anchor:: link:../specification/cli-and-security.adoc#_token_lane_credential_architecture_os_keyring_integration[CLI & Security § Token-Lane Credential Architecture],
link:../Requirements.adoc#PM-SEC-2[PM-SEC-2], link:../Requirements.adoc#PM-CRED-1[PM-CRED-1]
Hazard:: A foreign repository was identified by its checkout path. A renamed repository kept working for git and REST
reads through the provider's redirect, but the App installation-token mint did not follow the rename, so
credential lookups broke silently.
Guard:: Cross-project grants and CI queries identify the target by remote owner/name; a checkout path is only a
location. Because the credential project key derives from the remote URL's last segment, a rename changes the
key: `pm-mcp status` and `enter` detect a remote-name change and report the credential key mismatch instead of
silently missing credentials. A rename is probed before it is declared safe.
Fixture:: `pr-agent-settings` → `cuioss-review-bot` (cuioss-organization 0.30.0, plan-marshall #1603).
Source:: lessons-routing lessons 2026-09-24-12-001 and 2026-09-24-12-007.

== Operator Channel Isolation & Privileged CLI (`pm-mcp operator`)

[#PM-WATCH-CLI-3]
=== PM-WATCH-CLI-3: Every documented operator command form is executed as a test

Anchor:: link:../specification/cli-and-security.adoc#_operator_channel_isolation_privileged_cli_pm_mcp_operator[CLI & Security § Operator Channel Isolation & Privileged CLI],
link:../Requirements.adoc#PM-TEST-3[PM-TEST-3]
Hazard:: A documented invocation form (`--measured-diff-size ""`) was rejected at the barrier; five gate failures
followed.
Guard:: Every `pm-mcp operator …` example in documentation and skills runs in an integration test.
Source:: review-apparatus PLAN-PR-051 D3/D1a.

[#PM-WATCH-CLI-4]
=== PM-WATCH-CLI-4: The upstream filing credential is proven before any filing job exists

Anchor:: link:../specification/store-schemas.adoc#lesson-record[Store Schemas § Lesson Record] (Upstream Release),
link:../Requirements.adoc#PM-ARCH-2[PM-ARCH-2], link:../Requirements.adoc#PM-CRED-5[PM-CRED-5]
Hazard:: An upstream route was built before anyone proved that a consumer's credential can write to the vendor
tracker.
Guard:: Before the operator-confirmed filing job is implemented, a probe verifies write permission on the target
tracker with the enrolled credential; without it the release action only renders the issue body for the operator to
file (the other fallbacks: a flushed outbox, an operator-provisioned per-repository token).
Source:: lessons-routing PLAN-LR-03 D0.
