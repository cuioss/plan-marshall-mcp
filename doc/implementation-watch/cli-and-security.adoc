== Command-Line Binaries (`pm-mcp`, `pm-operator`) & Installation Layout

[#PM-WATCH-CLI-10]
=== PM-WATCH-CLI-10: Siblings are started by path, never through PATH

Anchor:: link:../specification/cli-and-security/01-cli-and-installer.adoc#installation-layout[CLI & Security § Installation Layout],
link:../Requirements.adoc#PM-DIST-1[PM-DIST-1]
Hazard:: A binary looked up through `PATH` lets any same-named executable earlier on `PATH` run as the runtime, and a
`PM_MCP_HOME` derived from an unresolved symlink points at the user bin directory instead of the installation.
Guard:: Fixture with a `pm-mcpd` and a `pm-exec` earlier on `PATH` that each write a sentinel: neither is ever
started, by `pm-mcp`, by `pm-operator`, or by the runtime, and the started processes are the ones in
`<PM_MCP_HOME>/bin/`; `pm-mcp` and `pm-operator`, each reached through a symlink in a user bin directory (and through
a chain of two symlinks), resolve `PM_MCP_HOME` to the installation directory.
Source:: design review.

[#PM-WATCH-CLI-11]
=== PM-WATCH-CLI-11: An upgrade never mixes releases

Anchor:: link:../specification/cli-and-security/01-cli-and-installer.adoc#installation-layout[CLI & Security § Installation Layout] (Upgrade),
link:../specification/cli-and-security/01-cli-and-installer.adoc#cli-daemon-access[CLI & Security § Runtime Access & On-Demand Start] (Version),
link:../Requirements.adoc#PM-DIST-4[PM-DIST-4]
Hazard:: After the symlink switch the new `pm-operator` installed its bundles against the old runtime, or the old installation
directory was removed while the old runtime still started jobs through its own `pm-exec`.
Guard:: Fixture with an old runtime running and the symlink switched to a new release: `pm-operator client update` is
refused naming `pm-operator drain` and writes nothing; a job the old runtime starts after the switch runs through the old
installation's `pm-exec` until the drain has completed; after the drain the next command starts the new `pm-mcpd`.
Source:: design review.

== Token-Lane Credential Architecture & OS Keyring Integration

[#PM-WATCH-CLI-2]
=== PM-WATCH-CLI-2: Repository identity is the remote, never the checkout path

Anchor:: link:../specification/cli-and-security/02-credentials-and-operator.adoc#_token_lane_credential_architecture_os_keyring_integration[CLI & Security § Token-Lane Credential Architecture],
link:../Requirements.adoc#PM-SEC-2[PM-SEC-2], link:../Requirements.adoc#PM-CRED-1[PM-CRED-1]
Hazard:: A foreign repository was identified by its checkout path. A renamed repository kept working for git and REST
reads through the provider's redirect, but the App installation-token mint did not follow the rename, so
credential lookups broke silently.
Guard:: Cross-project grants and CI queries identify the target by remote owner/name; a checkout path is only a
location. The credential project key is the enrolment identifier, so a remote rename leaves it
unchanged; `pm-operator status` and `enter` still detect a remote-name change and report it, because provider-side
calls (App installation tokens, cross-project grants) address the remote by owner/name. A rename is probed before
it is declared safe. The installation discovery (`GET /repos/{owner}/{repo}/installation`) and the cached derived
installation tokens (keyed by installation and permission set) are invalidated when the remote's owner/name changes,
and the native transport's origin check (`remote_origin_mismatch`) compares origins, never checkout paths or
repository names.
Fixture:: `pr-agent-settings` → `cuioss-review-bot` (cuioss-organization 0.30.0, plan-marshall #1603).
Source:: plan-marshall lessons 2026-09-24-12-001 and 2026-09-24-12-007.

[#PM-WATCH-CLI-4]
=== PM-WATCH-CLI-4: The upstream filing credential is proven before any filing job exists

Anchor:: link:../specification/cli-and-security/02-credentials-and-operator.adoc#_token_lane_credential_architecture_os_keyring_integration[CLI & Security § Token-Lane Credential Architecture],
link:../specification/store-schemas/10-job-and-lesson-records.adoc#lesson-record[Store Schemas § Lesson Record] (Upstream Release),
link:../Requirements.adoc#PM-ARCH-2[PM-ARCH-2], link:../Requirements.adoc#PM-CRED-5[PM-CRED-5]
Hazard:: An upstream route was built before anyone proved that a consumer's credential can write to the vendor
tracker.
Guard:: Before the operator-confirmed filing job is implemented, a probe verifies write permission on the target
tracker with the enrolled credential; without it the release action only renders the issue body for the operator to
file (the other fallbacks: a flushed outbox, an operator-provisioned per-repository token).
Source:: plan-marshall lessons-routing PLAN-LR-03 D0.

[#PM-WATCH-CLI-5]
=== PM-WATCH-CLI-5: A derived installation token never outlives its secret and never leaks

Anchor:: link:../specification/cli-and-security/02-credentials-and-operator.adoc#derived-tokens[CLI & Security § Short-Lived Derived Tokens],
link:../Requirements.adoc#PM-CRED-5[PM-CRED-5]
Hazard:: An in-memory cache of App installation tokens keeps acting after the App key was rotated or revoked, or a
cached token reaches a log, an audit record, a job output, or a tool result unredacted, because it never passed the
stored-secret resolution path that registers redaction.
Guard:: Tests rotate, remove, and re-set the `github` entry and answer a request with `auth_failed`: each drops every
cached token of the entry, and the next operation mints a new one; no token is used later than 5 minutes before its
expiry; every token is registered for redaction at mint, and a canary token value echoed in a recorded provider error
body is absent from `daemon.log`, `audit.jsonl`, job logs, and every tool result; no derived token is written to a
store or exported.
Source:: design review.

[#PM-WATCH-CLI-6]
=== PM-WATCH-CLI-6: The origin check sees the effective URL, whatever rewrites it

Anchor:: link:../specification/cli-and-security/02-credentials-and-operator.adoc#native-confinement[CLI & Security § Native Operation Confinement]
Hazard:: A repository-controlled rewrite (`url.<base>.insteadOf`, `pushInsteadOf`, `remote.<name>.pushurl`, a file
included through `includeIf`) or an HTTP redirect in the JGit transport sends the agent credential to a host other
than the origin of the credential entry.
Guard:: Adversarial fixture repositories whose remote is redirected to a foreign host by each of `insteadOf`,
`pushInsteadOf`, `pushurl`, and an `includeIf`-included file (inside and outside the repository), plus a recorded
redirect from the provider origin to a foreign host: every fetch and push refuses with `remote_origin_mismatch`,
appends one `security` audit record, and a listener on the foreign host counts zero connections; matched control:
the same rewrites onto the credential origin pass.
Source:: design review.

[#PM-WATCH-CLI-7]
=== PM-WATCH-CLI-7: The GitHub API and web origins are paired, never confused

Anchor:: link:../specification/cli-and-security/02-credentials-and-operator.adoc#agent-credentials[CLI & Security § Agent Credentials of the Native Variant],
link:../Requirements.adoc#PM-CRED-5[PM-CRED-5]
Hazard:: For `github.com` the API origin (`https://api.github.com`) differs from the web and transport origin
(`https://github.com`); an origin pin that takes one for the other sends the credential to the wrong origin or
refuses a valid request.
Guard:: Table test over a `github.com` entry, a GitHub Enterprise entry, and a GitLab entry: REST and GraphQL go to
the derived API origin and git transport to the `url` origin, each authenticated; a request to any other origin (for
example `api.github.com` with an Enterprise entry) carries no authentication header and is refused; GitLab uses the
`url` origin for both.
Source:: design review.

[#PM-WATCH-CLI-8]
=== PM-WATCH-CLI-8: No agent token and no askpass helper reach a CLI-variant job

Anchor:: link:../specification/cli-and-security/02-credentials-and-operator.adoc#cli-variant-credentials[CLI & Security § Credentials of the CLI Variant]
Hazard:: A token variable (`GH_TOKEN`, `GITHUB_TOKEN`, `GITLAB_TOKEN`) or an askpass or credential helper served by
a PM-MCP binary reaches the environment of a CLI `git`, `gh`, or `glab` job, where every descendant, repository hooks
included, and every same-user process can read it.
Guard:: CLI-variant job fixtures with a hook that records its environment and argument vector, run while the
runtime's own environment contains the forbidden variables: no token variable, no `GIT_ASKPASS` or `SSH_ASKPASS`, no
credential helper naming a PM-MCP binary (`pm-mcp`, `pm-operator`, `pm-mcpd`, `pm-exec`), and no secret canary value
appear, while the operator's ambient rows of the Job
Environment are present; the job's audit record carries `identity: operator_ambient`.
Source:: design review.

[#PM-WATCH-CLI-9]
=== PM-WATCH-CLI-9: A native operation never starts a process

Anchor:: link:../specification/cli-and-security/02-credentials-and-operator.adoc#native-confinement[CLI & Security § Native Operation Confinement]
Hazard:: JGit has several process entry points (hooks, filter drivers, `core.fsmonitor`, commit signing,
`FS.runInShell`); an `FS` subclass that covers only some of them leaves a repository value able to start a process
inside the runtime.
Guard:: Native-selected fixture repositories with a hook in `.git/hooks/`, a `core.hooksPath` hook, a clean/smudge
filter driver, `core.fsmonitor`, `commit.gpgSign` with `gpg.program`, and `core.sshCommand`: every native operation
that would reach one refuses with `capability_missing` or ignores the non-allowlisted key, and a sentinel file each
program would write stays absent; a build test enumerates the process call sites of the pinned JGit version, so an
upgrade that adds one fails until the `FS` subclass covers it.
Source:: design review.

[#PM-WATCH-CLI-24]
=== PM-WATCH-CLI-24: A model-relayed operator action is refused

Anchor:: link:../specification/cli-and-security/02-credentials-and-operator.adoc#operator-channel-isolation[CLI & Security § Operator Channel Isolation],

Hazard:: The model runs `pm-operator waive` from its shell, or submits an operator choice (an integration

Guard:: Tests: `pm-operator waive`, `unwaive`, and `abort` invoked with an agent environment marker or without a

operator-configuration value (link fuzzing over every catalogued state); an elicitation answer is accepted only on the
session connection that declared elicitation support and only for a setup or bootstrap choice; matched control: the
same verb from an interactive terminal writes the waiver.

[#PM-WATCH-CLI-23]
=== PM-WATCH-CLI-23: Unenrol never strands live work, and a store never changes its root

Hazard:: An unenrol that runs while plans, epics, or jobs are live leaves them without an enrolment, and a re-enrolment

reuses the store.
Source:: design review.

[#PM-WATCH-CLI-25]
=== PM-WATCH-CLI-25: The lifecycle gate is a release constant, and only a pilot passes a closed gate

Anchor:: link:../specification/cli-and-security/02-credentials-and-operator.adoc#enrolment-lifecycle-release[CLI & Security § Enrolment, Lifecycle Gate & Release] (Lifecycle gate)
Hazard:: A gate that a configuration key, an environment variable, or an edited enrolment file can open lets a
pre-Stage-4 release create plans everywhere, and a release that ships with the constant in the wrong position either
blocks every project or opens the lifecycle before its exit criteria are met.
Guard:: With the gate constant closed: `start.create-scope` in a project enrolled without `--pilot` is refused
`lifecycle_closed` and creates nothing, and in a project enrolled with `--pilot` it creates the scope; `pilot` is
covered by the enrolment HMAC, so an enrolment file edited to `pilot: true` outside the operator verb is refused
`enrolment_tampered`; re-running `enrol` without `--pilot` refuses later scope creations while the project's live
plans continue. With the gate constant open: both projects create scopes, and the flag has no effect. A release test
asserts the position of the constant against the release's Stage 4 status.
Source:: design review.

== Web Access & Pairing (`pm-operator web`)

[#PM-WATCH-CLI-15]
=== PM-WATCH-CLI-15: A pairing code is a single, short-lived, rate-limited secret

Anchor:: link:../specification/cli-and-security/03-web-server.adoc#web-pairing[CLI & Security § Pairing Protocol],
link:../specification/timeouts/02-runtime-leases-operator-web.adoc#web-access[Timeouts & Budgets § Web Access],
link:../Requirements.adoc#PM-SEC-7[PM-SEC-7]
Hazard:: A pairing code of about 34.5 bits stays guessable when failures are not counted per pairing, when the error
tells an expired code from a wrong one, when it survives a restart, or when it reaches a log.
Guard:: After five failed redemptions the sixth redemption fails even with the right code; a wrong, an expired, a
consumed, and a superseded code each get the identical `400` (`pairing_invalid`) body; a runtime restart invalidates
the open code; a canary code appears in no `audit.jsonl` or `daemon.log` line.
Source:: design review.

[#PM-WATCH-CLI-16]
=== PM-WATCH-CLI-16: A device secret exists only as its hash

Anchor:: link:../specification/cli-and-security/03-web-server.adoc#web-proxy[CLI & Security § API Access & Device Secret] (Logging),
link:../specification/store-schemas/12-machine-stores.adoc#web-access-records[Store Schemas § Web Access Records],
link:../Requirements.adoc#PM-SEC-7[PM-SEC-7]
Hazard:: A bearer secret logged by a request or access logger of the web listener or by an error message, or stored
in clear in the device store, stays valid until revoked and grants operator rights.
Guard:: Pair a device and drive requests, a failing request, and an event stream with a canary `pmw_` secret on the
web listener: the canary is absent from `daemon.log`, `audit.jsonl`, and `state/web-devices.json`, which holds only
its SHA-256.
Source:: design review.

[#PM-WATCH-CLI-17]
=== PM-WATCH-CLI-17: Revocation and idle expiry take effect at once

Anchor:: link:../specification/cli-and-security/03-web-server.adoc#web-devices[CLI & Security § Paired Devices],
link:../Requirements.adoc#PM-SEC-7[PM-SEC-7]
Hazard:: A validity cache in the runtime's web adapter, or an event stream authenticated only on connect, keeps a
revoked device working after the operator removed it.
Guard:: With an open event stream, `pm-operator web devices revoke <id>` ends the device's stream within one event cycle
and its next request is answered `401`; no cache exists to wait out; a device whose `last_used_at` lies 90 days back
(clock fixture) is answered `401` and removed with `reason: idle_expired`, while one a minute short of it still works.
Source:: design review.

[#PM-WATCH-CLI-18]
=== PM-WATCH-CLI-18: Every web response carries every security header

Anchor:: link:../specification/cli-and-security/03-web-server.adoc#web-security-headers[CLI & Security § Request Validation & Security Headers],
link:../Requirements.adoc#PM-SEC-7[PM-SEC-7]
Hazard:: Headers set by a filter on one route type only leave the error pages, the fallback page, or the event stream
without anti-framing or CSP, and those responses become the framing or injection target.
Guard:: For a static file, the SPA fallback page, API responses of every status the web listener produces (`200`,
`401`, `403`, and `404` among them), and an SSE stream, the `Content-Security-Policy` header equals the specified
value exactly, and `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, and `Referrer-Policy: no-referrer` are
present.
Source:: design review.

[#PM-WATCH-CLI-19]
=== PM-WATCH-CLI-19: Foreign hosts and origins are refused before routing

Anchor:: link:../specification/cli-and-security/03-web-server.adoc#web-security-headers[CLI & Security § Request Validation & Security Headers] (Host validation, No CORS),
link:../Requirements.adoc#PM-SEC-7[PM-SEC-7]
Hazard:: Host validation after routing, or an `Origin` check only on some methods, leaves the runtime's web listener
open to DNS rebinding and cross-site requests carrying a stored device secret.
Guard:: A request with a foreign `Host` on the web listener is answered `403` before routing: a spy records no route
handler invocation and no device-store lookup; a `POST` with a cross-origin `Origin` is answered `403`; no response
of any kind carries an `Access-Control-*` header, and a preflight `OPTIONS` is refused.
Source:: design review.

[#PM-WATCH-CLI-20]
=== PM-WATCH-CLI-20: The runtime checks the device secret on every request, and never takes the runtime token over TCP

Anchor:: link:../specification/cli-and-security/03-web-server.adoc#web-proxy[CLI & Security § API Access & Device Secret] (Device secret, No runtime token),
link:../specification/runtime-model/01-processes-and-transport.adoc#local-api[Runtime Model § Local API],
link:../Requirements.adoc#PM-SEC-7[PM-SEC-7]
Hazard:: A web adapter that checks a device secret once per connection or keeps a validity cache lets a revoked
device through; one that reuses the local adapter's authentication accepts the runtime token on the TCP listener, so
the machine-local secret becomes a network credential with operator rights.
Guard:: A device revoked while its keep-alive connection stays open is rejected on its next request on that
connection; a well-formed but unknown `pmw_` secret is answered `401` (the runtime's audit record shows the refusal);
a request on the web listener carrying the valid runtime token as `Authorization: Bearer`, or a running job's token,
is answered `401` on every `/api/v1/` path; a request without a device secret is answered `401` everywhere under
`/api/v1/` except pairing redemption (`POST /api/v1/pair`); a valid device secret presented on the Unix socket is
answered `401`; matched control: the runtime token on the Unix socket is accepted.
Source:: design review.

[#PM-WATCH-CLI-21]
=== PM-WATCH-CLI-21: The web listener exists only while enabled and never routes `/mcp`

Anchor:: link:../specification/cli-and-security/03-web-server.adoc#web-proxy[CLI & Security § API Access & Device Secret] (Route restriction),
link:../specification/cli-and-security/03-web-server.adoc#web-server-lifecycle[CLI & Security § Lifecycle],
link:../Requirements.adoc#PM-SEC-4[PM-SEC-4], link:../Requirements.adoc#PM-SEC-7[PM-SEC-7]
Hazard:: A second HTTP server that shares the routes of the Unix-socket listener, or a route match before path
normalization (`/api/v1/../../mcp`, `/api/v1/%2e%2e/mcp`, `//mcp`), puts the model's tool surface on a TCP listener; a
listener that is open while `web.enabled` is false, or stays open after `pm-operator web disable`, exposes the
runtime without the operator's decision.
Guard:: Table test on the web listener over `/mcp`, `/mcp/`, encoded, double-encoded, dot-segment, duplicate-slash,
and case variants, and over every path the Unix-socket listener serves outside `/api/v1/`: each is refused with a
valid device secret as with the runtime token, and a spy on the MCP endpoint records zero requests from the TCP
listener; listener test: with `web.enabled` false a `pm-mcpd` whose local adapter runs on the Unix socket holds no
listening TCP socket, across a restart too;
`pm-operator web enable` opens exactly one, and a restart with `enabled` true reopens it; `pm-operator web disable`
closes it and ends its open streams while `state/web-devices.json`, running plans, and running jobs stay untouched
(under the Milestone 0 spike's fallback the open and the close are asserted at the next runtime start).
Source:: design review.

[#PM-WATCH-CLI-26]
=== PM-WATCH-CLI-26: The listener decides what is web-originated, never a header

Anchor:: link:../specification/cli-and-security/03-web-server.adoc#web-proxy[CLI & Security § API Access & Device Secret] (Web-originated requests),
link:../Requirements.adoc#PM-SEC-7[PM-SEC-7]
Hazard:: With the web adapter inside the runtime, the CLI-only endpoints and the browser-reachable ones are routes of
one API in one process; an origin taken from a request header, or from the token kind instead of the listener, lets a
paired device issue a pairing code, enable or disable web access, or enter a credential secret.
Guard:: Table test on the web listener with a valid device secret over every CLI-only endpoint (issuing a pairing
code, enabling and disabling web access, the credential secret endpoints): each answers `403` (`cli_only`) whatever
headers the request carries (a forged forwarding or origin header, a `PM-MCP-*` header, the runtime token in a
second header) and changes nothing; matched control: the same requests on the Unix socket with the runtime token
succeed.
Source:: design review.

[#PM-WATCH-CLI-27]
=== PM-WATCH-CLI-27: The route table of the web listener is a closed allowlist

Anchor:: link:../specification/cli-and-security/03-web-server.adoc#web-proxy[CLI & Security § API Access & Device Secret] (Route restriction),
link:../Requirements.adoc#PM-SEC-4[PM-SEC-4]
Hazard:: A second HTTP server in the same Quarkus application inherits what an extension or a later resource
registers on every HTTP server (health, metrics, or development endpoints, a new REST resource outside `/api/v1/`);
a path table written by hand tests only the paths its author thought of.
Guard:: A build test enumerates the routes actually registered on the web listener of the assembled `pm-mcpd` and
fails on any route that is neither the static web app nor under `/api/v1/`; control: a fixture resource registered
outside `/api/v1/` trips the test.
Source:: design review.
