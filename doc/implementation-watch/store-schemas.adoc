== Overview

Watch items for the link:../specification/store-schemas.adoc[Store Schemas Specification]: persisted identities
and paths, findings and change-ledger records, footprint reconciliation, and the lesson store, whose tests should
run against the real plan-marshall corpora cited here as test fixtures (`PM-MCP` imports nothing, `PM-MIG-2`). The
sections mirror the specification. Item format and lifecycle: link:../ImplementationWatch.adoc[Implementation Watch].

[#PM-WATCH-STORE-1]
=== PM-WATCH-STORE-1: Stored path strings bypass any resolver redirect

Anchor:: link:../specification/store-schemas/01-format-and-session-log.adoc#scope-session-log[Store Schemas § Scope Session Log],
link:../specification/filesystem-layout.adoc#plan-worktree-resolution[Filesystem Layout § Plan & Worktree Resolution] (Project Resolution Rule),

Hazard:: A store move redirected the shared path resolver, but sites that matched a path-shaped string captured
elsewhere (an epic spec path captured as `source_id` in a plan's request) never passed through it.
Guard:: Cross-scope references are persisted as ids, never paths; no session row or scope record stores a path of
the checkout (the main checkout is always the enrolled `project_root`, a worktree only its name `worktree_of`). A
schema test asserts that no session-row field holds a path; a test re-enrols a relocated checkout and asserts that
every scope resolves through the new `project_root`, never a stale path, and that `pm-mcp enter` and the
`PM-MCP-Workspace` header resolve through the same one rule.

[#PM-WATCH-STORE-42]
=== PM-WATCH-STORE-42: A bootstrap entry leaves no residue

Anchor:: link:../specification/store-schemas/01-format-and-session-log.adoc#pending-entry-record[Store Schemas § Pending Entry Record],
