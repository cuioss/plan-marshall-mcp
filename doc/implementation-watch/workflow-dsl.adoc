== Module Boundary & Decoupled Core Architecture

[#PM-WATCH-DSL-12]
=== PM-WATCH-DSL-12: Clients never reach the engine

Anchor:: link:../specification/workflow-dsl.adoc#_module_boundary_decoupled_core_architecture[Workflow DSL § Module Boundary & Decoupled Core Architecture],
link:../Requirements.adoc#PM-IMPL-1[PM-IMPL-1]
Hazard:: One convenience dependency from a client module to `pm-mcp-core` or a provider module lets the CLI or the web
server run engine or store code in its own process, bypassing the runtime as the only writer; `jackson-databind` in
`pm-mcp-api` pulls reflection-heavy binding into the plain native CLI.
Guard:: A build-time dependency guard (Maven enforcer or an architecture test over the resolved dependency trees)
fails when any module under `pm-mcp-clients` depends, directly or transitively, on `pm-mcp-core` or a module under
`pm-mcp-providers`, and when `pm-mcp-api` depends on anything but `jackson-core`; control: a deliberately added
dependency in a test fixture module trips the guard.
Source:: PM-MCP client architecture design review, operator decisions of 2026-09-28 (Z1-3); no plan-marshall defect record.

[#PM-WATCH-DSL-13]
=== PM-WATCH-DSL-13: The release is exactly four binaries with a complete SBOM

Anchor:: link:../specification/workflow-dsl.adoc#_module_boundary_decoupled_core_architecture[Workflow DSL § Module Boundary & Decoupled Core Architecture],
link:../specification/cli-and-security.adoc#installation-layout[CLI & Security § Installation Layout],
link:../Requirements.adoc#PM-DIST-1[PM-DIST-1]
Hazard:: A release profile that packs a stray artifact, misses a binary or its digest, or builds the SBOM from the
Maven graph only leaves the npm packages of the web application unaccounted for.
Guard:: The release build's output is checked: `bin/` holds exactly `pm-mcp`, `pm-mcpd`, `pm-mcp-exec`, and
`pm-mcp-web`, each with its SHA-256 digest, and nothing else; the CycloneDX SBOM lists every package of
`pm-mcp-web-app/package-lock.json` with its pinned version next to the Java dependencies.
Source:: PM-MCP client architecture design review, operator decisions of 2026-09-28 (Z1-17, Z1-19.1); no plan-marshall defect record.

== AST Node Model

[#PM-WATCH-DSL-1]
=== PM-WATCH-DSL-1: Every state leaves a compliant move

Anchor:: link:../specification/workflow-dsl.adoc#no-dead-end-states[Workflow DSL § No Dead-End Non-Terminal States],
link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5]
Hazard:: Three prose rules (scripts-only store access, an orchestrator read carve-out, the plan write boundary)
jointly forbade every available action; six independent runs violated one of them.
Guard:: Property test: every persisted sub-state of every non-terminal state, including entity sub-states, every
condition overlay, and a bound job, has at least one exit (a link, a bounded wait, or a transition) whose guard can
hold; a guard assignment that is merely conceivable does not count. Vocabulary skills never add prose prohibitions
that remove the only offered link; a `rejected` whose detail no offered link can satisfy is a defect.
Fixture:: six-run record (`compliant-paths-001` and five folded predecessors; `phase-gates-003`).
Source:: process-compliance PLAN-09 D3.

[#PM-WATCH-DSL-2]
=== PM-WATCH-DSL-2: Guards are three-valued

Anchor:: link:../specification/workflow-dsl.adoc#_ast_node_model[Workflow DSL § AST Node Model] (guard expressions)
Hazard:: Guards collapsed "could not evaluate" into held or not held.
Guard:: Guards return the sealed `GuardResult` (`HELD`, `NOT_HELD`, `COULD_NOT_EVALUATE(reason)`) that is handled
exhaustively; `COULD_NOT_EVALUATE` raises the `guard_indeterminate` condition.
Source:: truthful-signals (quality-aspect) PLAN-207 D7.

[#PM-WATCH-DSL-3]
=== PM-WATCH-DSL-3: Every read token has a producer

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules],
link:../specification/phase-workflows.adoc#_build_time_startup_static_invariant_verification_finalizepipelinevalidator[Phase Workflows § Build-Time & Startup Static Invariant Verification]
Hazard:: A registered consumer key had no reachable producer, so the consuming section never rendered. The ordering
invariant checks one artifact only.
Guard:: Build-time test: every `reads` token except ambient ones (such as `worktree`) has a producing step of lower
order.
Source:: lessons-routing lesson 2026-09-23-05-008 (`.plan/orchestrator/orchestrator-refactor/inbox/archive/verdict-staleness-scoping/verdict-staleness-scoping-008.md`).

[#PM-WATCH-DSL-4]
=== PM-WATCH-DSL-4: A retry names the event that can change its outcome

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules]
Hazard:: Non-convergent loops (seven cases) retried without any event capable of changing the outcome, or the retry
was never wired while the configuration looked wired.
Guard:: Static check: every `retry` link's primitive declares the external event it awaits; a scenario test asserts
that a retry with no satisfying event is refused.
Source:: review-apparatus PLAN-PR-043 and PLAN-PR-045.

[#PM-WATCH-DSL-5]
=== PM-WATCH-DSL-5: Reachability holds under every configuration

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules],
link:../Requirements.adoc#PM-TEST-3[PM-TEST-3]
Hazard:: An escalation class was unreachable at the default configuration.
Guard:: Static reachability is evaluated under the default configuration and every enumerated configuration variant;
a class unreachable in all of them is made reachable or deleted.
Source:: review-apparatus PLAN-PR-069 D7.

[#PM-WATCH-DSL-8]
=== PM-WATCH-DSL-8: Every gated artifact has a producer on every path

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules] (rule 8, Gate Artifact Producer Coverage),
link:../Requirements.adoc#PM-WF-10[PM-WF-10]
Hazard:: A gate refused a plan for an artifact its own lane could not produce: `pr_title` was written only in the
deep-lane refine step, and the light lane skipped refine.
Guard:: A test unit whose recipe shortcut reaches the Phase 3 arrival gate without a `pr_title` producer fails rule 8;
the shipped recipe path passes because `init.recipe-selected` renders `pr_title_template`. The light lane, which skips
Phase 2 by design, passes because its collapsed envelope's `submit:outline` must carry `pr_title`; a test unit whose
light path lacks that producer fails rule 8.
Fixture:: `pr_title_missing` after exemption, because `pr_title` was written only in deep-lane refine Step 13 and the
light lane skipped refine (`ledger-joins-002`; recurrence `plan-09-outline-sweep-004`; root cause
`implement-opencode-enforcement-parity-001`).
Source:: process-compliance PLAN-10 D1.

[#PM-WATCH-DSL-9]
=== PM-WATCH-DSL-9: A composite with failed sub-operations never records `done`

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules] (rule 9, Step Completion Exactly Once & Failure Outcomes Never Map to Success),
link:../specification/workflow-dsl.adoc#primitive-outcome-classes[§ Outcome Classes & Step Records],
link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5]
Hazard:: A step whose sub-operations failed completed `done`.
Guard:: A composite step with 3 failing sub-operations records `failed`; rule 9 rejects a unit mapping a `FAILURE`
outcome to a `done` completion.
Fixture:: the retrospective fragment pipeline emitted three script-failure markers (stale `--output-file`, doubled
plan dir, missing fragments file) while the step completed `done` (work-log 2026-09-21T01:17–01:20Z,
`plan-07-opencode-repairs-007`).
Source:: process-compliance PLAN-12 deliverable 2 (folded plan-07-opencode-repairs-007).

[#PM-WATCH-DSL-11]
=== PM-WATCH-DSL-11: `skipped_by_operator` completes a step only on an approved decision

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules] (rule 9, Class admits the completion),
link:../specification/phase-workflows.adoc#_step_records_re_fire_loop_back_rules[Phase Workflows § Step Records, Re-Fire & Loop-Back Rules] (Operator Skip)
Hazard:: A `completes <step> as skipped_by_operator` clause on a routine or `SUCCESS` outcome lets a unit skip the
wait-region steps without an operator decision, and Phase-Exit Completeness accepts the skip.
Guard:: Static verifier tests: a unit placing the clause on a `SUCCESS`, `SKIP`, `FAILURE`, or `DENIED` outcome fails
rule 9 naming the transition; the shipped transitions of `review_barrier_gap`, `ci_failure_override`, and
`wait_cancelled_override` pass (class `APPROVED`) and complete `default:ci-verify`,
`plan-marshall:automatic-review`, and `default:sonar-roundtrip` with the grant or acknowledgement reference; the
completion never satisfies a barrier predicate.
Source:: PM-MCP git and provider integration design review, operator decisions of 2026-09-28 (F8B); no plan-marshall defect record.

== Reusable Compound Sub-Workflows & Call-Stack Execution

[#PM-WATCH-DSL-6]
=== PM-WATCH-DSL-6: Artifact-review candidacy scales with the change

Anchor:: link:../specification/workflow-dsl.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL § Six-Stage Execution Contract] (stage 2)
Hazard:: Artifact confirmation listed 271 pre-existing tracked fixture files while the 2 files actually committed
appeared in neither list.
Guard:: Test: a fixture repository with a large tracked `test/**/fixtures/**` corpus matching the artifact patterns
and a 2-file change yields zero review candidates and classifies both changed files.
Fixture:: `safe: []`, `uncertain: 271`, `total: 271`, all tracked `test/**/fixtures/**`, `tracked_resolved: true`; 2
committed files absent from both lists.
Source:: process-compliance inbox module-budget-campaign-completion-010.

[#PM-WATCH-DSL-7]
=== PM-WATCH-DSL-7: Each commit-trailer source has a matched test

Anchor:: link:../specification/workflow-dsl.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL § Six-Stage Execution Contract] (stages 3, 4)
Hazard:: A commit trailer from a non-authoritative channel could override the configured resolver.
Guard:: Only the trailer the server appends passes: a matched test per trailer source asserts that any
`Co-Authored-By:` line in model-supplied text (commit `message`, step-supplied message, answer payload), including
one identical to the resolved value, is refused with `invalid_link_args` naming the line, and that the commit carries
exactly one trailer, the resolved one. The same fixture commits through the native and the CLI variant and asserts
identical metadata: author the operator's `commit_identity`, committer the resolved agent identity (or the compiled
fallback identity), never the operator's git `user.*` configuration.
Source:: truthful-signals PLAN-TRUTH-154 D9.

[#PM-WATCH-DSL-10]
=== PM-WATCH-DSL-10: The commit-fix cap counts identical attempts only

Anchor:: link:../specification/workflow-dsl.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL § Six-Stage Execution Contract] (stage 4, `git.commit-fix`)
Hazard:: A cap counted over every hook failure aborts a plan that is converging (each fix changed the staged tree),
while a cap that never resets on a hook rewrite lets an unchanged change set fail forever.
Guard:: CLI-variant fixture with a failing hook: the first two failures on the same staged tree id and message
return to `git.commit-fix`, and the third identical failure ends `attempts_exhausted` in `git.done-aborted` and the
caller's `<phase>.commit-aborted`; matched control: a fix that changes the staged tree (or a `recompose` that changes
the message, or a hook rewrite) after the second failure resets the counter and the next attempt returns to
`git.commit-fix` again; the native variant has no hook and no counter.
Source:: PM-MCP git and provider integration design review, operator decisions of 2026-09-28 (F10); no plan-marshall defect record.
