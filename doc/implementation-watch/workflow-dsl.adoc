== Overview

Watch items for the link:../specification/workflow-dsl.adoc[Workflow DSL & Engine Specification]: static checks the
engine needs beyond graph integrity (producers for every read, retries with a satisfying event, reachability under
every configuration, a compliant move in every state), three-valued guards, and the `git.commit_and_push`
sub-workflow. The sections mirror the specification. Item format and lifecycle:
link:../ImplementationWatch.adoc[Implementation Watch].

== AST Node Model

[#PM-WATCH-DSL-1]
=== PM-WATCH-DSL-1: Every state leaves a compliant move

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules],
link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5]
Hazard:: Three prose rules (scripts-only store access, an orchestrator read carve-out, the plan write boundary)
jointly forbade every available action; six independent runs violated one of them.
Guard:: Property test: every non-terminal state offers at least one link or a bounded wait for every persisted
sub-state, including entity sub-states and operator-blocked states. Vocabulary skills never add prose prohibitions
that remove the only offered link; a `rejected` whose detail no offered link can satisfy is a defect.
Fixture:: six-run record (`compliant-paths-001` and five folded predecessors; `phase-gates-003`).
Source:: process-compliance PLAN-09 D3.

[#PM-WATCH-DSL-2]
=== PM-WATCH-DSL-2: Guards are three-valued

Anchor:: link:../specification/workflow-dsl.adoc#_ast_node_model[Workflow DSL § AST Node Model] (guard expressions)
Hazard:: Guards collapsed "could not evaluate" into held or not held.
Guard:: Guard primitives return a sealed outcome with `could_not_evaluate(reason)` that is handled exhaustively.
Source:: truthful-signals (quality-aspect) PLAN-207 D7.

[#PM-WATCH-DSL-3]
=== PM-WATCH-DSL-3: Every read token has a producer

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules],
link:../specification/phase-workflows.adoc#_build_time_startup_static_invariant_verification_finalizepipelinevalidator[Phase Workflows § Build-Time & Startup Static Invariant Verification]
Hazard:: A registered consumer key had no reachable producer, so the consuming section never rendered. The ordering
invariant checks one artifact only.
Guard:: Build-time test: every `reads` token except ambient ones (such as `worktree`) has a producing step of lower
order.
Source:: lessons-routing lesson 2026-09-23-05-008.

[#PM-WATCH-DSL-4]
=== PM-WATCH-DSL-4: A retry names the event that can change its outcome

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules]
Hazard:: Non-convergent loops (seven cases) retried without any event capable of changing the outcome, or the retry
was never wired while the configuration looked wired.
Guard:: Static check: every `retry` link's primitive declares the external event it awaits; a scenario test asserts
that a retry with no satisfying event is refused.
Source:: review-apparatus PLAN-PR-043 and PLAN-PR-045.

[#PM-WATCH-DSL-5]
=== PM-WATCH-DSL-5: Reachability holds under every configuration

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules],
link:../Requirements.adoc#PM-TEST-3[PM-TEST-3]
Hazard:: An escalation class was unreachable at the default configuration.
Guard:: Static reachability is evaluated under the default configuration and every enumerated configuration variant;
a class unreachable in all of them is made reachable or deleted.
Source:: review-apparatus PLAN-PR-069 D7.

[#PM-WATCH-DSL-8]
=== PM-WATCH-DSL-8: Every gated artifact has a producer on every path

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules] (rule 8, Gate Artifact Producer Coverage),
link:../Requirements.adoc#PM-WF-10[PM-WF-10]
Hazard:: A gate refused a plan for an artifact its own lane could not produce: `pr_title` was written only in the
deep-lane refine step, and the light lane skipped refine.
Guard:: A test unit whose recipe shortcut reaches the Phase 3 arrival gate without a `pr_title` producer fails rule 8;
the shipped recipe path passes because `init.recipe-selected` renders `pr_title_template`.
Fixture:: `pr_title_missing` after exemption, because `pr_title` was written only in deep-lane refine Step 13 and the
light lane skipped refine (`ledger-joins-002`; recurrence `plan-09-outline-sweep-004`; root cause
`implement-opencode-enforcement-parity-001`).
Source:: process-compliance PLAN-10 D1.

[#PM-WATCH-DSL-9]
=== PM-WATCH-DSL-9: A composite with failed sub-operations never records `done`

Anchor:: link:../specification/workflow-dsl.adoc#static-verification-rules[Workflow DSL § Static AST Verification Rules] (rule 9, Failure Outcomes Never Map to Success),
link:../specification/workflow-dsl.adoc#primitive-outcome-classes[§ Primitive Outcome Classes],
link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5]
Hazard:: A step whose sub-operations failed completed `done`.
Guard:: A composite step with 3 failing sub-operations records `failed`; rule 9 rejects a unit mapping a `FAILURE`
outcome to a `done` completion.
Fixture:: the retrospective fragment pipeline emitted three script-failure markers (stale `--output-file`, doubled
plan dir, missing fragments file) while the step completed `done` (work-log 2026-09-21T01:17–01:20Z,
`plan-07-opencode-repairs-007`).
Source:: process-compliance PLAN-12 D2a.

== Reusable Compound Sub-Workflows & Call-Stack Execution

[#PM-WATCH-DSL-6]
=== PM-WATCH-DSL-6: Artifact-review candidacy scales with the change

Anchor:: link:../specification/workflow-dsl.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL § Six-Stage Execution Contract] (stage 2)
Hazard:: Artifact confirmation listed 271 pre-existing tracked fixture files while the 2 files actually committed
appeared in neither list.
Guard:: Test: a fixture repository with a large tracked `test/**/fixtures/**` corpus matching the artifact patterns
and a 2-file change yields zero review candidates and classifies both changed files.
Fixture:: `safe: []`, `uncertain: 271`, `total: 271`, all tracked `test/**/fixtures/**`, `tracked_resolved: true`; 2
committed files absent from both lists.
Source:: process-compliance inbox module-budget-campaign-completion-010.

[#PM-WATCH-DSL-7]
=== PM-WATCH-DSL-7: Each commit-trailer source has a matched test

Anchor:: link:../specification/workflow-dsl.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL § Six-Stage Execution Contract] (stage 3)
Hazard:: A commit trailer from a non-authoritative channel could override the configured resolver.
Guard:: One matched test per trailer source: a trailer that differs from the resolved value is refused and the
divergence reported; the resolved value passes.
Source:: truthful-signals PLAN-TRUTH-154 D9.
