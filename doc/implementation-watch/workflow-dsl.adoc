== Overview

Watch items for the link:../specification/workflow-dsl.adoc[Workflow DSL & Engine Specification]: module dependency
direction and the release layout, static checks the
engine needs beyond graph integrity (producers for every read, retries with a satisfying event, reachability under
every configuration, a compliant move in every state), three-valued guards, and the `git.commit_and_push`
sub-workflow. The sections mirror the specification. Item format and lifecycle:
link:../ImplementationWatch.adoc[Implementation Watch].

== Module Boundary & Decoupled Core Architecture

[#PM-WATCH-DSL-12]
=== PM-WATCH-DSL-12: Clients never reach the engine

Anchor:: link:../specification/workflow-dsl/01-module-boundary-and-grammar.adoc#_module_boundary_decoupled_core_architecture[Workflow DSL § Module Boundary & Decoupled Core Architecture],
link:../Requirements.adoc#PM-IMPL-1[PM-IMPL-1]
Hazard:: One convenience dependency from a client module to `pm-mcp-core` or a provider module lets the CLI or the web
server run engine or store code in its own process, bypassing the runtime as the only writer; `jackson-databind` in
`pm-mcp-api` pulls reflection-heavy binding into the plain native CLI.
Guard:: A build-time dependency guard (Maven enforcer or an architecture test over the resolved dependency trees)
fails when any module under `pm-mcp-clients` depends, directly or transitively, on `pm-mcp-core` or a module under
`pm-mcp-providers`, and when `pm-mcp-api` depends on anything but `jackson-core`; control: a deliberately added
dependency in a test fixture module trips the guard.
Source:: PM-MCP client architecture design review, operator decisions of 2026-09-28 (Z1-3); no plan-marshall defect record.

[#PM-WATCH-DSL-13]
=== PM-WATCH-DSL-13: The release is exactly four binaries with a complete SBOM

Anchor:: link:../specification/workflow-dsl/01-module-boundary-and-grammar.adoc#_module_boundary_decoupled_core_architecture[Workflow DSL § Module Boundary & Decoupled Core Architecture],
link:../specification/cli-and-security/01-cli-and-installer.adoc#installation-layout[CLI & Security § Installation Layout],
link:../Requirements.adoc#PM-DIST-1[PM-DIST-1]
Hazard:: A release profile that packs a stray artifact, misses a binary or its digest, or builds the SBOM from the
Maven graph only leaves the npm packages of the web application unaccounted for.
Guard:: The release build's output is checked: `bin/` holds exactly `pm-mcp`, `pm-mcpd`, `pm-mcp-exec`, and
`pm-mcp-web`, each with its SHA-256 digest, and nothing else; the CycloneDX SBOM lists every package of
`pm-mcp-web-app/package-lock.json` with its pinned version next to the Java dependencies.
Source:: PM-MCP client architecture design review, operator decisions of 2026-09-28 (Z1-17, Z1-19.1); no plan-marshall defect record.

== AST Node Model

[#PM-WATCH-DSL-1]
=== PM-WATCH-DSL-1: Every state leaves a compliant move

Anchor:: link:../specification/workflow-dsl/07-loop-back-diagrams-verification.adoc#no-dead-end-states[Workflow DSL § No Dead-End Non-Terminal States],
link:../Requirements.adoc#PM-IMPL-5[PM-IMPL-5]
Hazard:: Three prose rules (scripts-only store access, an orchestrator read carve-out, the plan write boundary)
jointly forbade every available action; six independent runs violated one of them.
Guard:: Property test: every persisted sub-state of every non-terminal state, including entity sub-states, every
condition overlay, and a bound job, has at least one exit (a link, a bounded wait, or a transition) whose guard can
hold; a guard assignment that is merely conceivable does not count. Vocabulary skills never add prose prohibitions
that remove the only offered link; a `rejected` whose detail no offered link can satisfy is a defect.
Fixture:: six-run record (`compliant-paths-001` and five folded predecessors; `phase-gates-003`).
Source:: process-compliance PLAN-09 D3.

[#PM-WATCH-DSL-2]
=== PM-WATCH-DSL-2: Guards are three-valued

Anchor:: link:../specification/workflow-dsl/04-ast-node-model.adoc#_ast_node_model[Workflow DSL § AST Node Model] (guard expressions)
Hazard:: Guards collapsed "could not evaluate" into held or not held.
Guard:: Guards return the sealed `GuardResult` (`HELD`, `NOT_HELD`, `COULD_NOT_EVALUATE(reason)`) that is handled
exhaustively; `COULD_NOT_EVALUATE` raises the `guard_indeterminate` condition.
Source:: truthful-signals (quality-aspect) PLAN-207 D7.

[#PM-WATCH-DSL-4]
=== PM-WATCH-DSL-4: A retry names the event that can change its outcome

[#PM-WATCH-DSL-8]
=== PM-WATCH-DSL-8: Every gated artifact has a producer on every path

[#PM-WATCH-DSL-11]
=== PM-WATCH-DSL-11: `waived` completes a step only from a waived remediation terminal

steps without a waiver, and Phase-Exit Completeness accepts it; an operator skip verb, reintroduced, completes a

[#PM-WATCH-DSL-16]
=== PM-WATCH-DSL-16: Every engine-chained cycle passes a job, a submit, or an awaited event

[#PM-WATCH-DSL-17]
=== PM-WATCH-DSL-17: A remediation unit has no dead end and no budget-free remedy

Anchor:: link:../specification/workflow-dsl/08-remediation-units.adoc#remediation-invariants[Workflow DSL § Compiled Invariants of Remediation Units],
link:../Requirements.adoc#PM-WF-7[PM-WF-7]
Hazard:: A unit whose `decide` is entered with every budget spent rests without a remedy link; a `retry` or `fix`
link without its budget guard loops without bound; a land call site forced to route `fix_requested` it can never
reach invites a fake route.
Guard:: `DefaultUnitInvariantTest` refuses a weakened fixture for each of `INV-REM-1` to `INV-REM-6`: a `decide`

binding a budget above the hard cap; and Rule 2 at a `land` call site bound `actions=[retry]` demands routes only
for the outcomes the bound actions can reach (no `fix_requested`), while every call site still routes `stepped_out`.
Source:: operator decision of 2026-09-29 (workflow consistency, doc review); no plan-marshall defect record.

[#PM-WATCH-DSL-18]
=== PM-WATCH-DSL-18: The integrity pause offers nothing and holds every deadline

Hazard:: A paused scope still renders a link, or a server timer (question wait, waiver wait) expires during the
pause and takes a fallback the operator could not prevent; `accept-edit` clears the pause without re-verifying the

[#PM-WATCH-DSL-7]
=== PM-WATCH-DSL-7: Each commit-trailer source has a matched test

Anchor:: link:../specification/workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL § Six-Stage Execution Contract] (stages 3, 4)
Hazard:: A commit trailer from a non-authoritative channel could override the configured resolver.
Guard:: Only the trailer the server appends passes: a matched test per trailer source asserts that any
`Co-Authored-By:` line in model-supplied text (commit `message`, step-supplied message, answer payload), including
one identical to the resolved value, is refused with `invalid_link_args` naming the line, and that the commit carries
exactly one trailer, the resolved one. The same fixture commits through the native and the CLI variant and asserts
identical metadata: author the operator's `commit_identity`, committer the resolved agent identity (or the compiled
fallback identity), never the operator's git `user.*` configuration.
Source:: truthful-signals PLAN-TRUTH-154 D9.

[#PM-WATCH-DSL-10]
=== PM-WATCH-DSL-10: The commit-fix cap counts identical attempts only

Anchor:: link:../specification/workflow-dsl/06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Workflow DSL § Six-Stage Execution Contract] (stage 4, `git.commit-fix`)
Hazard:: A cap counted over every hook failure aborts a plan that is converging (each fix changed the staged tree),
while a cap that never resets on a hook rewrite lets an unchanged change set fail forever.
Guard:: CLI-variant fixture with a failing hook: the first two failures on the same staged tree id and message
return to `git.commit-fix`, and the third identical failure ends `attempts_exhausted` in `git.stepped-out` (server
step-out, `cause: attempts_exhausted`), which the caller routes (a plan caller to `finalize.hand-back`, a
remediation unit back to its `decide`); matched control: a fix that changes the staged tree (or a `recompose` that
changes the message, or a hook rewrite) after the second failure resets the counter and the next attempt returns to
`git.commit-fix` again; the native variant has no hook and no counter.
Source:: PM-MCP git and provider integration design review, operator decisions of 2026-09-28 (F10); no plan-marshall
defect record; rewritten per the operator decision of 2026-09-29 (workflow consistency, doc review).

[#PM-WATCH-DSL-14]
=== PM-WATCH-DSL-14: A step-out unwinds exactly one frame

Anchor:: link:../specification/workflow-dsl/01-module-boundary-and-grammar.adoc#sub-workflow-exits[Workflow DSL § Result Guards & Sub-Workflow Exit Contract],
link:../specification/workflow-dsl/04-ast-node-model.adoc#condition-overlays[Workflow DSL § Condition Overlays],
link:../Requirements.adoc#PM-WF-1[PM-WF-1]
Hazard:: A step-out that unwinds more than its own frame ends a plan from inside a nested unit (a commit inside a
remediation unit takes the plan's fallback although the unit could still remedy); a step-out offered at plan scope
or on an `auto` or job state lets the model leave a bounded wait.
Guard:: Scenario tests: the model's `step_out` inside `git.commit_and_push` called by `remediation-ci.commit-fix`
returns `stepped_out` to that call site only, which routes it to `remediation-ci.decide` (uncharged); a spent
condition budget inside the same nesting unwinds frame by frame with a server step-out, each caller routing it,
until the phase's fallback state is entered; a representation test asserts that `step_out` appears on every resting
`link` state of a sub-process and on no `auto`, `job`, or `composite_job` state and never at plan scope, where
`hand_back` is offered instead.
Source:: operator decision of 2026-09-29 (workflow consistency, doc review); no plan-marshall defect record.

[#PM-WATCH-DSL-15]
=== PM-WATCH-DSL-15: Result guards partition every `done` transition

Anchor:: link:../specification/workflow-dsl/01-module-boundary-and-grammar.adoc#sub-workflow-exits[Workflow DSL § Result Guards & Sub-Workflow Exit Contract],

`result.commit`) pass; a property test over generated result records asserts exactly one matching transition.
Source:: operator decision of 2026-09-29 (workflow consistency, doc review); no plan-marshall defect record.

=== PM-WATCH-DSL-19: The state catalogue drift test covers generic remediation rows
