== Runtime

[#PM-WATCH-RUN-1]
=== PM-WATCH-RUN-1: Started means reachable

Anchor:: link:../specification/runtime-model.adoc#_start_modes[Runtime Model § Start Modes],
link:../Requirements.adoc#PM-ARCH-8[PM-ARCH-8]
Hazard:: A daemon start reported `running` before liveness was verified.
Guard:: Every CLI command's on-demand start (the relay's included) and `pm-mcp status` report `running` only after a
successful authenticated round trip on the runtime's socket (runtime token); `status` is an API request, so its
`running` is that round trip, and `state/runtime.json` serves only the "not running" answer (no live record) without
starting the runtime; a test kills the runtime during start, and another leaves a `runtime.json` of a dead process
and a stale `runtime.token`.
Source:: truthful-signals PLAN-TRUTH-150 D8.

[#PM-WATCH-RUN-4]
=== PM-WATCH-RUN-4: The runtime token is fresh, private, and never leaks

Anchor:: link:../specification/runtime-model.adoc#runtime-token[Runtime Model § Local Trust: Runtime Token],
link:../Requirements.adoc#PM-SEC-4[PM-SEC-4]
Hazard:: A bearer secret shared by file becomes the weak point of the local boundary when it survives a restart, when
a client reads it from a directory or file another user or a symlink controls, or when it reaches a log, the audit
log, an argument vector, or a job's environment.
Guard:: The runtime writes a fresh token before it binds the socket on every start (a test compares the token across
two starts and asserts the file exists before the socket); a client refuses `run/` or `runtime.token` with a foreign
owner, a broader mode, or a symlink, sending nothing (one fixture per case); a canary token appears in no
`daemon.log`, `audit.jsonl`, process argument vector, or job environment; restart fixture: a client holding the old
token gets `401`, re-reads the file exactly once, and succeeds, and a second `401` is not retried.
Source:: PM-MCP client architecture design review, operator decisions of 2026-09-28 (Z1-6); no plan-marshall defect record.

[#PM-WATCH-RUN-5]
=== PM-WATCH-RUN-5: Without a runtime, the three offline verbs start nothing and write nothing

Anchor:: link:../specification/runtime-model.adoc#local-api[Runtime Model § Local API] (Availability),
link:../specification/cli-and-security.adoc#cli-daemon-access[CLI & Security § Runtime Access & On-Demand Start],
link:../Requirements.adoc#PM-ARCH-8[PM-ARCH-8]
Hazard:: A status query, a session-start hook, or a drain that silently brings up the runtime or writes a file breaks
the single-writer rule and turns a read-only check into a state change the host drives.
Guard:: With no runtime running, `pm-mcp status`, `pm-mcp hook session-start`, and `pm-mcp drain` each run against a
`PM_MCP_BASE` whose tree is hashed before and after: no runtime process is started, no socket exists afterwards, and
the tree is byte-identical (contents, names, and modes); matched control: any other verb starts the runtime on demand.
Source:: PM-MCP client architecture design review, operator decisions of 2026-09-28 (Z1-5); no plan-marshall defect record.

== Logical Plan Sessions

[#PM-WATCH-RUN-2]
=== PM-WATCH-RUN-2: Stalls and idle gaps on an active plan are derived

Anchor:: link:../specification/runtime-model.adoc#stalled-plans[Runtime Model § Stalled Plans],
link:../Requirements.adoc#PM-ARCH-8[PM-ARCH-8], link:../Requirements.adoc#PM-SEC-6[PM-SEC-6]
Hazard:: A stalled plan left no record; an agent that announced continuation and then ended its turn halted the plan
unnoticed.
Guard:: `pm-mcp status`, the web app, and the epic view derive `stalled` for non-terminal scopes without pending
condition or awaited event whose last transition or model call is older than the compiled stalled threshold (600 s),
and the runtime records one `plan_stalled` audit record per episode with the idle span; metrics derive idle gaps
between consecutive calls on a plan that is neither blocked nor waiting, from the audit log; nothing of it reaches a
model-facing representation; test with an aged fixture and a blocked control that is not reported.
Fixture:: a 17-min gap 13:45:20 → 14:02:28; 12h54m idle vs 2h8m worked; a deferred stall nothing recorded
(D-087-g).
Source:: post-run-quality PLAN-PRQ-04 D0; truthful-signals (quality-aspect) PLAN-217 D3.

== Verification

[#PM-WATCH-RUN-3]
=== PM-WATCH-RUN-3: Tests never observe machine-wide state

Anchor:: link:../specification/runtime-model.adoc#_verification[Runtime Model § Verification],
link:../Requirements.adoc#PM-DIST-5[PM-DIST-5], link:../Requirements.adoc#PM-TEST-4[PM-TEST-4]
Hazard:: A test-isolation guard blamed a 52.33 s test for a concurrent plan's write of a machine-global lock file.
Guard:: Every test that starts a runtime uses its own `PM_MCP_BASE`; isolation guards ignore writes outside the test's
base.
Fixture:: a concurrent plan's `merge.lock` write during a run of 23951 passing tests.
Source:: truthful-signals (quality-aspect) PLAN-205 D4.
