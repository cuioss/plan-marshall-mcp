== Overview

Watch items for the link:../specification/runtime-model.adoc[Runtime & Interaction Model Specification]: start-up
liveness, stall and idle-gap detection on active plans, and test isolation from machine-wide state. The sections
mirror the specification. Item format and lifecycle: link:../ImplementationWatch.adoc[Implementation Watch].

== Runtime

[#PM-WATCH-RUN-1]
=== PM-WATCH-RUN-1: Started means reachable

Anchor:: link:../specification/runtime-model.adoc#_start_modes[Runtime Model § Start Modes],
link:../Requirements.adoc#PM-ARCH-8[PM-ARCH-8]
Hazard:: A daemon start reported `running` before liveness was verified.
Guard:: The relay's start-on-demand and `pm-mcp status` report `running` only after a successful socket round trip; a
test kills the runtime during start.
Source:: truthful-signals PLAN-TRUTH-150 D8.

== Logical Plan Sessions

[#PM-WATCH-RUN-2]
=== PM-WATCH-RUN-2: Stalls and idle gaps on an active plan are derived

Anchor:: link:../specification/runtime-model.adoc#_continuation[Runtime Model § Continuation],
link:../Requirements.adoc#PM-ARCH-8[PM-ARCH-8], link:../Requirements.adoc#PM-SEC-6[PM-SEC-6]
Hazard:: A stalled plan left no record; an agent that announced continuation and then ended its turn halted the plan
unnoticed.
Guard:: `pm-mcp status` and the epic view derive `stalled` from the last-transition age of non-terminal plans and
record it; metrics derive idle gaps between consecutive calls on a plan that is neither blocked nor waiting, from
the audit log; test with an aged fixture.
Fixture:: a 17-min gap 13:45:20 → 14:02:28; 12h54m idle vs 2h8m worked; a deferred stall nothing recorded
(D-087-g).
Source:: post-run-quality PLAN-PRQ-04 D0; truthful-signals (quality-aspect) PLAN-217 D3.

== Verification

[#PM-WATCH-RUN-3]
=== PM-WATCH-RUN-3: Tests never observe machine-wide state

Anchor:: link:../specification/runtime-model.adoc#_verification[Runtime Model § Verification],
link:../Requirements.adoc#PM-DIST-5[PM-DIST-5], link:../Requirements.adoc#PM-TEST-4[PM-TEST-4]
Hazard:: A test-isolation guard blamed a 52.33 s test for a concurrent plan's write of a machine-global lock file.
Guard:: Every test that starts a runtime uses its own `PM_MCP_BASE`; isolation guards ignore writes outside the test's
base.
Fixture:: a concurrent plan's `merge.lock` write during a run of 23951 passing tests.
Source:: truthful-signals (quality-aspect) PLAN-205 D4.
