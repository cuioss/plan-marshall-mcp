== Dependency Rules

[#PM-WATCH-MOD-1]
=== PM-WATCH-MOD-1: Clients never reach the engine

Anchor:: link:../specification/module-structure.adoc#dependency-rules[Module Structure § Dependency Rules],
link:../Requirements.adoc#PM-IMPL-1[PM-IMPL-1]
Hazard:: One convenience dependency from a client module to `pm-core`, `pm-workflow` or a provider module
lets `pm-mcp` or `pm-operator` run engine or store code in its own process, bypassing the runtime as the only writer;
a dependency of one client module on the other puts operator verbs into the binary the model may run;
`jackson-databind` in `pm-api` pulls reflection-heavy binding into the plain native client binaries.
Guard:: A build-time dependency guard (Maven enforcer or an architecture test over the resolved dependency trees)
fails when any module under `pm-clients` depends, directly or transitively, on `pm-core`, `pm-workflow`
or a module under `pm-providers`, when `pm-relay` or `pm-operator` depends on a PM-MCP module other than `pm-api`
(the other client module and `pm-mcp-server` included), when a provider module depends on `pm-workflow`, when `pm-core` depends on a PM-MCP module other than
`pm-api` (which it uses for the host-detection table alone), and when `pm-api` depends on anything but
`jackson-core`; control: a deliberately added dependency in a test fixture module trips the
guard.
Source:: PM-MCP client architecture design review, operator decisions of 2026-09-28 (Z1-3); no plan-marshall defect record; rewritten per the
operator decisions of 2026-10-01 (binary split).

== Binaries & Build Types

[#PM-WATCH-MOD-2]
=== PM-WATCH-MOD-2: The release is exactly four binaries with a complete SBOM

Anchor:: link:../specification/module-structure.adoc#binaries[Module Structure § Binaries & Build Types],
link:../specification/cli-and-security/01-cli-and-installer.adoc#installation-layout[CLI & Security § Installation Layout],
link:../Requirements.adoc#PM-DIST-1[PM-DIST-1]
Hazard:: A release profile that packs a stray artifact, misses a binary or its digest, or ships operator verbs
inside the relay binary breaks the layout the host deny rule rests on; an SBOM built from the Maven graph only leaves
the npm packages of the web application, which `pm-mcpd` serves, unaccounted for.
Guard:: The release build's output is checked: `bin/` holds exactly `pm-mcp`, `pm-operator`, `pm-mcpd`, and
`pm-exec`, each with its SHA-256 digest, and nothing else; `pm-mcp` offers exactly the verbs `serve`, `enter`, and
`hook`, and no operator verb; the CycloneDX SBOM lists every package of
`pm-web-app/package-lock.json` with its pinned version next to the Java dependencies.
Source:: PM-MCP client architecture design review, operator decisions of 2026-09-28 (Z1-17, Z1-19.1); no plan-marshall defect record; rewritten per the
operator decisions of 2026-10-01 (binary split, web access in the runtime).
